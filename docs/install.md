# 安装

一条命令、手机扫码、发一句话，5 分钟内拿到第一个回答。Linux 和 macOS 均无需桌面浏览器或电脑端设备认证。

## 前提

- 这台机器上已装好并登录了 Claude Code、Codex 或 Antigravity（任一个就行，不用每个都装）。怎么装、怎么登录见[安装和登录 Harness](harnesses.md#安装和登录-harness)；安装器不教、也不替你装。
- **管家默认用 Claude Code。** 没有它、只有 Codex 或 Antigravity 调通时照样装：安装器让管家用调通的那个，专项、整理专项和别的默认开关照常开，小模型判断也问它，见[没有 Claude Code 时](#没有-claude-code-时)。
- Python 3.10+。没有 `lark-cli` 时安装器会用 npm 装它（没有 npm 时它会告诉你去装 Node.js）。
- 公司同事装核心加扩展，照扩展库 README 的「同事第一次安装」一节装；本文只写核心自己的装法。

## 安装

```bash
git clone https://github.com/ericxk/covey.git && cd covey
./install
```

终端里依次出现二维码时，用飞书手机端扫码确认（建应用、授权、订阅事件与回调共 3 步；扫码的人就是机器人的主人，不用填 open_id、不用配对，也不需要打开开发者后台或电脑端设备认证）；菜单项（`/usage`、`/board`、`/settings`）由官方斜杠命令接口自动注册。装好后它请你去飞书私聊机器人发一句话（私聊里会有一张欢迎卡，点卡上的示例也行），并在终端里等到这句话真的有了回答才结束。

## 它做了什么

每步一行标题，只在有事时多说一句：

1. **检查环境和目录**：数据根（默认是仓库同级的 `<仓库目录名>-data`，`--data-home` 或 `COVEY_DATA_HOME` 可改）、默认工作区、临时目录、浏览器和 `lark-cli` 的安装位置都有默认值，自动建好，不写系统盘。默认工作区就是主目录，所有话题从这里启动：`--workdir` 给了就用它；重跑时沿用上次注册的；在别的目录里运行是当前目录；在仓库里运行时终端里问一句“新话题默认在哪个目录干活？”，输入你的项目目录，或直接回车用主目录 `<数据根>/home`。新建的主目录里会放一份简短的 `AGENTS.md`（同样内容的 `CLAUDE.md`）、`.ignore`、`.skills/` 和 `tasks/`，见[配置 · 主目录与常用路径](configuration.md#主目录与常用路径)；已有的目录一个文件都不写。之后常去的仓库和目录在网页设置的「常用路径」页加，飞书「设置」→「仓库」只读地看。安装还会写 `<数据根>/bin/covey`（`covey repo …` 的命令入口）。
2. **准备 `lark-cli`**：没有就装；Skills 默认不同步（要用加 `--skills`）。
3. **检查 Harness**：对 Claude Code、Codex 和 Antigravity 各真实调用一次模型（Antigravity 没登录时不调，它会等一分钟浏览器登录；调的那次在一个临时主目录里，对话不留在你的 `~/.gemini`）。没登录、网络不通会分别说明；没调通的不启用。终端的 `PATH` 里找不到的，再看 `~/.local/bin` 和 `~/.claude/local`（Claude Code 自己的安装器放的地方，后者平时靠 shell 别名才找得到），在那里找到就把那个目录加进服务的 `PATH`。没装的合成一行，写明不用每个都装、以后装了重跑就加上。装了 dsh、给它用的模型网关的密钥也在文件里时直接启用（不调用模型；密钥只在终端的环境变量里时服务拿不到，会说写进哪个文件），没装 dsh 不提。网络不通时问一次代理地址，通过后代理和飞书域名的 `NO_PROXY` 一起写进服务环境。启用了扩展时，扩展的安装钩子也在这一步运行（装它要的工具、报告它提供的 Harness）。
4. **飞书应用**：默认直接用手机扫码 3 步（建应用、授权、一键订阅事件与回调），并通过官方接口自动注册斜杠命令（`/usage`、`/board`、`/settings`；有代答扩展时加 `/proxy`），无需下载或启动无头浏览器，也不受企业租户条件访问/电脑端设备认证拦截。若在允许网页登录的机器上想扫一次码由浏览器代点，可加 `--browser`（登录态只在本次运行的临时目录里，结束就删，`--keep-login` 留下；若触发条件访问仍会自动切回手机扫码）。
5. **注册并启动服务**：把服务注册给后台的 Manager 托管并启动，再注册开机自启：Linux 用 systemd 用户服务，macOS 用 launchd，都没有但有 `crontab` 时加一行 `@reboot`（`--no-autostart` 不加），什么都没有时开机不会自启，安装器会说明。细节见[服务托管](operations.md#服务托管)。终端里设了 Harness 可能靠它登录的变量（`ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL`、`OPENAI_API_KEY` 这类，或名字像密钥的）时，安装器按服务自己的环境再调一次模型：服务清单不存凭据，终端里能调通不代表服务里也能。调不通时只列变量名（不打印值）和改法，见下面「出问题」。新服务收消息和写卡片走飞书 SDK（`COVEY_EVENT_TRANSPORT=sdk`、`COVEY_CARD_TRANSPORT=sdk`，收下的消息和点击先记在状态目录里，重启不丢）：服务的 Python 里没有 `lark-oapi` 时先用 pip 装（装进用户目录，或它所在的虚拟环境），装不上就照旧走 lark-cli、不影响使用，并说怎么补。在 git 检出里运行时，还在数据根写 `upgrade.json`，网页「版本与更新」和[定时自动升级](deploy.md#定时自动升级)照它升级。
6. **等待就绪，等第一个回答**：诊断通过后先打几行“装在这里”：数据根、状态目录（日志 `bridge.log` 在里面）、默认工作区、服务开着哪些功能，和多开的现成命令（演示套餐、单个开关、诊断），再打印「去飞书私聊机器人「Covey」发一句话」。没就绪时打出诊断的中文摘要。在终端里运行时，安装器接着读状态目录里的记录，等私聊里第一句话真的有了回答，最多 10 分钟，每到一步打一行（欢迎卡已发、收到了、启动卡在等你点「开始任务」、已回答）。Ctrl-C 不等；没有终端（`--non-interactive`、管道或后台运行）时不等，和以前一样打印完就退出；之前已经有过回答的部署也不等。等到超时不算安装失败，最后一行说该查什么（[排障](troubleshooting.md#扫码后机器人没反应)）。

`harnesses.json`（`<数据根>/harnesses.json`）里只写能用的 Harness；重跑时已启用的照旧，这次能用、上次写这个文件时不能用的 Claude Code、Codex、Antigravity 或 dsh 加进去（之后装好了它，重跑一次就启用；上次停在注册之前也一样，每次的结果记在 `<数据根>/install-harnesses.json`），你自己从文件里删掉的不加回；别的 Harness 见[手工加一个 Harness](harnesses.md#手工加一个-harness)。

## 没有 Claude Code 时

第 3 步 Claude Code 没调通（没装、没登录或调不通）、Codex 或 Antigravity 调通了时，新装的服务这样开：

- **管家用调通的那个**：先 Codex 后 Antigravity。安装器在服务第一次启动前把它写进状态目录里 `main-thread.json` 的 `harness`（文件里已经选了 Harness 的不动），私聊里照样是管家先接住每句话。
- **别的照常开**：专项（负责人也跑在这个 Harness 上，只读，见[专项 · 负责人只读](projects.md#负责人只读)）、整理专项和其余默认开关都和有 Claude Code 时一样，`--showcase` 同样把协作也开上。
- **辅助模型跟着管家**：整理专项、同时做几件事的分流这些后台的一问一答问管家用的 Codex 或 Antigravity，一次 6 到 15 秒（Claude Code 约 3.4 秒）。分流最多等 10 秒，超时按新开一件；嫌慢就装好 Claude Code，在设置卡把辅助模型选成它（[配置 · 辅助模型](configuration.md#辅助模型)）。
- **用不了的**只有 Claude Code 自己的功能：↩️ 回退、子 Agent 的模型（设置卡「诊断」页下半的“能做什么”写着）。
- 装好后的最后几行写着管家用的是哪个、Claude Code 这次为什么没调通（没装、没登录、网络不通），和装好 Claude Code 以后怎么换。

装好并登录 Claude Code 以后：

1. 重新运行 `./install`，它把 Claude Code 加进启用的 Harness；已经在跑的服务的开关一项不动。
2. 想让管家用 Claude Code：飞书里「设置」→「配置」的管家一段，把 Harness 换成 Claude Code（安装器不替你换回）。已有的专项负责人留在原来的 Harness 上，之后新开的专项跟着管家。

旧版本在只有 Codex 时装的服务，清单里没有专项这些开关，升级到这个版本后它们不设就是开的，不用再手动打开；重跑 `./install` 最后几行列出现在开着哪些、哪些被你设成了关，要改照[改开关三步](configuration.md#改开关三步)。重跑不改你开着或关着的开关，也不改你在设置卡上选过的管家 Harness。

## 网页工作台（可选）

默认不装。想在这台机器上自托管[网页工作台](web.md)（浏览器里看专项和话题）时，三种方式任选：

- **终端里问一次**：这台机器有 Node 22 以上和 npm、服务还没开过网页时，安装器问“要不要在这台机器上跑网页工作台”，默认不要；回答要，再问要不要让人在外面直接打开（只在出网地址是公网地址时问，默认不要，建议值是那个地址，可以改成别的 IP 或域名）。Node 或 npm 不够时不问。没有终端（`--non-interactive`、管道）时不问。
- **`./install --web`**：不问，直接装；Node 或 npm 不够时在最后的「还差」里说原因，不影响服务。
- **`./install --web-public ADDR`**：隐含 `--web`，同时开公网 HTTPS 直连。`ADDR` 是 IP 或域名，逗号分隔；写 `auto` 用本机出网网卡的公网地址（终端里让你确认，没有终端时直接用，找不到就只开本机地址并在「还差」里说）。

选了之后，安装器在检查 Harness 之后马上在后台构建（`web/deploy/selfhost/build.sh`，目录 `<数据根>/web/app`，要联网装依赖，约 1 GB、几分钟），输出在 `<数据根>/install-logs/web-build.log`，和扫码等步骤并行；第 5 步注册服务前等它（每分钟说一句还在构建，最多等 20 分钟）。成功后写好网页配置和开放接口密钥，并把开关随注册写进服务清单，Manager 起网页进程。Ctrl-C 或别的步骤失败时构建按进程组停掉。

没选就什么都不做：不检测 Node、不构建、不写开关，最后「想多开」里多一行 `./install --web`。重跑是安全的：服务清单里已经开着网页的照旧保留、不再问；没开过又没选的不开；显式 `./install --web` 重跑则升级构建（`web/deploy/selfhost/build.sh --restart`，正在跑的网页进程几秒内换成新版）。

构建失败（或超时、Node 不够）只在「还差」里写原因和日志位置，服务照常注册。改好后手动补：

```bash
bash web/deploy/selfhost/build.sh <数据根>/web/app && python3 -B -m covey.service.web_selfhost --data-root <数据根> --dir <数据根>/web/app/dist-selfhost
```

第二条会打印要在服务清单里设的开关，按[改开关三步](configuration.md#改开关三步)写进去；也可以直接重新运行 `./install --web`。

装好后最后几行写网页地址。公网直连时还有要放行的 TCP 端口（防火墙或云安全组）、自签证书的指纹和第一次访问怎么信任：浏览器提示不安全时核对指纹一致，再选“继续访问”。第一次登录：打开网页，飞书私聊里机器人发来确认卡，点「允许」。构建目录、公网和证书选项、备份与排障见 [web/deploy/selfhost/README.md](../web/deploy/selfhost/README.md) 和 [web.md](web.md)。

## 选项

| 选项 | 含义 |
| --- | --- |
| `--reconfigure` | 重来：重新建应用、授权、补配置并重注册服务。不加时，已有的应用、授权、配置、服务都复用，重复运行是安全的：要重新注册时（换了检出目录、服务没在运行），服务清单里已有的设置（包括用 `covey_service.py set` 改的开关）照旧，只有终端里设了的才盖过它，新版本的默认开关只写给新服务 |
| `--skills` | 同时同步 `skills/` 到 Codex 和 Claude 的 Skills 目录（`harness-bridge-onboarding`、`change-walkthrough`） |
| `--non-interactive` | 不提问；缺什么就报什么退出；最后也不等第一个回答 |
| `--data-home DIR` | 数据根（不给时用 `COVEY_DATA_HOME`，再不然是仓库同级的 `<仓库目录名>-data`） |
| `--workdir DIR` | 主目录，新话题从这里启动（不给时：重跑沿用上次注册的；在仓库里运行时终端里问一次，回车用 `<数据根>/home`） |
| `--keep-login` | 配合 `--browser` 时，不删浏览器里主人的网页登录（之后补配置可用 `covey_app_setup.py apply --login-from`） |
| `--browser` | 改用无头浏览器扫一次码完成建应用和授权（默认不用浏览器、直接手机扫码；若遇条件访问拦截仍会自动切回手机扫码） |
| `--no-browser` | 不用无头浏览器：每个链接画成二维码，用手机依次打开（已是默认，保留此选项以兼容旧脚本） |
| `--no-autostart` | 没有 systemd、launchd 时不往 crontab 加开机自启的一行 |
| `--profile`、`--app-name` | `lark-cli` profile 名（默认 `covey`）、新应用的名称（默认 `Covey`） |
| `--no-start` | 只准备到飞书应用为止，不注册、不启动服务 |
| `--web` | 在这台机器上自托管网页工作台（要 Node 22 以上和 npm）：后台构建，注册服务前等它，见[网页工作台](#网页工作台可选)；不加时终端里没开过网页的机器问一次 |
| `--web-public ADDR` | 隐含 `--web`，同时开公网 HTTPS 直连：IP 或域名（逗号分隔），`auto` 用本机出网网卡的公网地址 |
| `--showcase` | 演示套餐：默认开的之外，再开协作（开发中），见[演示套餐](configuration.md#演示套餐)；终端里已经设了的开关不动；没有 Claude Code 时也开整套。已经装好的服务：清单里已有的设置照旧，只打开套餐里清单没有或关着的开关（效果同 `covey_service.py set --preset showcase`） |

## 第一个回答

私聊里会有一张[欢迎卡](usage.md#第一次使用)，每个部署只发一次（服务起来后就发；那时发不出去的，你发第一句话后补上）：这台机器启用了哪些 Harness、哪些现在用不了、主目录在哪，有没有管家（没有时写着为什么、怎么补上）。点卡上三句只读示例旁的「发这句」，和你自己发这句话一样处理；三句依次是出答案卡、出问题卡、指到菜单「看板」。

也可以在飞书里私聊机器人，自己发「只告诉我当前工作目录，不修改文件」：

- 私聊顶层的话交给[管家](usage.md#管家)：它直接回答，或开一个话题去做、做完把结论带回私聊。Claude Code 调通了的管家用它，没有时用调通了的 Codex 或 Antigravity。
- 没有管家时（比如管家选过的 Harness 后来没启用），消息下出现启动卡，点「开始任务」，答案里的目录就是主目录。

看到回答就说明装好了，终端里的安装器这时也打印「已回答，装好了。」并结束。再花两分钟走一遍下面的验收，确认追问、停止、问答都正常（本地测试代替不了飞书客户端里的点击）：

1. **开话题**：私聊发「开个话题：只告诉我当前工作目录，不修改文件」。管家开出话题，话题里出现任务卡，结束后答案卡里的目录和主目录（`--workdir`）一致。
2. **追问**：在这个话题里回复「我刚才问了什么」，确认接着上文回答。
3. **停止**：在话题里发「等待 30 秒后报告当前目录，不修改文件」，执行中点任务卡上的「停止」，这一轮停下，别的话题不受影响。
4. **回答问题**：发「先问我希望用中文还是英文，收到回答再继续」，出现问题卡；选一项提交，任务接着执行。
5. **每个 Harness 一次**：要用几个 Harness，就在启动卡上各选一次它的模型跑第 1 步，确认都能真实调用。

## 装好以后

- **默认开着的**：管家、专项（连同叫醒负责人、停住问你、专项记忆、问题分流四个进阶开关）、整理专项（只提议）、早晚汇总（09:30 和 21:30）、菜单「看板」、置顶的「手上的事」和话题自动 Pin、同时做几件事、派发卡、管家规则、到点回来看、记忆和知识条目、撤回或编辑消息后跟着处理、自动补齐飞书应用。这些是代码里的默认，安装器不往服务清单里写；安装器只写飞书 SDK 收消息和写卡片两个开关（装得上 SDK 时）。没有 Claude Code 时也一样（[没有 Claude Code 时](#没有-claude-code-时)）。哪些开着、怎么关见[开关速查](configuration.md#开关速查)，改开关按[改开关三步](configuration.md#改开关三步)做；想把协作也打开，装的时候加 `--showcase`（[演示套餐](configuration.md#演示套餐)）。置顶和话题自动 Pin 要应用有置顶权限和“消息已读”事件，装完「飞书应用待补」卡会提示补齐。
- **怎么用**：一页纸的[五分钟上手](quickstart.md)；[使用指南](usage.md)从[第一次使用](usage.md#第一次使用)开始。
- **扩展**：装好后用 `bin/covey_plugins.py` 查看、启用、停用，见[扩展的装和卸](operations.md#扩展的装和卸)。
- **升级**：在仓库里运行 `scripts/upgrade.sh`（先加 `--dry-run` 看看）：它取上游的新提交，照服务清单原样的开关做部署前检查，再部署成固定的 release、重启机器人，成功后把检出快进过去，自托管的网页也跟着换成新版，见[日常升级](deploy.md#日常升级)。想每天自己升一次：服务清单里设 `COVEY_AUTO_UPGRADE=05:00`，见[定时自动升级](deploy.md#定时自动升级)。不要直接 `git pull`：`./install` 装的服务直接从这个检出运行，拉代码之后新开的任务立刻用新代码，机器人本身却还是旧的。

## 出问题

| 现象 | 做法 |
| --- | --- |
| 「安装停在这里：……」 | 下面一行「下一步」写着该做什么（换个能写的目录、装 Node.js、设代理、`--no-browser` 改用手机扫码……），日志在数据根的 `install-logs/`；照做后重新运行 `./install`，做完的步骤会复用 |
| 「没有能调通的 Harness」 | 先在终端里登录 Claude Code、Codex 或 Antigravity，并确认 `claude -p "ok"`、`codex exec --skip-git-repo-check "ok"` 或 `agy -p "ok"` 有回答 |
| 「claude 在服务里调不通」「codex 在服务里调不通」 | 终端里靠环境变量（API key、网关地址）调通的，服务里没有这些变量（服务清单不存凭据）。Claude Code：把这些变量写进 `~/.claude/settings.json`（设了 `CLAUDE_CONFIG_DIR` 就是它下面的）的 `"env"`，或在终端里运行 `claude` 用 `/login` 登录；Codex：`codex login`（API key 用 `printenv OPENAI_API_KEY \| codex login --with-api-key`）。改完不用重装，重新运行 `./install` 会再查一次 |
| Harness 探测像网络不通 | 先 `export HTTPS_PROXY=http://主机:端口` 再 `./install`；代理地址不能带用户名密码 |
| `--browser` 遇到条件访问或浏览器装不上 | 默认 `./install` 已不启浏览器，直接手机扫码 3 步 + 自动注册斜杠命令，不需电脑端设备认证；显式加 `--browser` 时遇到浏览器起不来或条件访问拦截也会自动切回手机扫码。非交互（没有终端）时把链接列出来，扫完后重新运行 `./install` 或等几分钟，机器人缺订阅时每 20 秒重试一次 |
| 「还差：……」 | 安装完成但有未生效的配置（如非交互时第 3 步手机扫码尚未点完）：不影响服务启动，扫完后重跑 `./install` 或等机器人自动生效 |
| 扫完码机器人一直没反应 | 订阅生效前收不到消息，约半分钟内自动就绪；还不行见[排障 · 扫码后机器人没反应](troubleshooting.md#扫码后机器人没反应) |
| 安装器等了 10 分钟没等到回答 | 不算安装失败，机器人照常在运行。启动卡在等你时点「开始任务」就开工；发了消息没反应见[排障 · 扫码后机器人没反应](troubleshooting.md#扫码后机器人没反应)，收到了却一直没回答见[排障 · 发消息后没有反应](troubleshooting.md#发消息后没有反应) |
| 其他 | 安装日志在数据根的 `install-logs/`（每步一个文件）；服务装好以后先跑 `python3 -B bin/covey_doctor.py`，它说哪里不对、下一步做什么；其余见[排障](troubleshooting.md) |
