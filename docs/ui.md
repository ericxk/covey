# UI 规范 · 夜航

管三处：① 飞书聊天里的卡片 ② 私聊底部菜单「用量」「看板」「设置」点开的结果卡 ③ 网页工作台（[网页工作台](butler.md)）。词、颜色、组件三处共用一份：状态词表和颜色在 `covey/core/look.py`，卡片组件在 `covey/cards/ui.py`，网页从 `scripts/export_look.py` 导出的 `look.json` 生成自己的 token。状态词也收在 [名词表](glossary.md#状态词)。

主人定的（2026-11-18、11-19）：

- 三处风格统一，要清爽、有视觉中心、要炫；文案和交互也算 UI。
- 方向是**夜航**（参考 Linear、Vercel）：一屏只有结论那块抢眼，其余颜色只表示状态。
- 卡片的结论带用**雾靛浅带 + 光晕 + 光球**，不用近黑色块（近黑色块在白卡片上太突兀）。网页是深色。
- 失败、中断、超时、官方拒绝统一叫**停住了**，原因放第二行；主人自己停的叫**已停止**，算背景。

这份规范是改动的目标。各张卡片、网页按第 10 节一路一路改过来；还没改的照旧（规则 10：旧卡片、旧记录照常能读）。

## 1. 原则

1. **先结论，再细节。** 每屏第一眼看到的，是结论或要你做的事。
2. **分清“要你处理”和“告诉你一声”。** 前者排最前、有主按钮；后者不抢眼。
3. **颜色只表示状态。** 品牌靛色只给视觉中心和能点的东西，其余是中性灰。不为好看加颜色。
4. **光也表示状态。** 光球的颜色就是最急那件事的状态色，不是装饰。
5. **同一个东西，三处同名、同色、同图标。** 词和颜色都从一张表来（`core/look.py`）。
6. **信息分三层。** 一眼看到、点开看到、专门去查。主人每天要看的放第一层。

- 中文用系统字体。**数字一律等宽**：网页用 `JetBrains Mono` 或 `ui-monospace`；卡片里大号数字也用等宽，飞书支持的话用 `<font>` 或代码样式（第 0 步验）。
- 字号分四级：视觉中心（卡片 24/30，网页 34/46）、标题 16、正文 14、注释 12。

## 3. 状态词表

| key | 词 | 来自哪些记录状态 | 归类 | 图标 |
| --- | --- | --- | --- | --- |
| `waiting` | **等你** | `waiting_user`；`waiting_workspace` 说成“等你开工” | 要你处理 | 时钟 |
| `stopped` | **停住了** | `failed`、`interrupted`、超时、官方拒绝、不是主人停的 `cancelled` | 要你处理 | 三角警示 |
| `stuck` | **可能卡住** | `running` 且 `maybe_stuck` | 要你看一眼 | 三角警示 |
| `result` | **有结果** | `done`、`continued` 且没看过；分组标题写“有结果没看” | 告诉你一声 | 勾 |
| `running` | **在做** | `running`、`cancel_requested` | 背景 | 转圈 |
| `queued` | **排队** | `queued` | 背景 | — |
| `done` | **做完** | `done` 且看过 | 背景，默认折起 | 勾 |
| `cancelled` | **已停止** | 主人自己停的 `cancelled` | 背景 | — |
| `idle` | **空闲** | 网页上没有任务的话题 | 背景 | — |

- **停住的原因放第二行**，用 `core/failure.py` 的那句话。例如“测试没过：test_web_sync 2 个失败，停在第 4/7 步”“重启打断，已保存到第 3 步”。
- **不再用的说法**：已完成、完成、✅ 完成、进行中、等你回答、需要你回答、有结果未看、做完没看、执行失败、失败、中断、已中断。
- **要先查清的一点**：现在看板把所有 `cancelled` 都算进“停住了”（`cards/board.py` STOPPED）。规范要求主人自己停的算“已停止”，所以记录里得能分清是谁停的（主人、专项负责人、护栏、网页上的停止）。第 0 步先查记录里有没有这个信息，没有就补一个 `stopped_by`。
- 旧卡片和旧记录里的词照常能读，不改历史卡（规则 10）。

## 4. 组件

每个组件在卡片里（`cards/ui.py`）和网页里各实现一份，名字一一对应。

| 组件 | 长什么样 | 卡片怎么做 | 网页怎么做 |
| --- | --- | --- | --- |
| **结论带** `conclusion_band` | 每屏的视觉中心。第 1 行是小标签（“要你处理”或“有结果 · T12 标题”），第 2 行是大字（“2 件事”或结论句），第 3 行是灰色补充，最后是要你做条或分段状态条 | `interactive_container`，底色 indigo-50，边框 indigo-100，圆角 10px，内边距 12/14 | 没有底色，直接放在深色页面上，背后一团靛色径向光 |
| **光晕** `halo` | 结论带外两圈，一圈比一圈浅 | 再套两层容器：外层 padding 3px、底 halo1，内层 padding 2px、底 halo2，圆角 15/12 | `box-shadow: 0 0 40px -12px <状态色>` |
| **光球** `orb` | 结论带右上角一颗 40px 的发光球，颜色 = 最急那件事 | 第 1、2 行做成 `column_set`，右栏 40px 放 img。4 张透明 PNG（橙、红、绿、蓝），启动时上传一次，缓存 image_key，关掉点击预览 | CSS 径向渐变加 `box-shadow`；等你和停住了时慢慢呼吸（2.4s） |
| **要你做条** `todo_bar` | “要你做”三个字是橙色，后面跟一句话 | 结论带里一个白底小容器 | 同 |
| **分段状态条** `seg_bar` | 一条 6px 的横条，按件数分成橙、红、绿、蓝几段，下面一行图例 | `column_set`，每段一列，按件数给 weighted 宽度，每列用状态色底 | flex 横条 |
| **话题行** `topic_row` | 状态点、状态词、“T号 标题 ›”、一句人话、一行灰色数字，按钮在右 | 看板（`cards/board.py`）的 `block` 改成：浅色底、状态只用点和字；整块可点（`open_url`） | 列表行，悬停提亮 |
| **状态胶囊** `state_pill` | 圆角小标签：图标加状态词 | `text_tag`，用状态色 | 圆角胶囊，状态色 12% 透明底 |
| **进度条** `progress` | 5px 高，按步数算 | 话题行里不放，用“5/8 步”的文字代替（卡片太挤） | 渐变加流光动画 |
| **数字磁贴** `tiles` | 大号等宽数字加一行小字 | `column_set` 平分 | grid |
| **输入/输出框** `io_box` | 两行灰字，项和项之间用“｜”隔开 | 现有的 `cards/answer_card.py`，不动 | 同样的两行 |
| **折叠行** `fold_row` | 产物、改动、做完的话题 | 现有的 `collapsible` | 可展开的行 |
| **标题栏** `panel_header` | 图标、标题、副标题，右边是计数标签 | 现有的 `panel_header`，标题栏一律 `default` 模板，不用彩色标题栏 | 面包屑加同步状态 |

**光球选色**：按“等你 → 停住了 → 可能卡住 → 有结果 → 在做”的顺序，取第一个有的。一件都没有时不放光球，结论带写“都在掌握中”。结果卡上的光球用这一轮自己的状态色。

## 5. 每一屏怎么排

### 5.1 通用顺序

1. 结论带（加光晕和光球）。
2. 要你处理：等你 → 停住了 → 可能卡住。每块最多一个主按钮。
3. 告诉你一声：有结果。
4. 背景：在做、专项、排队；做完的折起来。
5. 末行灰字：“更新于 23:52”。

### 5.2 各屏

| 屏 | 结论带写什么 | 其余 |
| --- | --- | --- |
| 聊天结果卡（任务卡结束后、回带） | “有结果 · T12 标题”，下一行写结论句，再加要你做条（没有要你做的就不放） | 回答正文 → 产物、改动（折叠）→ 输入/输出框 → 按钮 |
| 任务卡（在跑） | 状态行就是结论：在做或可能卡住，后面写“现在：xxx”，加步数和预计时间 | 执行过程（折叠）、补充、停止 |
| 问题卡 | “等你 · T12”，下一行写“要你定：xxx” | 题目、选项、提交回答 |
| 停住的卡（恢复卡） | “停住了 · T12”，下一行写原因 | 检查并继续、换个模型、看原因 |
| 菜单「看板」 | “要你处理 N 件事”，加分段状态条；没有就写“都在掌握中” | 照现在看板的顺序，块改成话题行 |
| 菜单「用量」 | “本周 33.8M token”，下一行写“146 个任务 · 缓存命中 91%”这样的总数 | 磁贴、各 Harness 占比、每日趋势；结束状态用 3.1 的词 |
| 菜单「设置」 | 不放结论带，标题栏加标签行 | 开关和选项；保存后用一句灰字回执 |
| 网页首屏 | “2 件事要你处理”，大号数字，外加光球 | 要你处理的卡片 → 在做（带进度条）→ 有结果没看；右栏放专项、本周用量 |

### 5.3 信息分三层

| 层 | 卡片 | 网页 |
| --- | --- | --- |
| 一眼看到 | 结论带、状态词、主按钮 | 首屏结论、要你处理 |
| 点开看到 | 产物、改动、执行过程、任务详情、做完的折叠 | 话题页、专项页 |
| 专门去查 | 下载请求与结果；在网页上打开 | 搜索、用量页、历史 |

## 6. 按钮

| 操作 | 叫法 | 替换掉的写法 |
| --- | --- | --- |
| 去答题 | 去回答 | — |
| 没成功，接着做 | 检查并继续 | — |
| 换模型再试 | 换个模型 | — |
| 看为什么停 | 看原因 | — |
| 不用再管 | 不管了 | 取消（指“不要了”时）、算了、暂不考虑、这些先不补 |
| 停掉在跑的 | 停止 | ⏹ 停止 |
| 补一句 | 补充 | 📝 补充 |
| 进话题 | 打开话题 | › 打开话题串 |
| 去看板 | 去看板 | — |
| 记为看过 | 记为看过 | — |
| 换配置 | 换配置 | 🔁 换配置 |
| 回退一轮 | 回退 | ↩️ 回退 |
| 刷新 | 刷新 | 🔄 刷新 |

规则：

- 动词开头，2 到 5 个字，不带 emoji。要图标就用飞书 `standard_icon`（卡片）或线性图标（网页）。
- 每块最多一个主按钮（卡片 `primary`，网页实心靛色）。其余是边框按钮；“不管了”这类放弃的操作用文字按钮。
- 停止、回退、删除这类会丢东西的操作，不能做主按钮。
- 表单里取消填写仍叫“取消”，只有“不要这件事了”统一叫“不管了”。

## 7. 文案

- **先说事，后说系统**：写“测试没过，停在第 4/7 步”，不写“任务执行异常”。
- **称呼主人用“你”**，不用“用户”“主人”；界面上不出现代号（waiting_user、cancelled、job id）。
- **固定前缀**：要你定：／要你做：／现在：／目标：／原因：。
- **数字**：带单位，数字和单位之间留空格，如“6 分钟”“2.1M token”“5/8 步”“约 15 分钟”。
- **时间**：今天写 23:10，不是今天写 11-17 23:10；网页超过 3 分钟没同步，时间变橙色。
- **分隔**：同一行几项之间用灰色“｜”；分组计数和面包屑用“·”。
- **空状态**说一句让人安心的话：都在掌握中、现在没有在等你的事。不写“暂无数据”。
- **不写**“成功”“已为你”“请注意”“温馨提示”，不加感叹号。
- 一句话超过 40 字就拆开，第二句放到第二层。

## 8. 手机和电脑

- **卡片**：每张都在手机宽度（约 375px）和话题侧栏（约 300px）各验一次。带边框的按钮有最小宽度，一行最多两个。状态词不折行（`white-space` 做不到时，把词控制在 4 个字以内）。
- **网页**：
  - 宽度 ≥1024px：三栏，侧栏 248px，主栏，右栏 316px。
  - 768 到 1024px：右栏挪到主栏下面。
  - <768px：单栏，加底部标签栏（看板、管家、专项、话题）。首屏仍是结论加要你处理，按钮至少 40px 高。
- **深色和浅色**：网页先只做深色。卡片跟着飞书的深浅色模式走，两种都要验。

## 9. 动效（只有网页有）

| 什么 | 怎么动 |
| --- | --- |
| 光球 | 等你、停住了时慢慢呼吸（2.4s，亮度和光晕大小起伏 ±15%）；有结果、在做时不动 |
| 进度条 | 在做时有一道光从左到右扫过（2s）；可能卡住时不扫，变成橙色 |
| 数字变化 | 滚动到新值（300ms） |
| 新出现的要你处理 | 从上方滑入，光晕亮一下 |

- 系统设置了“减少动态效果”（`prefers-reduced-motion`）时全部关掉。
- 一屏同时在动的东西不超过 3 个。

## 10. 怎么开工

### 第 0 步：共享的部分（已做）

只抽代码、加组件，任何一张已有卡片的 JSON 都不变（`tests/golden/cards.json` 没有 diff）。

1. **`covey/core/look.py`**（只用标准库）：`STATES` 是第 3 节的词表（词、归类、飞书色名、块底色、网页色、图标），`BRAND`、`WEB` 是第 2 节的颜色；`tone(status, seen=, stuck=, by_owner=)` 和 `record_tone(record)` 把记录状态换成词表的 key；`orb(counts)` 按第 4 节的顺序选光球的颜色；`RETIRED` 是要换掉的旧说法。看板（`cards/board.py` LOOKS）的五个状态和这张表一致，由 `tests/test_look.py` 核对。
2. **`covey/cards/ui.py`**：`conclusion_band`（带光晕两圈和光球）、`todo_bar`、`seg_bar`、`topic_row`、`state_pill`、`state_word`、`number`。还没有卡片用它们，各路改卡时再用。
3. **光球图片**：`covey/core/orb_image.py` 用标准库画出每种状态的透明 PNG（同一状态每次字节相同，仓库里不放图片文件）；`covey/feishu/orb_images.py` 的 `orb_key` 第一次用时以机器人身份上传，image key 存在 `<state>/look/orbs.json`，按机器人、状态和图的哈希区分，图改了才重传。上传失败返回空，卡片照发、只是没有光球。上传是网络请求，不在记录锁内调用（规则 1）。
4. **网页数据约定 v5**：`topic` 条目在 `state` 之外多带 `tone`（第 3 节的 key，`app/web_sync.py` 的 `Collector.tone`）。网页按 `tone` 上色、取词，不再比较中文字；`state` 照旧，老网页不受影响。`python3 -B scripts/export_look.py --out look.json` 导出词表，网页的 token 由它生成。
5. **谁停的**：记录的 `cancel_requested_by` 写停止来源（`core/jobs.py` 的 `STOP_SOURCES`）：任务卡上的停止 `card`、对管家说停 `word`、网页上的停止 `web`、专项卡上的停止 `project`、主人撤回了任务的原消息 `recall`，这五个是主人自己停的（`look.OWNER_STOPS`），算**已停止**；负责人停的 `lead`、专项护栏停的 `guard`、代答换批次停的 `proxy` 算**停住了**。排队时取消的（`never_started`）也是主人的。旧记录只有 `card`，照旧读成主人停的；没有来源的 `cancelled` 读成停住了。停止来源走卡片点击的 `by` 字段，老版本的任务进程不认它，照旧记成 `card`。
6. **真机样卡**：结论带、光晕、光球、分段状态条，在手机和电脑、浅色和深色模式各看一次。要验：
   - indigo-50 这类色名能不能用；
   - 套三层容器的内边距会不会被吃掉；
   - 透明 PNG 的边缘好不好看，点图会不会弹预览；
   - 等宽数字能不能做出来。
   不行的，按第 11 节的退路改，改在 `cards/ui.py` 一处。

### 然后三路并行

| 路 | 改什么 | 主要文件 | 验收 |

## 11. 风险和退路

| 风险 | 退路 |
| --- | --- |
| 飞书不认 indigo-50 这类色名 | 用卡片 2.0 的自定义颜色 `config.style.color`，分别给 light_mode 和 dark_mode 两个值 |
| 三层容器的内边距被吃掉，光晕看不出来 | 只留一层：边框 indigo-200，底 indigo-50 |
| 透明 PNG 边缘发灰，或点了弹出预览 | 光球改成飞书 `standard_icon` 的实心圆点，放大到 20px，用状态色，不发光 |
| 卡片做不出等宽数字 | 用加粗大号数字，不强求等宽 |
| 卡片太长（超过 CardKit 大小上限） | 结论带和光晕只用在面板卡和结果卡上，任务卡在跑时不加光晕 |
