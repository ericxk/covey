# UI 规范 · 夜航

管三处：① 飞书聊天里的卡片 ② 私聊底部菜单「用量」「看板」「设置」点开的结果卡 ③ 网页工作台（[网页工作台](web.md)）。词、颜色、组件三处共用一份：状态词表和颜色在 `covey/core/look.py`，卡片组件在 `covey/cards/ui.py`，网页从 `scripts/export_look.py` 导出的 `look.json` 生成自己的 token。状态词也收在 [名词表](glossary.md#状态词)。

定下的方向：

- 三处风格统一，要清爽、有视觉中心、要炫；文案和交互也算 UI。
- 方向是**夜航**（参考 Linear、Vercel）：一屏只有结论那块抢眼，其余颜色只表示状态。
- 卡片的结论带用**浅靛底、上深下浅的细色阶渐变、一条细边**，不用近黑色块（在白卡片上太突兀），不加光球（突兀），不在四周套光晕圈（边缘发虚、看着头晕），色阶相邻只差 1%（3% 就看得出条纹）。网页是深色。
- 失败、中断、超时、官方拒绝统一叫**停住了**，原因放第二行；主人自己停的叫**已停止**，算背景。
- **夜航 v2**：网页一屏只留一块有底色和大字的东西（结论带，“炫”只在带子里：顶沿高光、右侧淡出的细网格），其余退成无框的行、发丝线和灰度文字；不框套框；侧栏一行一条不折行、T 号在行尾；话题页顶部是结论带（结论句、要你定和主按钮、“现在”一行），不是三行表；右栏只做索引，不重复主栏。

- **方案 X（状态优先，网页）**：业界调研三组都提到的结构改动。侧栏顶上先按状态分「要你处理」「在做」两组（每行两行字：谁，加一行灰字写要你定什么、停在哪、现在在做哪一步；右边等了多久或第几步），专项树在下面；话题页里在跑的一轮把过程折成一行（N 步 · 本轮用时 · 现在在做什么，点开才是瀑布图），输入框上沿居中一颗运行胶囊；输入框是主框加一条浅灰底座；结论带改成浅灰底简报；看板的要你处理改成一列收件箱。配色换成中性灰，状态色不变。

这份规范是卡片和网页的目标样子。还没照它改过来的卡片照旧能用（规则 10：旧卡片、旧记录照常能读）。

**改外观之前先读两节**：[第 12 节](#12-改外观先选样张)（先出 2~3 版样张让主人点选，再实现）和[第 13 节](#13-拍板记录)（已经拍板的规则，`tests/test_ui_rules.py` 逐条核对，测试不过就是改回去了）。

## 1. 原则

1. **先结论，再细节。** 每屏第一眼看到的，是结论或要你做的事。
2. **分清“要你处理”和“告诉你一声”。** 前者排最前、有主按钮；后者不抢眼。
3. **颜色只表示状态。** 品牌靛色只给视觉中心和能点的东西，其余是中性灰。不为好看加颜色。
4. **边缘清楚。** 卡片做不出真阴影和渐变，就不硬做：一条细边，渐变只在带子里面、细到看不出台阶。
5. **同一个东西，三处同名、同色、同图标。** 词和颜色都从一张表来（`core/look.py`）。
6. **信息分三层。** 一眼看到、点开看到、专门去查。主人每天要看的放第一层。

### 2.2 状态色

| 状态 | 网页 | 卡片文字和标签（飞书色名） | 卡片块底 |
| --- | --- | --- | --- |
| 等你 | #F5A524 | orange | orange-50 |
| 停住了 | #F2555A | red | red-50 |
| 可能卡住 | #F5A524，外加 2px 淡环 | orange | orange-50 |
| 有结果 | #3DD68C | green | green-50 |
| 在做 | #4C9AFF | blue | blue-50 |
| 排队、做完、已停止、空闲 | #5B6270 | neutral 或 grey | grey-50 |
| 专项（对象色） | 网页不用（夜航 v2：专项靠位置认） | violet | violet-50 |

- 卡片只用飞书自带的色名（`orange`、`orange-50`、`indigo-50`……），深色模式由飞书自动换。表里的 hex 只是网页和样张用的近似值。
- 不再出现：同一状态在不同卡上用不同的色（以前“中断”在状态卡上是红、在用量卡上是橙）。
- **橙色只说两件事**：等你（包括“等你确认”“N 条建议”这类等你定的）和可能卡住。缺配置、未确认、处理中这类不是在等你的，用中性灰或它对应状态的色（处理中是在做的蓝）；护栏停住的专项是“停住了”的红。整理专项等你定的提议是等你：看板、手上的事和早晚汇总都把它列在“等你”下面（橙色圆点和词，“提议”标签是专项的紫色），算进“要你处理”。
- **话题的身份色不是状态色**：私聊区话题的 T 号头像（第 4 节“话题头像”）用 12 种深色底白字（`look.TOPIC_COLORS`），按 T 号分，只用来分清是哪个话题，不说状态；状态仍只看旁边的标签（浅底彩字）。这是第 1 节“颜色只表示状态”唯一的例外。
- **红字不放在红底上**：红色只给停住了的字、标签、图标和分段状态条，卡片里不画红底（`red-50`）的块，也不用红色标题栏，失败卡上的正文是正文色。`tests/test_look.py` 拿样张核对这两条。

### 2.3 字

- 中文用系统字体。**单独显示的数字等宽**（计数、时间、耗时、表格里的数，要对齐、会跳的）：网页用 `JetBrains Mono` 或 `ui-monospace`，界面字体里的这类数字用 `tabular-nums`；句子和标题里的数字（回答正文、你说的话、结论句、标题、侧栏话题名）跟着正文用比例数字，SF Pro 的等宽“1”两边各空一块，“11/24”“T12”夹在句子里看着松。卡片里大号数字也用等宽，飞书支持的话用 `<font>` 或代码样式（第 0 步验）。
- 网页的英文和数字也用系统界面字体（参考 Codex 桌面版）：Mac、iOS 上是 SF Pro，Windows 上是 Segoe UI，没有时用网页自带的 Inter；等宽在 Mac 上是 SF Mono，别处用自带的 JetBrains Mono，等宽里夹的中文落到同一套中文字体。中文引号“”‘’用中文字体画（全角）。
- 字号分四级：视觉中心（卡片 24/30）、标题 16、正文 14、注释 12。
- 网页的渲染：深色开 `-webkit-font-smoothing: antialiased`（浅字深底不加粗，不发胀）；**浅色不开**：Mac 上它会关掉系统给浅底深字的笔画加粗，苹方和 SF Pro 的常规体被削细发虚，粗体看不出来，所以只有不加粗的字显得“差点意思”。浅色里彩底白字的小块（实心 T 号、主按钮、logo）照旧开。浅色界面正文灰（`--t2`）是 #353A46。
- 网页（夜航 v2）收成七档、字重只用 400/500/600：看板结论数字 72/72 等宽（全页唯一的渐变字）、结论句 28/36（看板）和 18/26（话题页）、右栏数字 28 或 20 等宽、长文 14/24、行标题 14/20（500）、界面正文 13/20、注释 12/18、小节标签 11（字距 .06em，最暗一档灰）。

### 2.4 正文排版（网页）

话题页的回答、大厅和专项页的负责人对话是要读长文的地方，按下面排：层次清楚，同时一屏能看到的内容够多。网页前端（不在本仓库）对应的样式表（`reading.css`）和这里的数值保持一致，改一处同时改另一处。

| 什么 | 数值 |
| --- | --- |
| 正文 | 15px，行高 1.78，段距 12px |
| 行宽 | 铺满对话列（列宽 740px），回答和你说的话右边对齐；大厅、专项页和话题页一样 |
| 标题 | 一级二级 17.5px、上 22 下 8；三级 15px、上 14 下 6；再往下 15px。字重 600，标题不比正文小 |
| 列表 | 项间 3px，列表后 10px，项内行高 1.65 |
| 代码、表格 | 行内代码和代码块 12.5px；表格 13px，单元格 5px 10px |
| 你说的话 | 靠右的气泡，品牌色浅底和边线、14px；答题的那句在气泡里画成“问题 → 选择”的表 |

- **一轮在大厅和话题页画法一样**：你说的气泡 → 谁、几点（管家、负责人是名字的头一个字，话题是 Harness 的图标和名字）→ “工具 N · 用时 · token”一颗，点开是过程（瀑布，下面一行 token、速度、上下文）→ 回答正文（直接铺在底上，不套框，是主角）→ 图、产物 → 没做完时的原因和按钮。话题页整页就是这样一条对话，不再有“第 N 轮：你 → 结论”的行（和大厅完全一样），找某一轮靠左边刻度。区块之间 10px。正文不套面板：框套框是“密”的第一来源。
- **跳到某一轮**：比半屏高的一轮从开头露出来，不居中；滚动区上方留 16px 并淡出，切到一半的行不能看着像被上面的卡片盖住。

### 2.5 表格和弹层（网页）

回答里的 Markdown 表格，宽表格的右边几列不能被裁掉。网页前端（不在本仓库）里对应 `MdTable.tsx` 和 `table.css`。

| 什么 | 数值 |
| --- | --- |
| 框 | 表格放在一个能横向滚的框里：1px 发丝线、圆角 10px；表格按内容取宽，比框宽就在框里滚，不裁掉 |
| 列宽 | 表头和短单元格（数字、百分比、短词）不折行；长文字列到 28em 才折行（手机 13em，弹层里 24em） |
| 单元格 | 13px，行高 1.55，内边距 5px 10px；表头 500、次一档灰、面板底 |
| 还能往右滚 | 右缘 40px 渐隐到页面底色，滚到头就没；往右滚过以后左缘同样渐隐 |
| 放大 | 右上角 28px 的放大按钮（手机 32px），悬停时出现，触屏一直在 |
| 弹层 | 遮罩深色 72% 加 4px 模糊（浅色 35%）；面板最宽 1400px、圆角 16px、1px 边；头部 48px（标题、提示、关闭）；表格在面板里横向、纵向都能滚；Esc、关闭、点遮罩都能关。手机上铺满全屏 |

### 2.6 数学公式（网页）

回答、你说的话和负责人对话里的 LaTeX 公式按 Codex 的习惯排出来（KaTeX，随前端打包、字体自托管，不连外网）。网页前端（不在本仓库）里对应 `mathText.ts`（哪些算公式）、`mathRender.ts`（渲染）和 `math.css`。

| 什么 | 规则和数值 |
| --- | --- |
| 行内公式 | `$…$`、`\(…\)`；比正文大一点（1.1em），和正文同一基线、同色 |
| 块级公式 | `$$…$$`、`\[…\]`（可以跨行，不能有空行）和 ` ```math ` 围栏；居中，上 8 下 12，比对话列宽时在自己的框里横向滚动（1.16em，手机 1.08em） |
| 不当公式的 | 代码块和行内代码里的；链接的网址（Markdown 链接和图片的网址、`[id]:` 引用定义、`<https://…>`、裸的 `https://…`、`www.…`；链接文字里的公式照常排）；`\$` 转义的；文件路径里夹在两个 `/` 之间的一段（`/docs/$fee$/latest`、`./$x$/a`、`/srv/$name$.txt`）；美元金额和变量（`$5`、`$10 - $20`、`$HOME`、`$PATH/$USER`）：行内 `$` 开头后面紧跟非空白、结尾前面紧跟非空白且后面不是数字或字母才算；行文里 `\[1\]`、列表里 `- \[x\]` 这类转义了的方括号（单独占一行的 `\[x\]`、`\[42\]` 是块级公式）；` ```latex ` 围栏是给人看的源码，照旧当代码 |
| 没闭合的 | 流式输出写到一半的 `$$`、`\[`、`$` 原样显示，闭合了才排成公式，不报错、不打乱排版 |
| 写错的 | 不抛错：原文画成次一档灰（`--t3`）、等宽、虚下划线，悬停看错误说明；太长（超过 1 万字）的显示 TeX 原文 |
| 颜色 | 跟着正文走（KaTeX 用 currentColor），深浅色主题不用另配 |
| 复制 | 选中公式复制时剪贴板里是 LaTeX 原文（KaTeX 的 copy-tex）；回答下面的复制按钮复制的本来就是 Markdown 原文 |
| 安全 | KaTeX 的 `trust` 关着：`\href`、`\url`、`\includegraphics`、`\htmlClass` 这类命令不生成链接、图片和属性；正文里的原始 HTML 照旧不渲染 |

## 3. 状态词表

| key | 词 | 来自哪些记录状态 | 归类 | 图标 |
| --- | --- | --- | --- | --- |
| `waiting` | **等你** | `waiting_user`；`waiting_workspace` 说成“等你开工” | 要你处理 | 时钟 |
| `stopped` | **停住了** | `failed`、`interrupted`、超时、官方拒绝、不是主人停的 `cancelled` | 要你处理 | 三角警示 |
| `stuck` | **可能卡住** | `running` 且 `maybe_stuck`（最新一步是还在跑的命令时不算：写“在等一条命令跑完 · 已 38 分钟”，仍是在做的蓝色） | 要你看一眼 | 三角警示 |
| `result` | **有结果** | `done`、`continued` 且没看过；分组标题写“有结果没看” | 告诉你一声 | 勾 |
| `running` | **在做** | `running`、`cancel_requested` | 背景 | 转圈 |
| `queued` | **排队** | `queued` | 背景 | — |
| `done` | **做完** | `done` 且看过 | 背景，默认折起 | 勾 |
| `cancelled` | **已停止** | 主人自己停的 `cancelled` | 背景 | — |
| `idle` | **空闲** | 网页上没有任务的话题 | 背景 | — |

- **停住的原因放第二行**，用 `core/failure.py` 的那句话。例如“测试没过：test_web_sync 2 个失败，停在第 4/7 步”“重启打断，已保存到第 3 步”。
- **不再用的说法**：已完成、完成、✅ 完成、进行中、等你回答、需要你回答、有结果未看、做完没看、执行失败、失败、中断、已中断。
- **谁停的**：主人自己停的算“已停止”，负责人、护栏或代答换批次停的算“停住了”，按记录的 `cancel_requested_by` 分（见[第 10 节](#10-代码在哪)第 6 条）。
- **执行过程里的一步**：在跑的面板标题写“在做”，一步没成功写“出错”（这是一步的结果，不是话题的状态）；命令或检查自己报的错照原样。管家快照的分组名和结局（`core/turn_words.py` 的 `GROUP_NAMES`、`RESULTS`）已经是上表的词。
- 旧卡片和旧记录里的词照常能读，不改历史卡（规则 10）。

## 4. 组件

每个组件在卡片里（`cards/ui.py`）和网页里各实现一份，名字一一对应。

| 组件 | 长什么样 | 卡片怎么做 | 网页怎么做 |
| --- | --- | --- | --- |
| **结论带** `conclusion_band` | 每屏的视觉中心。第 1 行是小标签（“要你处理”或“有结果 · T12 标题”），第 2 行是大字（“2 件事”或结论句），第 3 行是灰色补充，最后是要你做条或分段状态条 | 每一行一个 `interactive_container`，底色从 `band-0` 往下一行浅一档（相邻差 1%），外面一个容器只画 1px 细边 `band-line`、圆角 10px；颜色是卡片自己的 `config.style.color`，用到结论带的卡片过一次 `ui.styled` | 网页的话题页是浅灰底简报（大字 20px，不画渐变、网格和描边）；看板顶上的大数字那块同样浅灰底 |

### 4.1 短标签不折行、不被挤

状态胶囊、徽标（推荐、你说的、它总结的）、序号、T 号、计数、时间、头像字这类**短标签**，在任何宽度下都是一行（问题卡的“推荐”曾被旁边的长描述挤成“推/荐”两行）。

- **规则只有一条**：短标签 `white-space: nowrap` 加 `flex-shrink: 0`。旁边的长文字再长，被挤、被折行的只能是长文字自己。
- **网页的做法**：网页前端（不在本仓库）的 `tags.css` 里一条公共规则，列着所有短标签的类；新写的短标签加 `class="short"` 或加进这张表，不逐处补样式。`npm run test:tags` 核对这条规则还在、表里该有的类都在、别处没有把它们改回能折行或能压缩、页面代码里新出现的像短标签的类名（…tag、…pill、…badge、…cnt、…tno、…flag）都在表里。
- **带徽标的行，布局不随徽标变**：问题卡的选项分三列——序号一列（固定 18px）、文字一列、徽标一列（按内容宽）。有没有徽标，序号和文字的左边都不动；徽标不占文字的位置。
- **卡片**：飞书卡片里的短标签用 markdown 的 `<text_tag>`（`cards/ui.py` 的 `state_pill`），怎么折行由飞书客户端决定；这条规则目前只管网页。

### 5.1 通用顺序

1. 结论带。
2. 要你处理：等你 → 停住了 → 可能卡住。每块最多一个主按钮。

### 5.3 私聊区：谁在说、话交给谁、要你定的事

- **谁在说**：管家、专项负责人、各个话题都用同一个机器人发消息，每条顶层消息都带说话人（第 4 节 `speaker`）。
- **话交给谁**：回复哪条消息，就交给发它的那一方：话题的回带交给那个话题，负责人的回答和专项卡交给负责人，管家的回答交给管家；不经管家转。
- **负责人说什么**：你发起的轮次每轮都发；负责人自己醒来的轮次，派了活、停了话题、替你答了或转交了问题、记了按风格该报的进展才发，没变化只更新专项卡。
- **要你定的事**：谁问都走问题卡、进“等你”，不只在回复末尾问一句；管家也一样。

## 7. 文案

- **先说事，后说系统**：写“测试没过，停在第 4/7 步”，不写“任务执行异常”。
- **称呼主人用“你”**，不用“用户”“主人”；界面上不出现代号（waiting_user、cancelled、job id）。
- **固定前缀**：要你定：／要你做：／现在：／目标：／原因：。
- **数字**：带单位，数字和单位之间留空格，如“6 分钟”“2.1M token”“5/8 步”“约 15 分钟”。
- **时间**：今天的只写时刻（`23:10`），不带日期；网页超过 3 分钟没同步，时间后面加一句灰字“N 分钟没同步”（不用橙色：橙色只给等你和可能卡住，见 2.2）。
- **分隔**：同一行几项之间用灰色“｜”；分组计数和面包屑用“·”。
- **空状态**说一句让人安心的话，而且说的是真的，不写“暂无数据”。三种情况分开写：**还没有话题**（第一次用：写“还没有话题”，下面一行说先做什么——在私聊里发一句要做的事）；**这里显示的是某个时刻的记录**（卡上的内容是那个时刻读的、之后没重读：写“08:00 时没有等你的事”，下面说不是现在的、点刷新看现在的；现在只有「看板」里点“不管了”后按旧记录重画的那张，网页的同步提示在前端，不在这个仓库）；**现在没有等你的事**（真的清空了：都在掌握中、现在没有在等你的事）。
- **不写**“成功”“已为你”“请注意”“温馨提示”，不加感叹号。
- **网页上发出一个操作的几句话**（`web/client/src/cv/opWords.ts`，所有发件按钮共用）：请求还在路上写“发送中…”；请求写进了网页库（Covey 在线马上办，不在线也会接着办）：输入框发的话写“✓ 已发出”（气泡从半透明变成正式的样子），按钮、问题卡、看板卡写“已发出，等 Covey 处理…”；Covey 回执了写它回的原话（“已开下一轮”“已作为补充交给在做的任务 #…”，没写话才用“已执行”）；没办成写“没办成：原因”，请求没发出去写“没发出去：原因”；等满一分钟还没回音写“Covey 还没回音：操作留在发件箱里，Covey 回来会接着办”，不算失败。点了就锁：看板快速答题、不管了、接着做点后立刻禁用或收起、写“已发出，等 Covey 处理…”，到回执或等满才放开；停止点后写“正在停…”并禁用，到话题不在跑、失败或等满才放开；问题卡等请求真发出去才写“已发出”，之前写“发送中…”。
- 一句话超过 40 字就拆开，第二句放到第二层。

## 8. 手机和电脑

- **卡片**：每张都在手机宽度（约 375px）和话题侧栏（约 300px）各验一次。带边框的按钮有最小宽度，一行最多两个；按字宽排、窄了自己折行的按钮行（`flow`，如问题卡的选项）不受这条限制。状态词不折行（`white-space` 做不到时，把词控制在 4 个字以内）。
- **状态词在标题前面**：标题再长，截掉的只是标题。任务卡状态行第一个词就是状态词，标题只在标题栏（截到 24 个字）；话题列表的预览先写 T 号再写状态词（“T28 在做 · …”“T28 有结果 · …”“T28 · #431 等你 · …”）；看板的话题行先是状态点和词。`tests/test_long_titles.py` 核对。
- **网页**：
  - 宽度 ≥1024px：三栏，侧栏 248px，主栏，右栏 316px。
  - 侧栏顶上是「要你处理」「在做」两组（和看板、侧栏角标同一口径），每组收着时最多 6 行，多出 1 个就直接列出；要你处理多的写“还有 N 件，在看板里”，链到看板；在做多的写“还有 N 个在做”和折起来的 T 号，点开列全、再点「收起」（记在这台浏览器上）；行首照旧是话题头像（管家、负责人、停住的专项用头像），右下角是状态点。专项树和最近话题在它们下面。
  - 侧栏的先后不跟着同步抖：快照每秒取一次，在跑的话题每写一次进度 `updated_at` 就变，不能拿它排。在做组、专项里和最近话题里等你／在做／停住的那几行按编号大的在前（同看板的在做）；专项先分档（要你处理 → 有话题在做 → 其余），同一档里按不算在跑话题的最近活动排。鼠标（触控笔）在侧栏里动着时画的是鼠标进来那一刻的样子，移出侧栏或停着不动 5 秒才换成最新的，正要点的那行不会从鼠标底下挪走；手机抽屉照常跟着同步。
  - 电脑上是“外槽 + 画布”：侧栏直接铺在外槽上（不画右边线），主栏和右栏是一块四周留 8px、圆角 12px 的画布，右栏并进画布、只留一条发丝线；画布是面板色（浅色白，深色 #0D0F13），浅色外槽是浅灰，深色外槽压暗到 #060709、画布一圈细亮边。画布里拿 `--bg` 当遮罩的跟着画布色。侧栏选中的那行在浅色里是白底一圈细边。手机照旧铺满。
  - 侧栏的专项分组：负责人不另占一行，是专项标题行右侧的一个图标（负责人在做或等你时带状态点），和专项名去同一页；下面的话题用同一套格子（状态点 12px｜T 号 32px｜标题），整体缩到专项名下面。选中只换底色，不加竖条，也不改布局。
  - 768 到 1024px：右栏挪到主栏下面。
  - <768px：单栏，加底部标签栏（看板、大厅、专项、话题、设置）。首屏仍是结论加要你处理，按钮至少 40px 高。「专项」是一页专项一览（一个专项一张卡，卡下是要紧的话题），不是侧栏抽屉；专项页的磁贴在手机上收成标签下面一行。
- **深色和浅色**：网页默认深色，也有浅色；切换是一个常驻的线性图标（电脑在侧栏底部「设置」旁，手机在顶栏最右），设置页不另放一块。卡片跟着飞书的深浅色模式走，两种都要验。

## 9. 动效（只有网页有）

| 什么 | 怎么动 |
| --- | --- |
| 要你处理的数字 | 等你、停住了时数字旁的状态点慢慢呼吸（2.4s，亮度起伏 ±15%）；有结果、在做时不动 |
| 在做的状态点 | 实心点换成一圈细环在转（底环是状态色 22%，半圈弧 1.2s 一圈）：侧栏 T 号块和专项头像角上、看板和列表里的都一样；在做的个数不限，不算进下面“不超过 3 个” |
| 结论带的分段状态条 | 有在做的时，“在做”那一段有一道光从左到右扫过（2.4s）；话题行的步骤格不动 |
| 数字变化 | 滚动到新值（300ms） |
| 新出现的要你处理 | 从上方滑入 |

- 系统设置了“减少动态效果”（`prefers-reduced-motion`）时全部关掉。
- 动效只动透明度和 transform，不动阴影、背景位置这类每帧都要在主线程重算样式和重绘的属性：话题一多（几百个侧栏行），一个阴影脉冲就能让页面静止时也每帧重算，点击跟着发顿。
- 一屏同时在动的东西不超过 3 个（在做的转圈不算：它说的就是“正在跑”）。

## 10. 代码在哪

三处只通过 `core/look.py` 和 `cards/ui.py` 共用东西；要加组件，先加进这两个文件，再用。

1. **`covey/core/look.py`**（只用标准库）：`STATES` 是第 3 节的词表（词、归类、飞书色名、块底色、网页色、图标），`BRAND`、`WEB` 是第 2 节的颜色；`tone(status, seen=, stuck=, by_owner=)` 和 `record_tone(record)` 把记录状态换成词表的 key；`pressing(counts)` 按第 4 节的顺序取最急的那件；`ACT_KEYS` 是“要你处理”的三个状态；`RETIRED` 是要换掉的旧说法。看板（`cards/board.py` LOOKS）的五个状态和这张表一致，由 `tests/test_look.py` 核对。看板、手上的事、专项卡、话题状态卡、派发卡和对话里的卡（任务卡、执行过程、问题卡、恢复卡、答案卡）的状态词和颜色都从这张表取；“要你处理”数什么、怎么数只在 `core/board_read.py`（`Asks`、`asking`、`act_count`；整理专项等你定的提议是 `Asks.proposals`，算一件等你），看板、手上的事和早晚汇总共用；专项自己停住的口径在 `core/projects.py`（`pause_tone`、`halted`）。`tests/test_glossary.py` 核对这些卡、它们的样张和画它们的代码里没有第 3 节说的旧词（`STATUS_MODULES`、`STATUS_SAMPLES`）。
2. **`covey/cards/ui.py`**：`conclusion_band`（细色阶，见第 4 节）、`styled`（给卡片加上结论带和话题头像的颜色）、`topic_badge`（话题头像）、`peek`（露一截，只给答完的问题，切法在 `cards/review.py` 的 `opening`）、`todo_bar`、`seg_bar`、`topic_row`、`state_pill`、`state_word`、`number`、`band_label`（“有结果 · T12 标题”这种小字）、`has_band`、`banded`（带结论带的卡才过 `styled`，只有话题头像的只加头像的颜色），设置一组卡的回执经 `receipt` 变成一行灰字。
3. **聊天卡片**：状态词、按钮叫法用第 3、6 节的（`core/turn_words.py`、`core/status_line.py`、`core/failure.py`）；任务卡状态行的首词是带颜色圆点的状态词（`cards/task_status.py` 的 `marked`），可能卡住时首词就是“可能卡住”，在跑时不加结论带（第 11 节）。结论带只在汇总的卡上：看板、手上的事、早晚汇总、用量、欢迎卡、整理专项卡，和专项卡里等你的那一条（它说的是哪个话题在等、等什么，头像行没说）。话题的卡都不加：任务卡、答案卡、回带（做完了、停住了、等你）、问题卡和它的顶层副本、停住的卡（恢复卡，`cards/recovery.py`）、补充回执（`cards/steer_receipts.py`），状态在头像行或任务卡标题行的标签里，带子只会把它再说一遍；按钮的说明和细节收成一行灰字，点开才是全文（问题卡的“怎么回答”、停住的卡和失败任务卡的“怎么继续”、换配置卡的“换了以后”、补充回执的“查看详情”）。说话人（5.3）在答案、回带和问题卡副本的头像行上。
4. **菜单结果卡**：看板、用量用结论带和分段状态条，看板的块是话题行，`cancelled` 按谁停的分开（汇总行带 `tone`，`app/digest.py` collect）。
5. **网页数据约定 v5**：`topic` 条目在 `state` 之外多带 `tone`（第 3 节的 key，`app/web_collect.py` 的 `Collector.tone`）。网页按 `tone` 上色、取词，不再比较中文字；`state` 照旧，老网页不受影响。`python3 -B scripts/export_look.py --out look.json` 导出词表，网页的 token 由它生成。
6. **谁停的**：记录的 `cancel_requested_by` 写停止来源（`core/jobs.py` 的 `STOP_SOURCES`）：任务卡上的停止 `card`、对管家说停 `word`、网页上的停止 `web`、专项卡上的停止 `project`、主人撤回了任务的原消息 `recall`，这五个是主人自己停的（`look.OWNER_STOPS`），算**已停止**；负责人停的 `lead`、专项护栏停的 `guard`、代答换批次停的 `proxy` 算**停住了**。排队时取消的（`never_started`）也是主人的。旧记录只有 `card`，照旧读成主人停的；没有来源的 `cancelled` 读成停住了。停止来源走卡片点击的 `by` 字段，老版本的任务进程不认它，照旧记成 `card`。
7. **飞书客户端的限制**（真机验过）：自定义颜色 `config.style.color` 飞书认，浅色、深色两套都生效；图片设固定像素尺寸只能配 `crop_center`。不加光球、不在四周套光晕圈，带子里竖向渐变相邻差 1%（差 3% 看得出条纹）。
8. **网页记忆中心与仓库页（数据约定 v43）**：页面在 `web/client/src/cv/MemoryCenter.tsx`（纯函数 `memoryCenter.ts`，单测 `web/scripts/memory-center.test.mjs`），专项页、话题页右栏的精简清单 `MemoryList.tsx`；仓库页在 `Settings.tsx` 的 `ReposTab`（纯函数 `reposPage.ts`）；开新话题和换配置的去工作区在 `launch.ts`、`launchRepos.ts`、`switchConfig.ts`。样子按第 5.2 节的「记忆」「仓库」两行。

改卡片照仓库规则：在分支上开发，跑适用的测试，快进合进 `main`；卡片 JSON 一变就要真机验收（规则 9），手机、侧栏、深色各看一次；网页电脑、手机各截一屏，和样张对照。

## 11. 风险和退路

| 风险 | 退路 |
| --- | --- |
| 飞书不认 indigo-50 这类色名 | 用卡片 2.0 的自定义颜色 `config.style.color`，分别给 light_mode 和 dark_mode 两个值 |
| 某台设备上看得出色阶的台阶 | 把 `look.BAND` 的 `step` 再调小，或行数减少；只改这一处 |
| 卡片做不出等宽数字 | 用加粗大号数字，不强求等宽 |
| 露出的几百字在手机上太占地方或太少 | 只调 `cards/review.py` 的 `PEEK_WIDTH`、`PEEK_LINES` |
| 话题头像的宽高在某端不生效（`width: auto`、`height` 不认） | `cards/ui.py` 的 `topic_badge` 改按位数给固定像素宽（每位约 8 px 加左右各 8 px），颜色和字不动 |
| 卡片太长（超过 CardKit 大小上限） | 结论带只用在面板卡和结果卡上，任务卡在跑时不加 |

## 12. 改外观：先选样张

卡片统一改了 19 轮、“默认”去掉又出现、问题卡按钮同一天改过去又改回来：每次都是改完才给主人看，看了不满意再改。主人要的是：“给我弹一个卡片让我去验一验，给我不同的款式让我自己选择，这样一次性到位”。所以改卡片和网页的样子（布局、按钮、颜色、字样、折不折叠）先出样张，主人选定再实现。

**什么时候要先出样张**：改的是主人看得见的样子，而且有不止一种合理的做法。主人这一轮已经说清楚要哪种（“把 X 改成 Y”），或者只是修明显的错（字写错、链接坏了、违反了第 13 节的规则），直接改，不用出样张。

**流程**：

1. **先查[拍板记录](#13-拍板记录)**：要改的地方有已经定下的规则，就照它做；想推翻它，要主人这一轮明说。
2. **出 2~3 版**：A 一般是现在的样子，B、C 是改法；用真的卡片函数加演示数据画（`cards/` 里的函数都是纯函数），不手写 JSON。每版只放要比的那一块（变了的元素加一两行上下文），不放整张卡：一张问题卡最多 30 KB、200 个元素，三版加起来要放得下。
3. **自己先查一遍**（不发任何东西）：

   ```bash
   python3 -B scripts/ui_samples.py golden question.card_pending --out /absolute/A.json   # 现在的样子，取自 golden
   python3 -B scripts/ui_samples.py check /absolute/A.json /absolute/B.json /absolute/C.json \
       --labels "A 照旧（推荐）,B 文字按钮,C 收进折叠" --out /absolute/dir
   python3 -B scripts/cardkit_check.py --profile <机器人的 profile> /absolute/dir/question-card.json  # 只建不发
   ```

   `check` 照 Bridge 的读法读每个文件，说每版多大、画没画上，把主人会收到的问题卡写到 `question-card.json`；有一版没画上就退出 1。`cardkit_check.py` 在 CardKit 建一遍这张卡、不发到任何聊天，确认飞书收。
4. **问主人**：检查点里一道单选题，每个选项带 `sample`（样张文件的绝对路径），推荐的排第一、label 末尾加“（推荐）”：

   ```json
   {"requires_user": true, "question": "问题卡的不处理用哪一版？",
    "questions": [{"id": "look", "header": "不处理按钮", "question": "问题卡的不处理用哪一版？",
                   "options": [{"label": "A 照旧（推荐）", "description": "和提交回答并排、一样宽", "sample": "/absolute/A.json"},
                               {"label": "B 文字按钮", "description": "提交回答下面一行字", "sample": "/absolute/B.json"}]}]}
   ```

5. **主人选了以后**：照选中的实现；`GOLDEN_CARDS=update` 重写卡片 golden（[测试与验收](testing.md)）；在[拍板记录](#13-拍板记录)加一行（规则写选中的那版，“为什么”写没选另几版的原因；哪天、哪个话题定的写在提交说明里，文档不写），能机检的规则加进 `tests/test_ui_rules.py`；照规则 9 真机验收（手机、侧栏、深色各看一次）。

**主人看到的问题卡**（`cards/question_cards.py` 的 `with_samples`）：头像行下面一行灰字“下面 N 版样张由卡片 JSON 画成，样张里的按钮点不动”，然后每版一块：选项的 label（粗体）、说明（灰字）、样张本身，块和块之间一条细线；最后是题目和每个选项一个按钮，点一下就提交。选项的说明已经写在样张上面，表单里不再列一遍。答完以后卡收成答完的样子，样张不再画。

**Bridge 怎么处理样张**（`covey/core/ui_samples.py`）：

- 登记问题时读一次文件，把要画的内容存进问题记录：之后重画（重启、重投、答完重画）都画同一份，文件改了、删了都不影响。
- 样张里的东西都点不动：去掉所有 `behaviors`（回调和链接）、按钮的回调 `value`、`confirm`，表单拆成普通的列（字段照画、不提交、去掉 `required`），每版的 `element_id` 和 `name` 重新编号（两版不会撞），标题栏画成第一行粗体，测试用的假图片 key 画成灰色“［图］”。
- 只认单选题，一题最多 4 版有样张；文件最大 60 KB，一版清理后最多 20 KB、120 个元素，超了写一行灰字说为什么没画；整张卡超过 29 KB 或 195 个元素时从最后一版往前不画（写“这版样张放不下这张卡”）。
- 带样张的问题单独发一张问题卡（话题串里，私聊顶层的副本也有），不放在任务卡上；专项的话题问的也不交负责人代答（`core/project_gates.py` 的 `SAMPLE`：口味只能主人定）。
- 已知限制：网页工作台上只有选项名，样张要在飞书卡上看；设备上的话题，样张文件在设备上，Bridge 读不到，卡上写明；网页的样子不是卡片 JSON，用 `scripts/web_shots.py` 截图后放进 `show_images`，同一轮再问。
