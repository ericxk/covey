# 使用参考

[使用指南](usage.md)每一节的细节：卡上每一项写什么、规则和时限、出了异常会怎样。按需查，不用通读。

## 菜单卡

**再点一下收回**：菜单一项的卡还是私聊里最新的一条顶层消息时，再点这一项，卡原地收起成一行；再点一次原地展开，内容按当时重新画。卡发出后你在私聊顶层发过消息、别的菜单项发过卡，或者机器人重启过，都不算最新，这时发一张新卡。

**每种卡只留最新一张**：发新卡后机器人撤回这一项的上一张。超过撤回时限或旧卡已经没了时，旧卡留着。

**旧菜单项**：应用里还留着的“工作区”“脱敏”“群聊”“管家”菜单项照旧能点，打开设置卡对应的标签或单独的卡。代答还是设置卡里一个标签时发的旧设置卡，停在“代答”标签上的照旧能用。

**飞书应用待补**：机器人自己检查飞书应用缺不缺它要用的权限、事件和菜单（比如升级后新加的菜单项）。缺了就在私聊发一张「飞书应用待补」卡，按权限、事件与回调、菜单分组列出缺的项。点“扫码自动补齐”，用飞书手机端扫卡下面的二维码（有代答的网页端登录时不用扫）；卡上一步步显示进度，最后写哪些已生效、哪些仍然缺。要管理员审核的权限单列、默认不申请。点“不管了”不再提醒这一组。做法和限制见[自动补齐飞书应用](feishu-app.md#自动补齐飞书应用)。

## 设置卡

菜单「设置」打开，一排标签“配置 | 工作区 | 脱敏 | 群聊 | 诊断”，部署开了记忆时“群聊”后面多一个“记忆”，开了节点时再多一个“设备”；标签多时自动折成两行。点菜单先停在“配置”。点另一个标签，这张卡原地换成那个面板，不发新消息；点当前标签，卡原地收起成标题和标签行，再点展开。

- **配置**：新话题、管家、专项负责人和辅助模型怎么跑都在这一页，一段一处。一次只展开一段（一张卡放不下所有段的选项），其余的段是标题、“展开”和一行灰字写着现在的值；点“展开”换到那一段。点菜单打开时展开“新话题”，管家发来的设置卡展开“管家”。标题栏一句话写各段现在用的模型。展开的那一段里很少有人改的几项（管家、新话题、专项负责人的供应商，管家、新话题的脱敏，专项负责人的模型和思考预算，私聊顶层的消息）收在这一段末尾一条默认收起的“更多：…”里，点开就地展开；改了里面的一项，重画后它还开着。脱敏开着、私聊改成每条直接开一个话题时，那一项不收、照常显示。
  - **新话题**：所有新话题的预选，你自己发消息开的话题（启动卡）和管家开的话题都照它。两行：Harness、供应商、模型、思考预算 / 工作区、运行方式、脱敏；某一行选“跟上次一样”，就用你上次在启动卡上的选择，这一行写着现在会是什么。管家开的话题一律直接开工（以前的“直接开工”设置和“记住的工作区”已下线）。
  - **管家**：管家自己用的，第一行 Harness（只列能跑管家的；开着管家的脱敏时只列能脱敏的）、供应商、模型、思考预算，第二行工作区、脱敏、压缩阈值，另起一行是**私聊顶层的消息**：交给管家 / 每条直接开一个话题，见[管家的细节](#管家的细节)。纯话题模式下这一段只有私聊顶层的消息一行；部署不允许管家（`COVEY_BUTLER=0`）时没有这一段。
  - **专项负责人**：开了专项才有。新建的专项，负责人用这里选的 Harness、模型和思考预算；第一项“跟管家一样”就是没有这项设置时的做法。只列能接 Bridge 工具的 Harness（Claude Code、Codex、Antigravity），管家开着脱敏时只列能脱敏的。已有的专项在专项卡上点「换配置」换。
  - “更多”里是子 Agent 用什么模型（所有 Claude Code 话题和管家都照它：默认轻量，子 Agent 跑 Sonnet、搜索跑 Haiku；或者跟主模型）。
- **工作区**：[工作区列表](#管理工作区列表)；开了管家时每个工作区下面一行灰字写它的“用途”，点“改用途”才出输入框，改完点“保存用途”。
- **脱敏**：[脱敏词表](#脱敏词表)，直接在卡上改。
- **群聊**：见[群聊](#群聊)。
- **记忆**：部署开了[记忆](butler.md#记忆)时才有。飞书上只看数和处理待审核：标题下一行是规矩、决定、资料、待审核各多少条，下面各范围（全局、话题、各专项，专项多时只列前几个）一行计数；待审核列最旧的几条，每条“采纳”或“不要”，多了翻页；有网页时给“打开网页记忆中心”和“去网页逐条看”两个链接，没网页时多列全局和各专项规矩的标题，每条能“收起”（再点“确认收起”）。要改、要整理、要提到更大的范围，都到网页记忆中心。
- **设备**：部署开了节点时才有，列出每个节点现在的状况，可以添加、移除设备。
- **能做什么**（接在“诊断”页的下半，以前是单独一个标签，旧卡上点它会落到诊断）：只读的一段，写这台机器装了哪些 Harness、哪些现在用不了；功能分三组：交给它办事（管家、专项和负责人、到点回来看……）、不断不丢（重启不打断、换配置不断上下文、回退、限流后自动继续、撤回和编辑跟着变……）、看得全记得住（看板、早晚汇总、手上的事、记忆……）。每一行先写它给你带来什么；开着的后面灰字是读哪个开关，没开的整行灰色、写怎么开（比如管家用的 Harness 没启用：装好并登录 Claude Code 再运行一次 `./install`，或在「配置」页的“管家”一段把 Harness 换成这台机器上有的）。最后是启用了哪些扩展，和改开关的那条命令（带着这个服务的状态目录，照[配置 · 改开关三步](configuration.md#改开关三步)），改完再点这一页看。
- **诊断**（页面上半，下半接着“能做什么”）：只读，把服务器上 `covey_doctor.py` 的报告说成几行：服务管理器在不在、这个机器人（第几代、收消息和卡片点击的连接、丢没丢事件、清单里有没有已不生效的权限变量）、这个机器人设了哪些可选开关（只列[开关速查](configuration.md#开关速查)里的名字，名字像凭据的不列；值只显示短而普通的，路径、地址之类写“已设”）、开了 Claude Harness 时 Claude Code 的会话保留几天（读它的 `settings.json` 的 `cleanupPeriodDays`，缺省 30 天；少于约 90 天就写明旧话题会接不上、回退不了，和该加的那一行，只提示、不替你改）、开机会不会自动拉起、每个 Harness 上次探测能不能调通；标题栏写几项要看、几点查的。切到这一页或收起再展开时现查一次（要几秒），不改任何东西、不调模型；完整报告见[排障 · 健康诊断](troubleshooting.md#健康诊断)。

代答不在设置卡上，是菜单里单独的一项（代答话题的模型在代答卡上选）。网页工作台的设置页没有“记忆”和“能做什么”两页，“配置”在网页上仍分成“新话题”“管家”两页。

## 启动卡

| 选项 | 说明 |
| --- | --- |
| Harness、供应商、模型 | 分三级选：先 Harness（如 Claude Code），再供应商（如 Codex 自带 / 部署配的模型网关），模型只列选中的 Harness 和供应商的。卡上写成“Harness · 供应商 · 模型名”，Harness 自己的供应商不写（“Claude · Opus 5.5”“Codex · MyGW · GPT-6 Astra”，MyGW 代表部署配的某个网关），见 [Harness 和供应商](harnesses.md#支持的-harness)。只列各 Harness 最近读到的模型目录，读取失败的 Harness 不出现；目录还没准备好时只有一项“模型目录准备中，请稍后重新打开配置”。扩展 Harness 每个模型只列一项，它的推理预设是这一项的思考预算 |
| 模型的顺序 | 第一项是本聊天上一次开始任务用的模型；接着是本聊天最近 14 天选过的模型，选得多的在前；其余按 Harness 分段（Claude、Codex、DeepSeek Harness、Antigravity，扩展的 Harness 排在它自己声明的位置），段内按模型目录的顺序，部署可以用 `models_first` 把某些模型排到段首（见[配置](configuration.md#harnessesjson)）。私聊和每个群各算各的 |
| 思考预算 | 模型支持的各档，从高到低，每档写名字（和设置卡一样，没有“推荐 · 档位”和“模型原生默认（不指定）”：看不出实际跑哪一档）。模型没有可选档位时只有“模型自动管理（无可选预算）” |
| 工作模式 | 只在提供工作模式的 Harness（公司扩展的 Harness）的模型时出现：“Focus（推荐）”一个 Agent 自己完成；“Adaptive（派子 Agent）”按需把工作派给子 Agent，更慢、用量更多 |
| 敏感词脱敏 | 只在 Claude 的模型时出现，“关 / 开”，默认值是设置卡「配置」页“新话题”一段的“脱敏”，见[敏感词脱敏](usage.md#敏感词脱敏) |
| 工作区 | 已保存的工作区，最近用过的在前；最后一项“⚙️ 添加或管理工作区…”打开管理页 |
| 运行方式 | “原目录”或“独立 worktree”（只能用于 git 仓库），见[原目录与独立 worktree](usage.md#原目录与独立-worktree) |
| 其他目录… | 在卡内逐层浏览目录，或粘贴绝对路径，见[浏览目录](#浏览目录) |

**预选**：

- 先看设置卡「配置」页的“新话题”一段：选了模型、工作区、运行方式、脱敏的，照它预选；只选了 Harness 没选模型时，上次用的是这个 Harness 的模型就用上次的，否则用这个 Harness 的默认模型；Claude Code 目录里的“Default (recommended)”不写是哪个模型，启动卡、换配置卡和网页开新话题都不列它；上次开始任务或常选的是它时，预选这个 Harness 的默认模型（没有时菜单上它的第一个具体模型）。话题正绑在它上面时，换配置卡照旧列出它。
- 这些行选“跟上次一样”的项，预选本聊天上一次开始任务时的选择；本聊天还没开始过任务时，预选最近一次在任意聊天的选择。上次的工作区已不在列表里时预选列表里标“兜底”的工作区。运行方式没设时从“原目录”开始。
- 思考预算：设置卡「配置」页的“新话题”一段设了思考预算时，同一 Harness 的模型先预选这一档（模型支持它时；比如设成 high 后启动卡不再预选 xhigh）；没设、Harness 不同或模型没有这一档时，预选本聊天给这个模型最常选的一档（最近 14 天里最近 10 次）；没选过时预选推荐的那一档（模型支持的次高档，写它的名字，如 xhigh）。以前记下的“推荐”“模型原生默认”画成推荐的那一档。没有合适的推荐档时不预选，提示“此模型没有合适的推荐档，请选择预算”，选好才能开始。
- 换一个模型后，思考预算按上一条重新预选，工作区、运行方式保持。

**点“开始任务”之后**：

- 启动卡变成回执：绿色对勾和“已提交”，标签写运行方式和敏感词脱敏，副标题写话题、模型和思考预算，正文是工作区名（完整路径在“完整工作区路径”里）。任务卡随后出现（通常 1–2 秒）。
- 提交时再核对一次：模型或预算目录刚更新、所选目录不存在时，任务不启动，按提示重新选择后再点。重复点击不会重复开始。
- 话题开始后再点它的启动卡，提示“本话题配置已固定；新任务请在主聊天发送消息”。
- 启动卡没能发出时，话题里收到“配置卡暂未送达，请在本话题回复消息以重新显示；任务尚未启动。”。在本话题再发一条消息就会出现新的启动卡。

开始前在话题里继续发的消息也会保存，每条下面各出现一张启动卡。在任意一张上点“开始任务”，这些消息按顺序依次执行。启动卡 7 天没人点（期间话题里也没有别的操作）时自动关闭，卡上写“超过 7 天未处理，已自动关闭；需要继续请在本话题直接发消息。”。

## 工作区

### 浏览目录

启动卡的“其他目录…”和管理页的“＋ 添加工作区…”用同一个浏览页，整张卡换成它：

| 控件 | 作用 |
| --- | --- |
| 📂 当前目录 | 目录名和完整路径；已在工作区列表时写“· 已在列表” |
| “上一级”“刷新” | 回到父目录；重新读取当前目录 |
| 搜索框、“搜索” | 填名称：搜当前目录的子目录（不分大小写，包含即可），往下最多 3 层。填以 `/` 或 `~` 开头的路径：直接前往 |
| 目录行 | “进入”进入该目录；“使用”（启动卡）或“添加”（管理页）直接选这一项。每页 15 行 |
| “使用此目录”/“添加此目录” | 选用或添加当前目录 |
| “返回”/“返回管理页” | 回到启动卡或管理卡，不改动已选内容 |

- 启动卡上选用后，卡片回到启动卡并写明“已选择工作区：名称”。仍要点“开始任务”才会启动。
- 列目录只读当前这一层，不跟随链接。搜索不进以 `.` 开头的目录、`node_modules` 和 `__pycache__`，最多查 5000 个目录、6 秒；没查完时状态行写“只查了前 N 个目录，可进入子目录再搜”。
- 读取或搜索要等时状态行写“正在读取…”，读到后卡片自动刷新。

### 管理工作区列表

两个入口：菜单「设置」的「工作区」标签；或启动卡工作区一行最后的“⚙️ 添加或管理工作区…”（整张启动卡换成管理页，底部有“返回启动卡”和“结束，不启动任务”）。

- 列表里兜底的工作区在最前，其余最近用过的在前，每页 8 个。每行是名称、状态标签（兜底 / 目录不存在 / 未确认）、路径和最近使用日期，右侧是“移除”。新话题用哪个工作区在设置卡「配置」页“新话题”一段的“工作区”一行选；“兜底”只是启动卡没有上次可跟时用的那个。
- 超过一页时列表上方可以按名称或路径搜索、按状态筛选（全部 / 目录不存在 / 30 天以上未使用 / 从未用于任务）。有确认不存在的目录时，多一个“移除不存在的（N）”。
- 移除只改列表，不删除磁盘上的目录；已开始的话题记下了自己的目录，不受影响。兜底的工作区不能移除。
- 其他话题还没开始的启动卡仍可能列出被移出的工作区，选它开始会提示“未找到该工作区，可能已从列表移除；…”。

服务器上用命令维护工作区列表见[日常操作](operations.md#日常操作)。

第一次用的目录自动加入列表，名称取目录名，重名时加 `-2`、`-3`。

### 独立 worktree

- 机器人从仓库当前提交（`HEAD`）新建分支 `bridge/<时间>-<话题 ID 前 8 位>`，在数据根的 `worktrees/` 下检出，话题在与所选目录对应的子目录里运行。源检出里未提交的改动不会带过去。
- 点“开始任务”后整张卡换成“正在创建独立 worktree…”，通常几秒到十几秒，完成后任务自动开始。
- 检出失败（包括检出期间服务重启）时，卡片换回启动表单并保留已选内容，顶部写“⚠️ 任务未启动：原因”。已经建好的 worktree 不会删除。
- 话题结束后 worktree 和分支都保留，由你合并或自己删除（例如 `git worktree remove <路径>`）。

## 排队

- 排队的消息有自己的任务卡。前面有本话题的任务时，卡的第一行（状态行）写“这句话会在 #1190 结束后单独执行”；阶段写“排队中 · 排在 #1190 后面 · #1190 已运行 1小时23分（10:05 开始）”或“排队中 · 并发已满（最多 10 个任务）”。
- 任务在跑时在话题里发的消息先补充给它（`COVEY_TOPIC_STEER`，默认开，见[排队消息卡上的补充](#排队消息卡上的补充)），没送进去才留在这里排队。
- 每张任务卡上的“停止”只取消这张卡的任务：排队中的立即取消、不调用后端。
- Claude（和有同样行为的扩展 Harness）的原生问题等你回答时，任务仍占一个执行名额；Codex 遇到必须回答的问题会结束本轮、释放名额；检查点里登记的问题也在本轮结束时释放名额。

## 补充

补充表单的标题是“补充任务 T8”，输入框上方一行灰字“最多 1000 字；更长的或带附件的直接在话题里发”。提交后表单换成一行回执，下面一行灰字“查看详情”，点开列出各状态的时间和补充原文。任务结束后，还开着的表单变成“任务已结束，不能再补充”。

### 打断正在跑的命令

Claude 只在两次工具调用之间读补充，一条长命令在跑时，补充要等它结束才读到。两种办法让它马上读到：

- **点“打断它，马上读”**：回执卡上，补充还没读到时出现。Bridge 停掉模型正在等的那条命令（只停这条命令，不停这一轮），模型拿到命令被停的结果，接着读补充。
- **急的补充自动打断**：补充里有“马上”“立刻”“赶紧”“停一下”“过期”“重发”这类词，送达 20 秒还没读到，Bridge 自动这样做。负责人或管家转给话题的话也算。

推送、部署、发布、安装、远程拷贝、改服务、删除和移动文件这类命令（`git push`、`deploy`、`pip install`、`kubectl`、`rsync`、`rm`、`mv` 等）不打断，回执上写明；模型在等子任务或正在写回答时没有命令可停，回执上也写明。设备上的任务不能打断。时长和开关见[配置](configuration.md)的 `COVEY_STEER_URGENT_SECONDS`。

### 送达状态

每条补充只发送一次：

| 卡上写法 | 含义 |
| --- | --- |
| ✓ 任务开始前收到，已并入本轮请求 | 目标任务还在排队，补充并入它的请求 |
| ⏳ 已保存，尚未送达 #N | 任务刚开始，后端还不能接收。先保存，能接收时自动送入，只送一次；送入前可以“撤回” |
| ✓ 后端已接收 · 当前一步结束后读到 | 已交给模型后端。模型在手上这一步（一条命令、一个子任务）结束后才读到它；长命令或前台子任务在跑时要等它们结束 |
| ✓ 已送达 · 还没读到 · 已等 N 秒 | 只在 Claude：已交给后端，模型还没读到。送达后 20 秒、1 分钟、3 分钟、10 分钟、30 分钟各刷新一次等了多久；下面有“打断它，马上读” |
| ✓ 模型已读取 | Claude 把补充回放进了会话（只有 Claude 有这一步） |
| ⚠️ 任务 #N 已结束，模型没有读到这条补充 | 只在 Claude：后端接收了，但任务在读到它之前就结束了 |
| ⚠️ 没有补充到 #N：原因 | 什么都没发出（任务在收尾、已结束、在等回答，或后端拒绝）。表单保留内容，可直接再次提交 |
| ⏳ 补充 #N 送达未确认 | 发出后没拿到确认。**不会自动重发**，点“检查送达状态”核对 |
| 已撤回，这条补充没有发给 #N | 在送入前撤回了 |
| 已补充到这一轮，不另开一轮 | 任务在跑时在话题里发的消息，自动补充给了在跑的这一轮（[排队消息卡上的补充](#排队消息卡上的补充)）；后面跟着上面各行的送达状态 |
| #N 结束前没有读到这条补充，已排成新一轮 #M | 排成了新一轮 #M，不用再发：自动补充的消息确定没被读到时自己排，别的补充是你点了“重新排队”；都只排一次（没有收到、已撤回、送达未确认的也这样写） |

回执上的按钮按状态出现：**撤回**（已保存、尚未送达时）；**检查送达状态**（送达未确认，或 Claude 已接收、还没读到时；只核对已有记录，不重发）；**重新排队执行**（只对排队消息转成的补充，在没有发出、已撤回或模型没有读到时可用，把原消息排成一个新任务，只能排一次；自动补充的消息确定没读到时自己排，不出这个按钮）。

没送到、要你处理的回执（模型没读到、没有发出、送达未确认、重新排队结果未确认）第一行粗体写怎么了（“任务 #N 已结束，模型没有读到这条补充”），下面一行橙色“要你做”，只写卡上有的办法（有“重新排队”按钮时才写重新排队；重新排队结果未确认时先看话题里有没有新任务，没有再发一次，以免跑两遍）。原来开头还有一条结论带（“要你处理 · 补充 #N”、怎么了、原因），和第一行说的是同一件事，去掉了。这里不写“停住了”：那是任务没成功的状态词，补充没送到时它要补给的任务可能好好的。排成了新一轮的回执只剩一行。

补充送入后，目标任务卡在“本轮请求”上方显示“📝 最新补充 HH:MM · 内容开头”。

### 任务在等回答时

任务在等一个**必须回答才能继续**的问题时，机器人不发送补充：暂停中的回合不接收输入。这时点“补充”回复“补充当前任务未完成：任务 #N 正在等待回答，请先回答问题，之后可以再补充”。Codex 的**非阻塞**提问（问题卡写“其他工作继续”）不暂停任务，补充照常送入。

### 排队消息卡上的补充

排队消息自己的任务卡上的补充按钮写作“现在补给 #N”，它补充的是**上一任务**：同一话题里排在这条消息之前、最近的那个未结束任务，按钮上写出编号。这条消息的任务开始后，按钮改回“补充”，补充的是它自己。

- 点一下就把这条消息原样交给上一任务，连同附件和话题背景。不点，这条消息照常排队。
- 上一任务已结束、已取消或正在等回答时不发送，这条消息继续排队，原因写在它自己的卡上。
- 送入后排队卡整卡换成回执“✓ 已补充到这一轮，不再单独排队”，这条消息不会单独执行；送达未确认时也不单独执行，以免重复。

**任务在跑时发的消息自动这样送**（`COVEY_TOPIC_STEER`，默认开；设成 `0` 就只在点按钮时送）：上一任务已经开始，消息一进来就照上面点一下那样交给它，卡先写“正在补充到 #N”，随即换成回执“✓ 已补充到 #N，不另开一轮”，你那句话上同时加一个 ✅ 表情（送进去了才加，没送进去或没确认的不加），查看详情里写“来源：#N 在做时发到话题里的消息，自动作为补充交给它”。只对支持执行中补充的后端，不含管家（管家本来就补充）；群里谁的消息被服务，谁的就这样送，送进去的话和平时一样以发送人开头。

- 连着发几条：每条各是一个补充，按收到的顺序送，每条只送一次；飞书重投同一条消息也不再送。
- 没有发出（任务正在收尾、已结束、在等回答，或后端拒绝）：消息照旧排成下一轮，卡的第一行写“这句话会在 #N 结束后单独执行”，下面一行写“⚠️ 没有补充到 #N：任务正在收尾，不能再补充”这样的原因，按钮“现在补给 #N”可以再试。
- 送达未确认：和点按钮一样不单独执行、不重发，回执上点“查送达状态”核对。
- 确定没读到（任务刚开始时保存的补充没等到送入任务就结束了，或 Claude 到结束都没读到它）：自动排成新一轮，和点“重新排队”一样只排一次，回执写“#N 结束前没有读到这条补充，已排成新一轮 #M”（排队进行中写“正在排成新一轮”）。你停掉的任务带着的补充不自动排，回执上留“重新排队”。
- 任务在任务进程里跑时，任务进程只标记，任务进程结束后由 Bridge 排；那一刻 Bridge 不在（重启、部署），下次启动时由话题所在 Harness 补排。

## 回答

### 问题卡

问题卡开头是话题的头像行（T 号、标题、“等你”），下面直接是题目，没有结论带。任务不等这道题时，题目上面一行灰字写“其他工作继续”（不阻塞）或“本轮已结束，可继续补充”；任务等你回答才继续的不另写。任务卡上的表单头上没有头像行，第一行是粗体“等你 · 等你回答后继续”。聊天列表里开着的问题卡预览“T12 等你 · 要你定：…”：一道题写它的小标题或题目本身，几道题写各自的小标题或题目开头，用“；”隔开，放不下写“等 3 件”。

- 每道题以题号和题目标签开头（粗体）；一道没有题目标签的短题，题目本身是粗体。只有一道有选项的单选题时，每个选项一个按钮，按字的长短排：按钮的字加起来不长（连“不回答此题”在内，中文和全角符号一个算 2、其余一个算 1，每个按钮另加 4，不超过 56，约 380px）时并排一行、各按字宽，和原来一样，窄了自己折行；放不下一行就排成几行，每行放到 56 为止；有一个选项超过 24（12 个汉字）时一项一行、和卡片一样宽，最后一行是“不回答此题”。选项再长也不挤出卡片，桌面、话题侧栏和手机上一样。点了就提交，补充说明一起带上；回答框里写了字再点选项，以点的选项为准，要按写的回答提交就点“提交回答”。几道题时有选项的题是下拉框（多选题为多选框）。下拉框下面还有一个“自己写回答”的输入框：写了就以写的为准。没有选项的题只有回答框。
- 模型在检查点里给题目写了一句背景（`context`：这题在改什么、为什么现在问）时，卡上写在题目下面，灰色小字“背景：…”，最多 120 字；没写就没有这一行。
- 每道题都能选“不回答此题”，模型收到“用户选择不回答此题（不表示同意或授权）”。
- 题目下面是**补充说明（可选）**输入框，不针对某一题，模型收到单独一段“用户补充说明：…”。
- 再下面是**提交回答**（蓝色）和**不处理**，一样宽。**提交回答**把选的、写的和补充说明一起交：写了补充说明时，没答的题记为“不回答此题”；只写补充说明就是每题都不答，模型收到的那段标题是“用户补充说明（没有回答上面的问题，不表示同意或授权；可能是对问题的反馈、疑问或新的要求……）”，所以说问题不合适、给新要求、先问一句都写在这里。没写补充说明时每道题都要处理，漏了回一张小卡说哪题没答。
- **不处理**（提交回答旁边）：每道题记为“不回答此题”，什么都不补充，和只写补充说明却没写一样，但现在不发给模型、不开新一轮。问题从“等你”里撤下（手上的事、看板、早晚汇总、网页都不再算它，网页上这道题算“每题都选了不回答”，它的话题不再显示“等你”），在话题里发的话也不再当作它的回答，等它的任务照旧不动。卡收成答完的样子：题目露开头，下面一行灰字“→ 你选了不处理 · 话题下一轮开始前可以撤销”，旁边是**撤销**：点了问题回到“等你”，表单重新打开，和没点过一样。**撤销到什么时候**：这个话题下一轮开始为止（你在话题里发的下一句、管家或网页转来的话、别的问题的回答，哪一个先排进来都算）：那一轮的请求前面带上“你之前问的题，用户点了不处理”和每题“用户选择不回答此题（不表示同意或授权）”，暂存的补充也一起带上，只带一次；卡上那一行改成“你选了不处理 · 随 #N 告诉了模型”，撤销按钮没了。这样不定时间窗口：没有下一轮就一直能撤，有了下一轮模型已经看到，撤也没有意义。换配置、回退、负责人或网页停话题时，它和待答问题一起作废。在旧卡上点提交回答或选项，回一句“这组题你点了不处理……要回答的话先点卡上的撤销”。模型用自己的提问工具问的、只能拿这道题的回答接着做的（Claude 的原生问题、Codex 必须回答的问题）不出这个按钮：它的会话只等这一个回答，撤下会让它一直等。管家和负责人在私聊顶层问的问题也没有。
- 最后一行是灰色小字“怎么回答：点选项就提交，也可以直接在话题里回复”（顶层副本是“引用这张卡直接回复”，几道题时是“逐题选择或填写，最后点“提交回答””），点开是全部答法；它在按钮下面，不插在正文和题目中间。
- 旧卡上还有“只发补充说明”“先问一句”：点哪个都只发补充说明、每题记为不回答（选了的选项不算），补充说明是空的就在卡上说一句并重画成新样子。“以后这类按推荐走”已下线，见[已下线的功能](#已下线的功能)。
- 输入框只能填文字，每个最多 1,000 字符；只有一个待答问题时直接在话题里回复不受这个限制。
- 漏答或填法冲突时，你点的那张卡（话题里的卡，或私聊顶层的副本）原地重画，表单下面一行写原因，选的、写的都还在，改好再点“提交回答”。任务卡上的表单不单独重画，话题里回一张小卡说明原因。
- 卡片里不能放图片。有问题待答时发的图也会交给模型：单题时随回答一起送出，多题时随暂存的补充一起送出。

### 多题待答时直接发的消息

多道题待答时，话题里直接发的消息既不当作回答，也不排成新任务，而是暂存为补充，出现小卡“📝 这条消息还没发给模型：20:24 的 2 道题还没答，提交回答时会一起带上”，按钮下面一行灰字“怎么处理：要模型现在就看到它，点“作为问题反馈发送””，点开是全文。按钮：

- 什么都不点：它随下一次提交的回答一起交给模型。
- **作为问题反馈发送**：现在就把它作为对问题的反馈交给模型。反馈不算回答，未回答的部分不视为同意或授权。
- **留作下一轮**：问题都回答后，这条消息单独排队执行。
- **撤回**：这条消息不发送。

一条补充只会发送一次。已经随回答发出时，小卡改为“已随回答一起发送”。

### 回答之后

- Claude 的原生问题：答案送回仍在等待的原任务，同一轮继续。
- Codex 必须回答的问题，以及[检查点](usage.md#长任务与检查点)里登记的问题：提问时本轮已结束，答案排成同话题的续接任务，在同一会话里继续。续接任务卡标题写“问了什么 → 答了什么”。
- 不阻塞的问题：任务还在执行时答案直接送入；本轮已结束时排成续接任务。

回答后问题卡（话题串里的、任务卡上的、顶层副本都一样）收成：题目露开头，点开是其余的题目和你的回答，下面一行灰字写你选了什么、去了哪：“→ 你选了「方案 A」 · #1111 有结果”；送达未确认时“查看提交状态”“核查已保存回答并继续”露在外面。聊天列表里写“#1107 的提问 · 已回答 → #1111 有结果”。重复提交、在别的话题提交都会被拒绝。

- 标题为“回答已保存 · 送达未确认，请先核查，不会自动重复发送”时，卡上有“核查已保存回答并继续”：排一个续接任务，先核查后端会话、已有产物和外部操作再继续。
- 同一话题出现新的问题卡后，更早还没回答的问题卡自动收起，写“已收起 → #1106 又提了问题”，要说的写在新卡上。
- 模型提出必须回答的问题时，机器人**先把正文发到话题，再显示问题卡**。正文没送达时不显示问题卡，在话题里发消息会提示先点重试按钮补发。
- 停止任务会同时取消它还没回答的问题。任务进程退出后（例如机器重启），原生等待中的问题随进程失效，需要继续时在话题里重新说明要求。
- 问题 7 天没有回答（期间话题里也没有其他操作）时自动关闭，等它的任务一起关闭。

## 撤回与编辑

- **撤回**：这条消息的任务还在排队就不执行，在跑就停下，任务卡写“原消息已撤回”。如果它是发给正在跑的任务的补充，任务会再收到一句“这条撤回了，别按它做”。这一轮已经记下的记忆和知识条目也一起作废。管家已经因为这条消息开了话题的，话题串里会出现“来源消息已撤回”和一个停止按钮，停不停由你定。
- **编辑**：正文真的改了才算（只加了话题串、表情不算），改后的内容作为补充交给这条消息的任务。还在排队的，开跑时直接按改后的做；在跑的，当前一步结束后读到。任务已经做完的不会自动重做，话题里会提示你一句，要重做就再说一句。
- 只对你自己发的消息生效；撤回或编辑超过一天，或者任务结束超过 10 分钟后才改的，不再跟进。Bridge 重启后，重启前发的消息也不再跟进。
- 回复一条被撤回或编辑过的消息时，模型会知道它已撤回（不会看到原文），或者看到的是改后的内容。

## 换配置卡

在任务卡（排队、运行中和结束后的都有）上点“换配置”。在话题里发“换配置”是普通的补充或追问。

1. 话题里出现一张“换配置”卡，第一行是当前配置。下面是和启动卡一样的清单：点一行展开选项，点一项选中，卡片重画。和当前配置不同的那一行名称变成蓝色加粗；一项都没改时“确认更换”是灰的。
2. 分级选 Harness、供应商、模型。提供工作模式的 Harness 的模型还有工作模式一行。
3. 工作区（不能在这里输入新目录，先在设置卡「工作区」里添加）和运行方式。
4. 选中 Claude 的模型时还有脱敏一行。开着脱敏时选了不能脱敏的模型，卡上写明确认后本话题会关闭脱敏，点“确认更换”先弹确认框。
5. 点“确认更换”。成功后卡片变成“🔁 已换配置”，逐项写改了什么。点“取消”则话题保持原样。按钮下面一行灰字“换了以后：开新会话接着做，上下文不断”，点开是换了以后会怎样（交接摘要、旧会话没答的问题会取消、只改脱敏时会话不变）。

## 换配置之后

确认更换时会重新检查：有任务在排队或执行、正在创建 worktree、有回答在提交，或上一轮结果还没送达时，卡上出现“⚠️ 还没有换（时:分）：…”，话题保持原配置，已选的项不变。处理完（例如先点任务卡上的“停止”）再点“确认更换”。

更换后：

- **换了 Harness、供应商、模型、思考预算、工作模式、工作区或运行方式**：下一条消息开一个新会话。从 Claude Code 或 Codex 的模型换走、且之前已有会话时，原模型先在更换前会话的一个分叉上写一份交接摘要（分叉不带工具、不改原会话；Codex 不能脱敏，话题开着脱敏时不写）（目标、已做的决定、当前状态、文件和提交、未决问题和下一步，约 1500 字以内，存在话题目录下的 `handoff/summary-r<版本>.md`）；任务卡的执行过程里写着“正在请原模型写交接摘要”，最多等 3 分钟，失败、超时、原来是 Antigravity 或 dsh（它们的命令行只能续接会话、不能分叉），或刚 ↩️ 回退过一轮还没发下一条就换配置时没有摘要，照常往下走。原会话被安全拒绝或官方模型降级停过、是安全拒绝后换旧模型重试的那个会话、或已禁止续接时，也不写摘要，执行过程里按原因写一行；原会话上一轮因登录失效、额度用完、模型不可用、网关断开这类原因停下，或原来的 Harness 正在后台熔断、额度被挡时同样不再请它写（握手 30 秒没回应也直接退回原文）。等摘要时点停止，这一轮就此停下，新模型不会开跑。新会话的第一轮拿到摘要、最近几轮问答的原文（有摘要时 1 轮，没有时 3 轮，每条超过 2000 字的截断），和一个完整会话记录文件的位置（话题目录下的 `handoff/transcript-r<版本>.md`），模型需要更早的背景时自己去读。这一轮的任务卡在答案上方有一块“交接”：粗体写从什么换到什么，灰字写交了什么；等摘要时写“正在请原模型写交接摘要”，有摘要时点开就是摘要原文，没有时写为什么没有（原来的 Harness 不会写、原来的配置还没有会话、超时等），停了写“已停止，没有写交接摘要”。换了工作目录时还告诉它原来的目录在哪。这些只给换配置后的第一轮（第一轮没留下可续接的会话时给下一轮）；之后同一配置下再开新会话（安全拒绝后的自动重试、会话因失败不能续接、回退了会话的第一轮）都和平常的新会话一样，用最近几轮问答。
- **工作区和运行方式**：原目录 → 独立 worktree 时，从所选工作区的当前提交新建分支和 worktree；独立 worktree → 原目录时直接回到工作区目录，原来的 worktree 和分支保留。
- **只改敏感词脱敏**：会话不变，下一条消息起生效。之前各轮已经原样发出过，收不回。
- 之前留下的待答问题作废（只改脱敏时不作废）。
- 更换前的任务卡只能查看，不能再重试、回退或换配置。
- 换回之前用过的 Harness 时同样开新会话，不接着它更早的会话。

## 回退

- **文件怎么改回**：用 Claude Code 自己的文件快照，把这一轮用编辑工具改过的文件改回这一轮开始时的样子，新建的文件删除。命令改的文件和 git 提交不会动；原目录运行时，别的话题之后对这些文件的改动也会一起改回。
- **只能回退最新一轮**，一次一步。话题有任务在排队或执行、有回答在提交、结果还没送达时不能回退。换过配置之后，换之前的轮次不能回退。代答话题和管家没有这个按钮。
- **撤销回退**：只回退了对话时，发下一条消息之前可以点“撤销回退”。连文件一起回退的不能撤销。
- 其他 Harness 没有这个按钮。

## 任务卡

**标题行**是话题的 T 号头像、问题开头和灰色的“#196”，右边是**状态**：带底色的状态标签（词和颜色见 [UI 规范](ui.md#3-状态词表)），结束后跟着写几点结束；卡片没有标题栏（标题栏发出后改不了，标题行里的状态能跟着变）。**输入/输出**两行，和答案卡一样没有灰底：“输入”是 Harness ｜ 供应商 ｜ 模型 ｜ 思考 xhigh ｜ 脱敏开/关 ｜ 工作区；“输出”运行中是开始时间 ｜ 已运行 ｜ token ｜ 每秒 token 数 ｜ 上下文占比，结束后是用时 ｜ 每秒 token 数 ｜ token ｜ 缓存命中比例。

**状态行**写得很短：

- 运行中一般是“阶段：…”和“当前：最近一步 · 2 分钟前在跑测试”。命令写模型自己说明的用途，没有用途时写命令本身（去掉 shell 外壳和管道尾巴，长路径只留最后两段）。子任务运行时写子任务最近的一步。“2 分钟前在跑测试”是最近一次动静（执行过程的一步、流式输出、模型请求、检查点更新）和它的人话，只写到分钟，不到一分钟不写，从不写原始命令。
- 检查点写了 `steps` 且这一轮做完了至少两步（或这个话题以前做完过三轮以上）时，第一行末尾写“预计还要约 40 分钟”：按这一轮平均每步用时（从第一次看到计划算起；那时已经标完成的步骤是上一轮做的，不算）乘剩下的步数，再减去当前这步已经做了的时间，所以干等着只会往下走，不会越等越长；以往各轮用时的中位数比这一轮已用的长时，再往它拉一半；估不出来就不写。
- 当前这步做得比此前平均每步还久时，不再给“还要多久”，改写“本步 35 分钟 · 此前平均每步约 6 分钟”；看板、手上的事和汇总写“第 3 步比此前几步慢”。
- 超过 30 分钟没有动静（`COVEY_PROGRESS_STUCK_MINUTES`）时，状态行的状态词变成“可能卡住”，下面写“超过 30 分钟没有动静，可能卡住了”，再多一个“看看”：Bridge 只读地看一眼这一轮的任务进程、它下面的进程这一秒有没有在用 CPU、任务进程的日志和执行过程最近几步，在话题里回一句结论（还在干活、在等某条命令、在等模型、任务进程已经不在了）和依据；话题没开脱敏、[辅助模型](configuration.md#辅助模型)有可问的时，这句话由它按这些依据写，哪个 Harness 的话题都一样（Claude Code 的话题也问辅助模型选的那个）（只把进程名和状态、日志和执行过程最近几行交给它）；开了脱敏、辅助模型选了不用模型或用不了时用规则写的那句。它不停、不改、不重跑任何东西。有了新动静或这一轮结束，按钮自动撤下。
- 模型请求在重试时写“模型请求重试中 · 第 N 次 …”和上游原因，可以点“停止”结束等待。
- Claude 命令在排队等网关空位时（包装命令按 [Harness 配置](harnesses.md) 说的格式报排队）写“排队 · 已等 …”、几路在跑、前面还有几个，可以点“停止”结束等待。
- 还没有输出时写“当前：已提交给模型，等待首个输出”；只在思考、不流式输出时写“当前：模型思考中”。
- 检查点里写了 `steps` 时，状态行写“第 3/5 步：<步骤> · 本步 40 分钟”，看板的状态卡和管家的快照也写第几步。
- 运行一结束，状态行换成结局和结束时刻，按钮行同时移除。结果没能送达时改为“停住了”。

**用时**在每张卡上是同一个数：从 Bridge 请求后端开工到这一轮执行结束（`core/metrics.py` 的 `run_seconds`）。写法“45秒”“1分30秒”“1小时23分”。

**话题列表的预览**跟着任务走：排队时“T42 排队 · 问题开头”，运行中“T42 在做 · 阶段”，等回答时“T42 等你”，结束后“T42 有结果 · 用时 3分39秒”。答案卡的预览是“T42 有结果 · 回答开头”。卡片标题只取文字，像密钥的值写成“[已隐藏]”。

**执行过程**是一个折叠面板，运行中也收起（状态行已经写着“现在：…”），点开看每一步，运行中的刷新不会把它合上；结束时合上一次，标题写“执行过程 · 128 步”。

- 按时间从早到晚排，最新的在最下面。主任务和子任务的条目按开始时间穿插，子任务的条目前面写“子任务 · 名称 · ”。
- 进展说明保留全文，放在浅蓝底块里。两条说明之间的命令、文件修改、搜索、工具调用逐条列出：“✓ **执行命令** · 1.2 秒 · 10:32:06”（完成 ✓、运行中 ●、失败 ✕），下一行灰字是摘要。一段超过 8 项时只列最后 3 项，前面的收进折叠的“收起了更早的 N 项操作：…”。
- 卡片约 30 KB 放不下时，从最早的一段开始把命令收成一行计数，最后才收进最早的进展说明。最后一条进展说明的结尾始终完整。
- 命令那一行写模型自己说的这一步做什么：Claude Code 的 description，Antigravity 的 toolSummary，Codex 等没有说明字段的写在命令第一行的 `# 注释`（桥接规则要它们用你的语言写）。都没有时显示真正在跑的那条命令，去掉开头的 `set -euo pipefail`、清代理的循环、变量赋值、`cd`、`timeout`、`bash -c` 这些样板，后面还有命令的加“ …”。Antigravity 的定时等待写回来做什么和多久以后。
- 写本任务检查点文件的命令显示为“更新检查点”。没收到完成事件的步骤标“结束状态未确认”。
- 机器人重启时插入一行“机器人 HH:MM 重启过，任务未中断。”；任务卡的“输出”行最后也马上多一项“重启 HH:MM 没打断”（重启过两次以上写“重启 N 次没打断”），这一轮结束后的答案卡和回带卡也这样写。
- 卡片不显示工具输出和推理内容。没有执行记录的一轮结束后是一行“执行过程 · 无执行记录”。

任务卡没有任务详情，只有本轮请求和执行过程两个折叠；结束的任务卡底部也没有“下载请求与结果”（这个按钮已经下线）。

- token 是本轮主任务加各层子任务的合计，含缓存命中，每次模型请求只算一次。它是各次请求的输入之和，不是一次请求的上下文长度，也不是计费折算量。token/s 是主任务的平均输出速度，后端给了生成计时才有。
- 子任务的用量没收全时写“部分统计：”和缺什么。后端没提供的项不显示，不估算。口径见[执行指标口径](architecture.md#执行指标口径)。

**本轮命令留下的进程**：每轮后端关闭后，机器人查找这一轮的命令留下、仍在运行的进程。搜索工具（rg、grep、find、fd 等）直接结束，执行过程里写“机器人 HH:MM 结束了本轮命令留下的 N 个搜索进程：…”；其他进程（服务、训练等）不处理，只写“本轮命令留下的 N 个进程仍在运行，没有处理：…”，需要时自己结束。

**内存看门狗的告警**：开了[内存看门狗](operations.md#内存看门狗)的机器上，某个任务的命令占内存过多时，机器人在这个任务的话题里发一条“【内存看门狗】…”；不属于任何任务的发到私聊。每小时最多 6 条。

**刷新节奏**：前 3 分钟流式更新，状态行约每 2 秒刷新；之后状态行每 60 秒刷新，检查点或重试状态变化时提前刷新。超过 15 分钟没有新进展时加一行“较长时间没有新进展，可能正在等待外部任务；尚不能据此判定失败。”。机器人不推断失败，也不生成进度百分比；“后端进程仍在运行”只说明本机进程活着，**不能证明外部训练等任务健康**。

## 答案卡

- 后端交来已核验的回答时，回答单独发在任务卡下方，作为一张答案卡（超过 20,000 字节时作为 Markdown 文件，后面补一张只有头像行、产物和输入/输出的小卡；不到 20,000 字节但一张卡放不下的，分几张卡发，每张的头像行写“1/2”，产物和输入/输出在最后一张）。答案卡从上到下：话题的头像行（T 号头像、标题、状态标签）；回答全文；一个折叠，标题列出里面有什么（“产物 2 个 · REPORT.md 等 · 改动 · 验收说明（点开看）”），里面是产物、改了代码的轮次的“改动”（提交、部署、验收，取自检查点的 `delivery`）、列的提交号在话题写过的 git 仓库（工作目录所在的仓库，加上话题用到的各仓库的 worktree 和检出）里都找不到时一行橙色的“提交号对不上”写出是哪几个（展开后那个提交号后面也标“写过的仓库里没有”；查不了时不写）、验收说明和完成标准，只有一样时不折；最后是输入/输出两行。
- 改了界面或你说了要验收的一轮，模型在检查点写 `acceptance`（改了什么、去哪看、怎么验）时，这三行收在回答下面的折叠里（在完成标准前面）；“去哪看”只有 https 或飞书链接才可点，本机地址（localhost、127.0.0.1）和没写的都显示“只做了本地验证”。
- 话题带完成标准时（管家开话题时写的，1 到 4 条），回答下面的折叠里再列这一轮没满足的（“没满足”橙色）和没核对的（“没查”）；模型在检查点逐条写满足 / 没满足 / 没查，没写的算没查，都满足就不列。
- 任务卡正文这时写加粗的“结论”和回答的第一个标题或第一句。
- 回答里的标题加粗显示，表格和代码块照常显示，只有一行的代码块改成行内代码。飞书拒收这张卡片时，回答作为 Markdown 消息发出。
- 没有单独发送的回答显示在任务卡正文，以“✅ 答案”开头。超过卡片容量时卡片保留预览并注明“完整内容会以 Markdown 文件发到本话题”。
- 答案里用 Markdown 图片语法引用的本机图片（绝对路径或相对工作区）会上传并显示为图片。
- 任务改了 git 工作区里的文件时，答案末尾附修改摘要（文件数和前 10 个文件），完整差异报告作为产物上传。
- **马上看的图片**：登录二维码、要你确认的截图不等这一轮结束：任务把图片写进检查点的 `show_images`，机器人读到就发到这个话题的串里，先一行说明、再一张图片（手机上长按能识别二维码）。标了 `urgent` 的，同时在私聊聊天区再发一份，第一行写“T号 · 说明”并带“到话题里看 ›”链接；在话题串里没发出去的也会发到聊天区。管家自己的只发在聊天区。同一张图只发一次，同一个文件改写后（比如二维码刷新）会再发；这只在这一轮还在执行时生效（`app/turn_images.py`）。

## 产物与导出

### 产物上传到云空间

任务完成且结果送达后，机器人以自己的身份把本轮产物上传到云空间，卡片上直接给出下载链接。

- **哪些文件**：模型在[检查点](usage.md#长任务与检查点)的 `artifacts` 里登记的文件、长答案文件、本轮的差异报告。
- **放在哪**：机器人云空间的“Harness Bridge 产物”文件夹，里面按日期每天一个文件夹，当天每个任务一个子文件夹。你对这个文件夹有可管理权限。文件夹满了 1500 个时自动新建“日期 (2)”或“Harness Bridge 产物 2”接着放，旧的不删不动。
- **卡片**：产物在答案卡上；答案在任务卡正文里时在任务卡上。正在上传、上传失败或有文件没上传时保持展开，能看到“重新上传”。
- **限制**：非空普通文件，不超过 200 MB。登记的目录打包成“目录名.zip”：`.git`、`.env` 这类配置和凭据文件以及符号链接不打包，总大小不超过 200 MB、文件不超过 5000 个。`.git`、`.ssh`、`.codex`、`.claude`、扩展声明的 Agent 目录（如扩展的子 Agent 工作目录）、`.env` 等路径不上传，也不列出。同一内容只上传一次。上传的文件不会自动删除。
- **失败**：卡片显示原因（例如“机器人应用缺少云空间权限：…”“云空间接口调用失败（错误码 …：…）”）和“重新上传”，处理好后点它，已上传的不会重复上传。权限见[配置飞书应用](feishu-app.md#在开发者后台手动配置)。

## 附件与转发消息

- **图片和文件**：先下载到本话题的状态目录，提示词里列出本地路径请模型按需读取，下载失败的单独列出。支持原生图片输入的后端，还会把 PNG、JPEG、WebP、GIF 图片直接交给模型，见 [Harness 说明](harnesses.md#支持的-harness)；超过该 Harness 能直接附上的大小的图片只给路径，执行过程里写明“… 张图片没有直接交给模型”。
- **回复消息**：回复某条消息时，被回复的内容也一起交给模型。
- **合并转发**：递归展开（最多 50 条、5 层），嵌套的文字、卡片、图片和文件都提取和下载；无权查看、下载失败和截断都会写明，不补造内容。任务卡上显示为“[合并转发 N 条…]”。
- **飞书文档链接**：机器人只取得链接和标题，不读正文，提示词要求模型按自己的权限读取。

## 脱敏词表

点菜单「设置」的「脱敏」标签（卡的标题是“敏感词脱敏”），一层，从上到下：

- 一行小字统计：几个词、近 7 天替换几次、几个话题开着脱敏。
- 两行小字说怎么生效：新话题默认开还是关（在「配置」页“新话题”一段改，已开的话题用换配置改）；只有 Claude Code 的模型能脱敏，默认开着时选了别的，启动卡和管家会先问你。
- **填词**：一个多行框，每行一个词（词里可以有空格；飞书输入框一次最多 1000 字），可以整批粘贴。点“加入词表”一次加进去；点“从词表删除”把框里的词一次删掉（要和词表里的词整词一致，“不区分大小写”开着时大小写不论），删后卡上有“撤销”，整批放回。加不进去、没找到的行按行号说原因。替身词由系统自动生成（“RX + 8 位十六进制”），不能指定。
- **试一下**（一直展开，就在填词下面）：粘贴一段文字，点“试一下”，显示发出去的样子、替换了几处，以及还原后是否与原文一致。
- 搜索框（一直在）：按词查找，下面写“找到几个”和“清除搜索”。
- **词表**：每页 10 个词，最新的在前，一个词一行：首字和字数，加近 7 天命中次数，右边是“删除”；删除后卡上有“撤销”。旧版本手动设过的替身词已不再使用，这些词也换成自动替身；旧版本设的“任意位置匹配”照常生效，行上标出来，删了再撤销能原样放回。
- 两个默认收起的折叠面板：**开关与上游地址**（“不区分大小写”“回复还原”点一下切换；Claude 账号的上游地址，“修改地址”在折叠面板下面打开输入框，“探测”看没填时这一轮的请求会发到哪里）、**记录**（开着脱敏的话题和最近 10 轮）。（飞书的折叠面板里放不了表单，所以试一下和上游地址的输入框都不收在折叠面板里。）
- **卡片上不出现原词**：词表里的词在卡上只写首字和字数（如“内··（4 字）”），替身词也不显示；框里输入的内容不留在卡上，加不进去的原因也不提原词。私聊和话题里的卡片，模型可能读到再发给厂商，所以这样做。框里输入的词提交时会经过飞书送到机器人一次。改动从下一轮起生效。
- **网页工作台**：开了[网页工作台](web.md)时，它的设置页也能批量加删词，和这张卡改的是同一份词表。以前的独立网页看板已经去掉。

## 本周用量

点菜单「用量」，私聊里收到一张「本周用量」卡（只读），不开任务。

- **范围**：最近 7 天（往前滚动 7×24 小时）开始的任务，私聊和各群的都算。一次运行算一次任务，提问后接着做的那一轮也算。
- **卡上**：最上面一条结论带写本周 token 总量，下一行是任务数、话题数和缓存命中占输入的比例，再下面一条分段条是任务怎么结束的（做完、在做、等你、排队、停住了、已停止，词和看板一样：你自己停的算“已停止”，失败、中断和负责人、护栏、代答停的算“停住了”）；然后是输入、缓存命中、输出三块数字，每天的 token 柱状图，各 Harness 的 token 占比环形图和表格（次数、token、缓存命中），最后一行“更新于”。已下架的 Harness 不算也不列。
- **token 总量**：输入加输出，含缓存命中，含子任务，和任务详情的算法一样。没有 token 记录的任务另写一行有几次。
- **本周找你**：结论带下面一行“本周找你 N 次：问题 a 次、停住 b 次”，只计数，不设目标。问题是这 7 天里发到你面前的问题卡（哪个聊天都算；专项负责人替你答了、没到你面前的不算），停住是这 7 天开始、结束在“停住了”的任务（你自己停的不算）。晚间汇总也带这一行。
- 每次点都按当时的任务记录重新算。

## 手上的事

部署开了「手上的事」时，私聊里置顶的那张卡原地更新，样子和[看板卡](#看板卡)一样：最上面一条结论带“要你处理 N 件事”（等你、停住了、可能卡住，整理专项等你定的提议算一件等你，和看板同一个数：同一套记录、同一条规则，`core/board_read.py` 的 `Asks`），下一行“先看：”最急的那个，再下面一条分段条；标题旁是几个等你、停住了、可能卡住、在做；没有要你处理的事时，灰字写“现在没有在等你的事”，什么都没在做时才写“现在没有在做的任务，也没有在等你的事”。下面每个话题一行，最前面是它的 T 号头像，然后是状态的圆点和词，要你处理的排前（等你 → 停住了 → 可能卡住）。每一行整行能点，标题后有“›”：

- **等你**：在等你的事，最新的在前：话题和管家、负责人问你的问题，还有等你在启动卡上点开始的消息。整行和右边的「去回答」直接打开那张问题卡或启动卡，下面写问的什么、几点问的。整理专项等你定的提议（私聊里才有）跟在问题后面，写提议的名字和要收进的话题，右边「建专项」「不管了」，和看板上的一样，点了这张卡马上重画。等了一天以上的不再单列，最后一行灰字写有几个和它们的话题号，旁边是“不管了”（开了话题看板时才有按钮）。
- **停住了**：和看板“停住了”同一批：最新一轮失败、中断、被负责人、护栏或代答停下的话题（按看板对结果的规则：没看过的一直列，看过 12 小时后不再列），和被护栏停住的专项（写为什么停，在看板上点「继续」）；整行打开那次任务的任务卡或专项卡。
- **可能卡住**：超过 30 分钟没动静的在跑任务，橙色；整行打开那一轮的任务卡（「看看」在那里）。
- **在做**：排队和在跑的任务，先开始的在前，写阶段，灰字是几点开始的（排队的写“排队中”）、预计几点做完、Harness 和工作区；整行打开那一轮的任务卡（补充、停止在那里），排队里还没有任务卡的不能点。
- **刚结束**：刚完成（有结果）、你停的（已停止）的任务，留 10 分钟；每行有一句话，同看板（有结果的第一行）；整行打开话题串里那一轮的卡。停住的列在上面“停住了”里。
- 部署配了网页工作台的地址时，最后一行“更新于”旁边有「打开网页」。
- 开了话题看板时这张卡是 Pin 的索引：结论带按全部的数算，下面只列没 Pin 上的，按 等你 → 停住了 → 可能卡住 → 在做 → 有结果 → 已停止 分组（你自己停的不再和有结果混在一起）。
- 每部分最多列 8 件。只有内容变了才重画（最多每 15 秒一次）。只列私聊里的任务，群里的不列。
- 卡只置顶一次：你在 Pin 里取消后不会再 Pin 上。每 7 天换一张新卡并置顶，旧卡改成“已不再更新”。

## 早晚汇总

样子和[看板卡](#看板卡)一样，是那个时刻的记录：标题写“汇总 · 21:30”，结论带的小字是“要你处理 · 21:30”，数和那个时刻的看板、手上的事一样（同一个 `Asks`）。每个话题一行（T 号头像、状态、标题、一句话、灰字），整行点了打开那个话题。

- **等你**：和看板的“等你”同一批（见[看板：自动 Pin 话题](#看板自动-pin-话题)）：每个话题最新的待回答问题，或等你在启动卡上点开始的消息，专项里的话题也列在这里；右边「去回答」或「去开始」。整理专项等你定的提议也列在这里，不带按钮（这张卡是记录），写“在它的提议卡或菜单「看板」上定”。等了一天以上的合成一行“另有 N 个等了一天以上：T…”，也算进个数。
- **停住了**：和看板同一批，不管多久前停的；右边「去任务卡」。被护栏停住的专项也在这里，写为什么停和“在菜单「看板」上点「继续」接着做”。
- **可能卡住**：右边「去任务卡」。
- **有结果没看**：上一次汇总之后做完的，加上更早做完、你还没看过的（和看板的“有结果没看”是同一批，标题后灰字写从几点之后结束、“另有更早没看的 N 个”）。
- **在做**：在跑或排队的。
- **做完、已停止**：看过的做完和你自己停的，收进最下面的折叠。
- 每组最多 8 行，卡太大时每组少列几行。你从看板撤下的话题不列。都空就不发。最后一行灰字“只列这个私聊里的话题，管家不列”，配了网页工作台的地址时旁边有「打开网页」。
- 之前版本发出的汇总卡（点“不管了”或“记下”时会按当时存下的内容重画）也画成这个样子。
- 部署开了知识条目时，卡的末尾多一节“新记的知识”：上次汇总以来新增、改写、作废的条目，最多 10 行；只有这一节时汇总不会单独发出来。
- 开了手上的事和话题看板时，那一行带「不管了」，和手上的事那个按钮一样；点了这一行变成灰字“已撤下 N 个”，旁边有「撤销」：把这一行列出的话题放回去（问题已经答了或收了的不会回来，也不出错）。手上的事底部“你撤下的 N 个”旁边是「撤销最近一次」：只放回你最近一次点「不管了」撤下的那批，手动取消 Pin 或管家撤下的不动（那一行列的是全部撤下的，批次可能是几天前的）；一天前的那批不再给按钮。
- **晚间汇总**：一天里最后一个汇总时间（比如设了 09:30 和 21:30，就是 21:30 那张）在三组后面多两行：“本周找你 N 次：问题 a 次、停住 b 次”（和本周用量卡同一个算法）；部署有代答时“今天代答发出 N 条”，有没发出去的再写几条、去菜单「代答」看。这两行只计数，汇总不会因为它们单独发出来。
- **整理记忆**（开着记忆就每天整理一次，当天收起了东西时晚间汇总才有这一节；规矩一条不收）：“收起 N 条：办完的 a 条、别的专项的 b 条、很久没用的 c 条”带「撤销」，收起的不再每轮带、用查记忆还能查到。待审核里只有推断要管全局的和涉及要你点头的规矩，汇总只有“记忆：待审核 N 条”一行。
- 看板不影响定时汇总。

## 看板卡

菜单「看板」的卡，标题旁是几个等你、停住了、可能卡住、在做，数法和结论带一样。最上面一条结论带：“要你处理 N 件事”（等你、停住了、可能卡住加起来，被护栏停住的专项算一件停住了；和手上的事是同一个数），下一行“先看：”最急的那个话题或专项（点结论带打开它），再下面一条分段条按件数画出各状态。下面每个话题一行，前面是状态的圆点和词，整行点了打开那个话题，标题后有“›”；打不开的那行灰字写“找不到它在私聊里的位置，打不开”。时间写到分钟（“等了 45 分钟”）：

- **等你**（橙）：要你定什么（那个话题最新一轮写的阶段）、等了多久，右边「去回答」。等了一天以上的合成一行，带「不管了」。
- **停住了**（红）：失败、中断、被负责人、专项护栏或代答停下的话题，写为什么停（负责人、护栏、代答停的写明是谁）、停在哪一步、几点停的。那一轮的记录能接着做时，右边直接是任务卡上的那个按钮：「检查并继续」，结果没发出去的「重新投递结果」（只重发存下的结果，不重跑模型），限流的「现在重试」；点了和在任务卡上点一样（排好的自动重试作废，不会两次都跑），看板原地重画，结论带下面一行灰字写“↪ T12 已接着做 · 任务 #N”或没做的原因；再点一次、重复的点击、在任务卡上已经点过，都不会多开一轮。不能在看板上接着做的（只能换个模型、之后换过配置、重启后已排好自动接着做）右边是「去任务卡」，灰字写下一步在任务卡上点什么。「不管了」把它从看板撤下（有了新动静会回来）。专项里的话题停住了：`COVEY_PROJECT_AUTOWAKE` 开着（默认）时它的回执会叫醒负责人，由负责人处理，不算“要你处理”，不列在这里（专项卡上照样看得到它停住了）；设成 `0` 时没人会被叫醒，它要你处理，列在这里。
- **可能卡住**（橙）：超过 30 分钟没动静的在跑话题，紧跟在停住了后面，右边「去任务卡」（任务卡上有「看看」）。
- **有结果没看**（绿）：做完了你还没看的，写结论的第一句；点进话题看一眼就算看过（网页上有「记为看过」）；看板上的「记为看过」「全部记为看过」小按钮已拿掉。
- **在做**（蓝）：现在在干什么，步骤进度条、预计还要多久、几分钟前有动静、已跑多久。
- **专项**（灰）：标题写“专项 N 个”。有等你、停住了、可能卡住、在做的专项排前；前 8 个各一块，写目标和它的话题里几个等你、停住了、可能卡住、在做，其余和收起的专项折成一行一个（“另有 N 个专项 · 收起的专项 M 个”，最多列 20 个）；它们在做和做完的话题不再单独列在上面。被护栏停住的专项（token 用完、连续唤醒到上限、很久没动静）块里写红色“停住了 · 原因”，右边「继续」：和停住卡上的继续一样，专项重新开始、叫醒负责人，看板原地重画；你自己停的专项写灰色“已停止”。部署开了整理专项时，这里是「整理专项」按钮（只在这里有）。
- **整理专项的提议**：等你定的提议是“等你”（橙色圆点和词，紫色“提议”标签），列在等你那一组的问题后面，算进“要你处理”，和手上的事一样；话题都能点开，右边「建专项」「不管了」直接定，定了看板原地重画，不用回聊天里找提议卡；要改名或增删话题，在提议卡的表单里改。
- **Covey 定时回看**（灰）：到点回来看开着（默认）时，有定时回看的话题各一行，写“Covey 将于 21:40 自动回看：看什么”，右边「取消」；排出去在看的那一行写“Covey 正在自动回看”，没有按钮。见[到点回来看](usage.md#到点回来看)。
- **做完、已停止**：上一次早晚汇总以来做完、都看过的话题，和你自己停掉的话题（任务卡上的停止、跟管家说停、网页上停、撤回原消息），收进最下面的折叠里（“09:30 以来做完的话题 N 个”，有你停的时写“做完 N 个 · 已停止 M 个”），和专项无关；折叠里每个话题号都能点开。
- 最后一行“更新于”旁边是「刷新」，原地按现在重算；配了网页工作台的地址（`page_url`，见[网页工作台](web.md#怎么打开)）时还有「打开网页」。再点一次菜单「看板」是收起，再点展开。
- 每个话题行最前面是它的 T 号头像（12 种颜色按 T 号分，见 [UI 规范](ui.md#4-组件)），看板、手上的事、早晚汇总、专项卡和回带卡上同一个话题同一个颜色。
- 话题和专项多到一张卡放不下时（飞书卡片的元素数和大小上限），每组少列几行，剩下的写成一行“另有 N 个”；结论带和标题旁的数照样算全部。
- 手上的事、早晚汇总和看板用同一套词：等你、在做、有结果、做完、停住了、已停止。

## 看板：自动 Pin 话题


部署再开了话题看板时，Bridge 把私聊里的话题自动 Pin 出来，「手上的事」固定在 Pin 列表最下面当索引：

- **顺序**（Pin 页从上到下）：等你 → 在做 → 有结果，组内新的在前。一个话题只出现在一组里。“有结果”包括完成、失败、中断和停止。
- **Pin 的是哪张卡**：话题自己的卡。等你 Pin 问题卡（等你在启动卡上点开始的 Pin 启动卡），在做 Pin 任务卡，有结果 Pin 这一轮的答案卡（答案写在任务卡上时 Pin 任务卡）。纯话题模式下有话题串的话题 Pin 一张三行状态卡：话题号和标题、状态和时间、一句话。点一下直接打开那个话题的话题串。
- **做完的留多久**：没看过的一直留着；看过之后从第一次看过算起再留 12 小时才自动撤。“看过”靠飞书的已读事件判断：读到这个话题在结束之后的消息才算。
- **“等你”到处一样**：早晚汇总、菜单「看板」、「手上的事」、管家的快照、网页工作台说的“等你”是同一批，个数也一样：话题和管家、负责人问你、卡已经发出的问题（交给负责人分流、还没轮到你的不算），加上等你在启动卡上点开始的消息（启动卡已经用过或没发出去的不算），每个话题算一个；等了一天以上的也算，只是合成一行；你撤下的话题不算。每一条都带入口，点开就是那张问题卡或启动卡。「手上的事」的“等你 N”是这个数，不是 Pin 了几格。
- **“有结果没看”到处一样**：看板、「手上的事」、早晚汇总、管家的快照和它查话题时说的“有结果没看”，都是看板这一组里还没看过的那些：完成、失败、中断和停止都算，没看过的不论多久都算。「手上的事」的“有结果”后面写“（未看 N）”，看过的那行标“已看”。
- **最多 10 个**：多了先让看过的“有结果”让位；还放不下的在「手上的事」里按组列出。
- **撤下话题**：在 Pin 页里取消它的 Pin；点「手上的事」里那行“不管了”；或跟管家说“T12 不用管了”。都只改看板，不动任务和问题。撤下的话题等有了新问题或新结果会自己回来。
- **不来回跳**：话题从“等你”或“有结果”变回“在做”时，原来 Pin 的卡跑满 5 分钟才挪。
- 顺序变了最多每分钟调整一次；Pin 和取消 Pin 不产生新消息、不加未读。

## 管家的细节

**表情和卡。** 你发一句话，它先不发卡，只在这句话上加一个表情：开工时 “OnIt”，自己答完换成 “DONE”，交给话题换成 “Get”，失败或被拒换成 “❌”，你停了或它要你回答时表情去掉。一轮跑过 90 秒还没完，它的卡才发出来，在你这句话的话题串里，能看进度、能停止。卡结束时状态行写它做了什么（“✅ 已答：开头”“↪ 开了 T44「标题」”“↪ 交给 T42 接着做”“↪ 拆成 2 件”）。一句话里有几件事就开几个话题；两个以上话题都像时，它出一道单选题问你。

**聊天区的消息。** 它直接给的答案、话题每一轮的结论、要你回答的问题卡，都作为新消息出现在聊天区最下面。最上面一块灰底写“你问 · 12:31 ›”和你那句话的原文（表单作答开的一轮写“你答”和“问题 → 回答”）。这一轮属于哪个话题，点了就跳到那个话题串里这一轮的位置；管家自己答的，点了回到你那句话在聊天里的位置。

- 只交给了话题、没说别的的一轮不另发答案，表情 “Get” 就是回执。
- 这一轮失败、被拒或超时，聊天区另发一条带“你问”的短消息说明；答案没发出去时，这条消息上有“重新投递结果”或“检查并继续”。
- 话题每一轮的结论和话题串里的答案卡一个样子，“输出”那行末尾多一个 T 号，点了跳到这一轮的卡。你自己点停止的那一轮不发。引用这些卡回话，就是对那个话题说。
- 聊天区那张问题卡上面带这一轮的输出。和话题里的卡一样，只有一道单选题时每个选项一个按钮，点了就提交。在哪张上答都一样，答了两张一起收起。

**交给话题的是什么。** 话题的模型收到管家整理的任务说明，加上你的原话和这条消息的图片、文件。话题的卡上只显示你的原话。

**原则管到哪。** 不管话题用哪个 Harness 都带上原则。只对某个工作区成立的记在那个工作区下；通用的只在你自己发的消息那一轮带上。

**不用管家。** 在「配置」页“管家”一段里把“私聊顶层的消息”选成“每条直接开一个话题”，卡上先说一句改了会怎样，点“确定改”才生效，顶层的新消息就各开一个话题。这时管家一段只剩这一行，选回“交给管家”马上改回。正在回答的那一轮会做完；管家开过的话题照常在各自的话题串里继续，只是结论不再回到顶层。管家的会话留着，改回时接着用。管家用的 Harness 暂时不可用时，顶层消息也会照旧新开话题。

**它在回答时你又发了消息。** 这条并入正在回答的这一轮。并不进去的排到这一轮后面。这一轮正在收尾、没来得及读到你这条就结束时，这条自动作为新的一轮处理，和你刚发的一样：表情和回答都在这条消息上，不用再发一次。几条都这样时按发出的顺序各算一轮。你点了停止的那一轮除外；送没送到说不准的，它在这条消息下说一句，不会重发。

**先转发、再说要做什么。** 只转发了卡片、聊天记录，只发了图片、文件或一个链接时，它等你说要做什么，最多 30 秒；这期间你写的话和转发的内容合成一次请求。

**它自己的设置。** 管家的任务卡没有回退和换配置，也不进「手上的事」。它的 Harness、供应商、模型、思考预算、脱敏在设置卡「配置」页的“管家”一段上改：Harness 可以是 Claude Code、Codex 或 Antigravity（没选时用 Claude Code，没启用 Claude Code 时用启用了的 Codex 或 Antigravity；Claude Code 没调通的新装默认就是调通的那个），脱敏只有 Claude Code 能开。管家用 Claude Code 时，上下文超过设置的阈值（默认 20 万 token），下一轮开始前自动压缩；Codex 和 Antigravity 自己压缩，Bridge 不介入。

### 引用卡片接着说

在聊天区引用一张直达话题的卡说话（话题带回来的结论、问题卡在聊天区的那一张、派发卡、管家只交给一个话题时那张卡或它下面的 “→ T53” 一行），这句话交给那个话题，任务卡和答案在那个话题的串里。你这句话下面没有卡，所以由它上面的表情说这一轮到哪了，和管家那一轮一样：

| 这句话 | 表情 |
| --- | --- |
| 排上就开工 | OnIt |
| 前面还有这个话题的任务，或机器人同时在跑的任务满了 | OneSecond，开跑时换成 OnIt |
| 正在跑的任务直接收下了（补充给它、它在等的那道题的回答） | DONE |
| 补充给的任务还没准备好接收 | OneSecond，送进去后换成 DONE；任务没等到就结束时，这句自动排成新一轮，表情跟着新一轮走 |
| 补充送没送到说不准 | 不加（回执上能“查送达状态”），后来确认送到了再加 DONE |
| 问题卡有几道题，这句先留作补充说明 | OneSecond，你提交回答时一起带上，换成 DONE；撤回就去掉 |
| 没能处理（结果或问题卡还没送达、这道题已经答过） | ❌，原因写在话题串里 |
| 做完 | DONE（不会是 Get） |
| 失败、被拒 | ❌ |
| 你停了，或它要你回答问题 | 表情去掉（问题卡在聊天区也有一张） |
| 重启打断了这一轮 | 表情去掉；检查并继续、自动重试时换回 OnIt，结束时照上面 |

- 在话题串里说话（包括回复串里的卡），或者话题的第一句（卡就挂在它下面），表情照旧：只有补充送进去时加 DONE。
- 群里也一样：群里引用这类卡说话，谁说的就在谁那句话上加。代答群不加。

## 群聊

- 机器人先去掉 @ 它的部分再处理。不管谁 @、@ 几次，群都不会自己启用。你第一次在一个群 @ 机器人时，它查一次这个群：外部群只记下，一直只处理你；其余的群等你确认，私聊里来一张启用确认卡（你的个人群、部署关了团队空间时不发）。一个群只发一张；没发出去（比如你还没私聊过机器人）时，你下次在那个群 @ 再发。查询失败时什么都不定，下次 @ 再查。
- **启用确认卡**：写明群名，启用后群里所有成员 @ 机器人都能开话题、追问、补充、回答问题、点卡片，这些话题在你的机器上用你的全部权限、凭据和模型额度运行，群里的人都看得到卡片、答案和产物。“启用”和群聊卡的“启用”一样；“先不启用”和“停用”一样：只处理你，你再 @ 也不会再问。点了以后卡原地换成结果；这个群已经定过（在这张卡上或群聊卡上）时再点，卡上说已经定过了，什么都不改。
- **群聊卡**：设置卡「群聊」标签列出记录过的群，每个群的状态（已启用 / 等你确认 / 已停用 / 未确认 / 外部群）。等你确认的排在最前，有“启用”和“先不启用”；已启用的可以“停用”，其余可以“启用”。停用后只处理你，你再 @ 也不会再问。群里发“停用本群”是普通任务。
- **免@**（部署打开时才有）：每个群一行多一个“免@”按钮，选这个群里谁说话不用 @：**关闭**、**只有你**、**你和选中的人**（列出群成员）、**群里所有人**（每个人的每句话都会开任务，以你的全部权限运行）。成员只在已启用的群里免@；代答在用的群不能免@。免@ 的群里 @ 了别人却没 @ 机器人的消息当作在跟别人说话，不接。两个机器人在同一个群都开免@ 时每句话两个都会接，一个群只给一个开。
- **群成员只读**：已启用的群一行多一个“设为只读”（设了以后标签「群成员只读」，按钮换成“取消只读”）。只读的群里，群成员开的任务（重试、检查并继续、回答问题后的下一轮都算发起人的）：Claude 只有 Read、Grep、Glob，不挂你的 MCP 服务；Codex 在只读沙箱里跑（命令能跑，写不了文件、上不了网）；别的 Harness 做不到，这一轮不启动，卡上说可以换配置换到 Claude 或 Codex。交给模型的消息末尾写明“这一轮只读”，检查点也不写，所以这些轮不出检查点问题卡。你自己的消息、你的任务照旧；群成员回答你的任务提的问题，下一轮仍是你的任务。部署设 `COVEY_GROUP_MEMBERS=read` 时，没单独选过的群按只读，启用确认卡也照这个写。
- **谁发的**：群里每条消息交给模型时，第一行写明发送者（“发送者：主人”或“发送者：群成员 …”）。
- 群成员点“添加或管理工作区…”或“其他目录…”时，卡上提示“仅机器人主人可以…”。其余被拒的消息和点击都不回复，只在 `bridge.log` 记一行。

## 代答

### 代答卡

机器人菜单的「代答」（部署有代答发送器才有这一项）打开这张卡。从上到下：

- **状态行**：“代答开着 ｜ 白名单 12 个 ｜ 3 条在处理”，关着写“代答关着”；有暂停的联系人时多一项“暂停 N 个”，没有在处理的就不写“在处理”。读不到你的消息或发不出去时，状态行上面先有一条警告，用人话写原因，变量名放在括号里。
- **开启代答 / 关闭代答**：总开关。“开启代答”是主按钮，“关闭代答”是文字按钮。第一次开启时机器人新建一个代答群（只有你和机器人），并把最近一次用的 Harness、模型、思考预算定为代答话题的配置。
- **登录**：网页登录正常时只有一行灰字“网页登录正常”；登录失效或还没确认过时才出“去登录”，二维码回复在卡下面，用飞书手机端扫码（用你本人的账号）。登录好以后，之前因为没登录而扣住的回复自动再发一次。
- **最近**：24 小时内要你看一眼的代答，最多 5 条，只有三类：**拟好没发**（回复写好了但没发出去：要你确认的建议、没发出去的、发前检查拦下的）、**发送结果待核**（可能已发出、不会自动重发）、**你自己回了**（你在会话里亲自回了，代答就没发）。每条写联系人和时间，原文和原因在那个联系人的话题里。没有时不显示这一节。
- **白名单**：每行“名称 · 私聊/群 @我 · 运行中/⏸ 已暂停”，带“暂停/恢复”“删除”。暂停后已经在处理的回复也不发；删除只移出白名单，话题保留。一起加入的群成员合成一行，带“暂停全部”“恢复全部”“删除全部”“同步成员”“逐个管理”。
- **添加**：输入框里可以一次写多个人名、邮箱、群名或 ou_/oc_ ID（一次最多 20 个），点“查找”后逐个列结果，点“全部添加”或单个“添加”。群有两个按钮：“群里@我”（只代答群里 @你 的消息）和“全员 N 人”（先确认，再把每个成员加成一条私聊白名单；超过 500 人的群不能整体加入）。
- **代答话题的模型**（最下面，标题行写着当前模型和思考预算）：Harness、供应商、模型、思考预算四行，和启动卡一样点开一行再点一项。改了就保存，所有联系人话题都用它，已有话题在没有任务进行时自动换过去。

点击被拒绝或出错时，原因写在这张卡上。只有最新的一张代答卡能用。

### 代答怎么工作

- **一个联系人一个话题**：每个人、每个群在代答群里各有一个话题，同一个会话接着聊。只回加入白名单之后的新消息；对方连发几条，合成一次回复（停下约 10 秒再回，至多等 45 秒）。
- **怎么回**：Bridge 把这个会话最近 20 条聊天（含你自己发的）附给模型，模型再按需检索（更早的聊天、相关群聊和文档、你的代码和记录、联系人笔记的摘要），答案明确就直接以你的身份发出，不等你确认，话题里记一行“✅ 已代你回复”。对方聊的是你在做的事时，模型以你的身份接话、给具体内容，不用反问代替回答。你在做的项目和常用说法写在 `<state>/proxy/owner-context.md`（只写能对外说的），口吻照 `<state>/proxy/style.md` 里归纳的你的聊天风格写，想调整就改这两个文件。群里是引用回复那条 @你 的消息。
- **不用回的时候**：对方只是收尾或确认（好的、收到、谢谢、表情），模型不发，话题里留一行“· 不用回”。
- **不回的时候**：涉及承诺、审批、费用、人事、隐私、凭据，或回错会有后果的事，模型不发，话题里出一张“⏸ 没有代你回复”的卡，有建议回复时带按钮**按建议回复**。你也可以在话题里 @机器人 说怎么回，那一轮的回复会发给对方。
- **对方又发了消息**：任务还在跑时对方又发了消息，这一轮的回复不发，新的一轮把前后的消息一起回（连着这样 2 轮后不再这样）。刚开始跑（不到 90 秒）的那一轮跑完再接新的一轮，新的一轮接着它的会话、不用重查一遍；还在排队或已跑得久的直接停下。
- **暂停、关闭、删除**：已经在跑的任务照常结束，但回复不发；恢复或开启后不会自动补发。对方最新一条消息已过去 2 小时还没发出的回复也不自动发。
- **不会重复发**：你已经在会话里亲自回了的，不跑任务也不发。每个联系人一小时最多代答 10 条。发送结果不明的标“⚠️ 可能已发出”，不会自动重发，请到会话里看一眼。
- **没发出去时**：确定没发出的会再试，共 3 次；都没发出时话题里出一张“⚠️ 代答没有发出”的卡，写为什么，下面是原文。点**重新发送**原样再发（不重新跑模型）。
- **发前检查**：每条要发出的回复先查有没有本机路径、内部编号（open_id、群 ID、任务键这类）、像密钥的字符串、没填的占位符（【…】、{{…}}、TODO 这类）。默认只记下命中了几次、照常发出，先看一周误报多不多；部署设 `COVEY_PROXY_REPLY_CHECK=hold` 后，命中的回复不发，话题里出“⏸ 没有代你回复”的卡，写着命中了什么，你看过点**按建议回复**照原样发，或在话题里说怎么回。
- **代答话题的工具**：话题用 Claude 时，模型只能读文件和搜索、跑只读的 lark-cli 命令（读聊天、搜消息、读文档），只能写这个联系人的笔记；别的命令和写别处的文件不执行。用 Codex 时照旧。
- 代答话题不出问题卡：模型要问你的问题会被丢掉，这一轮直接写回复。代答话题的任务卡只有“换配置”。

### 代发草稿

话题要以你的身份给同事发飞书消息时（比如把开好的 key 交给对方），这一轮结束后话题里出一张“✉️ 代发草稿”卡，私聊区顶层也提示一行。卡上写发给谁（姓名、部门、邮箱）、为什么发，正文在输入框里可以直接改。点**发送**才以你的身份私聊发出，发出的是框里的内容；点**不发**就不发。同名多人时先点选是谁。发出后卡上和话题里各说一句，话题之后的轮次也知道结果；没发出时卡上写原因，可以改了再点**重新发送**；结果不明的标“可能已发出”，不会自动再发。拿不准时在正文框下面那行写上想问的，点**先问一句**：这句交给写草稿的话题（它在跑就补充给它，否则排成下一轮），说明草稿还没发、卡还开着、要改就用同一个 id 重写；卡不重画，框里改过的正文还在，草稿不发也不作废。那一行是空的或话题已经找不到时，话题里回一句为什么没问。只有你能点。部署没有代答发送器时没有这个功能。

## 知识条目

- 话题里记：那一轮模型把要记的列在回复里，Bridge 在那一轮结束后记下；只有你本人说了“记一下 / 记住 / 记下来”才记，代答话题和开了脱敏的话题不记。
- 搜条目时说“包括改过的”，也搜已取代、已作废的。
- 每条最多 200 字，分决定、做法、坑、事实、待定五类；通用的所有话题都带，只对某个工作区的只有那个工作区的话题带。同一组里意思相同的不重复记。
- 新话题的第一轮带最近的条目（总共约 1500 字，超出的是较早的）；续接的会话只补上一轮之后新增或改动的。
- 部署还配了历史搜索（`COVEY_HISTORY_CMD`）时，话题里的模型和管家在你问“之前 / 上次 / 那个 X 怎么弄的”时会自己查：管家先查知识条目，再按链接、路径找话题，最后搜全部历史轮次。

## 停住以后

### 检查并继续

- 任务卡没法再改时，另发一张恢复卡，样子和任务卡一样：标题行（T 号、这一轮的标题、“停住了”标签），下面粗体写原因、灰字写下一步，再下面是检查点里写过的停在哪一步、已做完的，然后是按钮，按钮下面一行灰字“怎么继续：…”，点开是每个按钮做什么。模型还没写过检查点时不写“尚无记录”这类空话。点“检查并继续”或自动重试接走后，原卡片标题行右边写“↪ 限流后自动重试”这类说法，下面一行灰字“不用处理，接着做的进展在后面。”。
- 失败卡的技术详情最后一项是这个 Harness 自己的原话（如“Codex 原话：badRequest: …”），不论什么错误都写：密钥、令牌、key、路径、IP、邮箱、链接先遮掉，最多 300 字（`core/failure.py` 的 `said_of`）。按原因分的标题、按钮和要不要自动重试不变。
- 有“看原因”的卡上它旁边有“复制诊断”：机器人在话题里回一条消息，代码块里是这一轮的诊断摘要，整段复制给帮你排障的人：版本（Bridge 的 release 和第几代，这一轮的任务进程是别的 release 时也写）、设了哪些可选开关（同诊断页的规矩）、话题和任务编号、Harness 和模型、状态、开始结束时间、最近成功的一步、检查点、重试（自动重试几次、接着哪个任务做）、原因和技术详情、错误字段和失败回答的开头；像密钥的字样打码（`core/text.py`）。只有你点了有用，不开新任务、不调模型。
- 新任务带上原请求、上一轮结果和检查点。执行前机器人检查检查点里登记的、工作区内的产物是否存在，并要求模型先查询外部任务状态、禁止直接重复提交。检查点内容不是完成证明。
- 限流：走模型网关的 Codex、DeepSeek Harness 任务在同一轮里自己重试，不用点。
- 官方拒绝或降级：Claude 的主任务或子任务带了明确的 `refusal`、`fallback` 时停止这一轮；只有一个子代理第一次被拦时不停，执行过程里记一行，主任务自己绕开。因 cyber、bio 拒绝停下的一轮换旧模型在新会话里自动重试一次，原卡写“已转到任务 #N 继续”。见 [policy-stop.md](policy-stop.md)。

### 自动重试

下面几种情况结束、又没有发出任何回复时，机器人自动执行“检查并继续”。每次的等待时间另加 0–30 秒随机，同时停下的几个话题不会同一秒撞回去（`COVEY_AUTO_RETRY_LONG=0` 关掉下面前两条的新做法，回到原来的两次、没有随机）：

- **模型服务限流**（所有内置 Harness）：失败后 60 秒、3 分钟、10 分钟、30 分钟、1 小时、1 小时各一次，一共约 2 小时 45 分钟，仍然限流就停下。Claude 在限流输出里说了什么时候恢复（订阅额度的 5 小时或每周窗口）、而且在 6 小时以内时，改成恢复后 1 分钟（另加随机）自动继续，卡上写“预计 16:20 恢复”；没有写时区的时间不读，超过 6 小时的按上面的等待时间。重试的那一轮做了实事（至少 3 步工具调用、跑了至少 1 分钟）就把整条链的次数清零，所以一轮很长的活不会被很早以前的次数截断；在恢复时间重试后连续 3 次一点进展也没有，就停下留下失败卡。
- **模型服务临时故障**（所有内置 Harness）：529（过载）、500、502、503、504、连接被重置或断开、流空闲超时，Harness 自己重试用完之后：30 秒、2 分钟、5 分钟各一次；同样做了实事就清零。各 Harness 怎么认出限流和临时故障见 [harnesses.md](harnesses.md)；登录失效（401）、额度用完、模型不存在、请求被拒（其他 4xx）、安全拒绝和你点的停止都不算，不自动重试。读得出恢复时间的只有 Claude，别的 Harness 按上面的等待时间。
- **模型额度用完、知道几点恢复**（所有内置 Harness，[账号与额度](quota.md#失败说明)）：网关的号池全用完（快照或 429 的文字说了几点有号）、agy 每个号的这一组都用完时，恢复在 6 小时内就恢复后 1 分钟（另加随机）自动接着做，卡上写“额度预计 17:10 恢复”；一条链最多 3 次。超过 6 小时或不知道几点的不自动等，卡上写最早几点恢复、可以换个模型。
- **本轮未全部完成**（只有 Claude）：60 秒后一次；又这样结束就停下。设了任务超时的不自动继续。
- **被重启打断**（所有 Harness）：机器或机器人重启时任务进程没了，或任务进程收到 SIGTERM，这一轮按中断处理，机器人起来后 60 秒自动检查并继续一次；又被打断就停下。

- 各种各算各的次数，交替出现也不会重新计数（做了实事的限流或故障重试除外，见上）。你点过“停止”的、因官方拒绝停止的、有已保存的结果等着重新投递的，都不自动继续。
- 等待期间按钮上方一行“⏳ 模型服务限流，预计 20:10 恢复，将于 20:11 自动重试”（恢复时间不知道就不写；临时故障和别的两种写“第 1/3 次”这样的次数）之类，按钮多一个“停止自动重试”，按钮下面一行灰字“怎么继续：到点自动重试，不想等就点…”，点开是怎么取消和每个按钮做什么。额度用完（402）不自动重试：它的恢复时间没有可靠的来源，只给“换个模型”（额度快照或网关的话说了几点恢复的除外，见上）；模型网关的每日额度说了恢复时间的，卡上写几点恢复、能换到哪里，恢复前新的一轮直接停住（[harnesses.md](harnesses.md#每日额度用完)）。到点回来看的那一轮被限流或遇上临时故障时，盯守不结束，等自动重试那一轮的结果；重试被取消或用完才像以前一样结束。限流、临时故障和额度用完的卡上还有“换个 Harness”（另启用了别的 Harness、话题没开脱敏时）：和“换个模型”打开同一张换配置卡，只是预选另一个 Harness 里你最近常用、现在能用的模型（`app/availability.py` 的 `usable`：本机预检没说不可用，它最近一个任务没在 15 分钟内因限流、额度、账号被拦或登录失败停下）；不点“确认更换”什么都不换，计费不同的 Harness 不会被自动换上。到点前点“检查并继续”立即重试；点“停止自动重试”、在本话题发消息或换配置会取消它。
- 几个话题差不多同时因同一原因（限流或临时故障）停下、各自排好了自动重试时，你的私聊里只多一条提示：“N 个话题同样停在模型服务限流”，列出每个话题几点继续（读得到恢复时间也写）。第一个话题照旧只有它自己的任务卡；10 分钟窗口里的第一批发一次（最后一个话题停下 45 秒后），之后同一窗口再停的不再提示；重试又失败的不算新停。没排上自动重试的停止（管家的“停了”回带）不合并、不等：它在等你，一个话题一条，和以前一样。`COVEY_LIMIT_NOTICE=0` 关掉这条提示。“全部现在重试”和“全部换到某个 Harness”这类批量按钮现在没有：每个话题的任务卡上有自己的“现在重试”和“换个 Harness”。
- 计划写在任务记录里，Bridge 重启后照常执行。提交时出错时不再自动重试，卡片提示先查看话题再决定。

### 任务进程退出后

每个任务在自己的任务进程里运行。任务进程退出时（例如机器重启、崩溃、被 `kill`），任务**不会被静默重跑**，也不算“已停止”：原卡片换成“T12 · #N · 任务已中断”，写明当前阶段、已完成步骤和下一步，按钮是“检查并继续”。

任务进程在模型被调用前就退出时，机器人隔 2 秒自动再启动一次；再失败或根本起不来时，卡片换成“任务未能启动”，括号里写原因。

### 任务卡没出来

飞书拒收任务卡时，机器人先去掉“补充”“换配置”，只留“停止”再发一次。卡建好了、但回复到话题时被飞书明确拒绝（比如 2200 “Something went wrong”）时，先在原处再回复一次，还不行就改发到会话顶层；卡上的 T 号和任务号照常，点它的按钮照常进这个话题，任务记录的 `last_card_error` 记下飞书的错误码和最后发在哪。可能已经送达的失败（超时等）不再另发。都没发出去时，话题里收到“任务 #N 已收到，但任务卡没有发出去（飞书返回 …）。…”（点“检查并继续”“重试”时也在入队那句后面说）：任务照常执行，执行中每分钟再补发一次任务卡，最多 3 次；补发成功之前没法在飞书里停止它或回答它的提问，结果单独发回本话题。反馈问题时带上括号里的错误码。

### 结果送达失败

模型已经完成、但结果没能发到飞书时，任务不会重跑：

- 任务卡写“完整结果尚未成功发送，原始回复已保留。…”，机器人在后台自动重试投递。
- 重试按钮是“**重新投递结果**”（或等待回答的“**重新投递问题**”）：只发送已保存的正文和问题卡，不调用模型；已经送达的不会再发。
- 没送达的结果在等时，本话题的新消息先被拦下，提示先重新投递。
- 飞书内容审核拒收含明文邮箱或手机号的消息（错误码 230028）时，机器人把它们打码后再发一次；原文仍保存在本地任务记录。打码后还是被拒（或者没有可打码的）时，这一轮保存的回答作为 Markdown 文件发到本该放答案卡的地方，下面一行“飞书内容审核拦下了这条回答（打码后也没通过），原文作为文件发在上面。”；只发保存过的原文，不会重新跑模型。

### 机器人重启或更新

- 机器人重启或部署新版本时，正在执行的任务继续运行，同一张任务卡接着刷新，执行过程里注明“机器人 HH:MM 重启过，任务未中断。”，任务卡的“输出”行马上多一项“重启 HH:MM 没打断”，结束后的答案卡和回带卡也有。排队中的任务按原顺序继续排队。机器人停了很久、发过“⚠️ 机器人没起来”的，恢复时那条“✅ 机器人恢复了”还会写有几个任务一直在跑（[运维 · 机器人停了会告诉主人](operations.md#机器人停了会告诉主人)）。
- 机器人停着的那段时间点卡片没有响应，等它恢复后再点。
- 飞书把同一条消息再推一次时，机器人只处理第一次。
