# 使用参考

[使用指南](usage.md)每一节的细节：卡上每一项写什么、规则和时限、出了异常会怎样。按需查，不用通读。

## 菜单卡

**再点一下收回**：菜单一项的卡还是私聊里最新的一条顶层消息时，再点这一项，卡原地收起成一行；再点一次原地展开，内容按当时重新画。卡发出后你在私聊顶层发过消息、别的菜单项发过卡，或者机器人重启过，都不算最新，这时发一张新卡。

**每种卡只留最新一张**：发新卡后机器人撤回这一项的上一张。超过撤回时限或旧卡已经没了时，旧卡留着。

**旧菜单项**：应用里还留着的“工作区”“脱敏”“群聊”“管家”菜单项照旧能点，打开设置卡对应的标签或单独的卡。代答还是设置卡里一个标签时发的旧设置卡，停在“代答”标签上的照旧能用。

**飞书应用待补**：机器人自己检查飞书应用缺不缺它要用的权限、事件和菜单（比如升级后新加的菜单项）。缺了就在私聊发一张「飞书应用待补」卡，按权限、事件与回调、菜单分组列出缺的项。点“扫码自动补齐”，用飞书手机端扫卡下面的二维码（有代答的网页端登录时不用扫）；卡上一步步显示进度，最后写哪些已生效、哪些仍然缺。要管理员审核的权限单列、默认不申请。点“不管了”不再提醒这一组。做法和限制见[自动补齐飞书应用](feishu-app.md#自动补齐飞书应用)。

## 设置卡

菜单「设置」打开，一排标签“新话题 | 管家 | 工作区 | 脱敏 | 群聊”，部署开了节点时末尾多一个“设备”。点菜单先停在“新话题”。点另一个标签，这张卡原地换成那个面板，不发新消息；点当前标签，卡原地收起成标题和标签行，再点展开。

- **新话题**：所有新话题预选的配置，你自己发消息开的话题（启动卡）和管家开的话题都照它。一行一项：Harness、供应商、模型、思考预算、运行方式、脱敏、工作区；某一行选“跟上次一样”，就用你上次在启动卡上的选择，这一行写着现在会是什么。开了管家时下面多一行“直接开工”：都直接开工 / 只读的直接开工，改文件的等你点 / 都等你点开始，只管管家开的话题；选中间那档时下面列出“记住的工作区”（管家问过你“以后这类直接开工吗”、你同意过的），每项可删。最下面“更多”里是子 Agent 用什么模型（所有 Claude Code 话题和管家都照它：默认轻量，子 Agent 跑 Sonnet、搜索跑 Haiku；或者跟主模型）。
- **管家**：管家自己用的供应商、模型、思考预算、脱敏（Harness 只能是 Claude Code，写在标题下面）；“更多”里是压缩阈值和**私聊顶层的消息**：交给管家 / 每条直接开一个话题，见[管家的细节](#管家的细节)。部署不允许管家（`COVEY_BUTLER=0`）时没有这个标签，“新话题”页也没有“直接开工”。
- **工作区**：[工作区列表](#管理工作区列表)；开了管家时每个工作区下面一行灰字写它的“用途”，点“改用途”才出输入框，改完点“保存用途”。
- **脱敏**：[脱敏词表](#脱敏词表)，直接在卡上改。
- **群聊**：见[群聊](#群聊)。
- **设备**：部署开了节点时才有，列出每个节点现在的状况，可以添加、移除设备。

代答不在设置卡上，是菜单里单独的一项。

## 启动卡

| 选项 | 说明 |
| --- | --- |
| Harness、供应商、模型 | 分三级选：先 Harness（如 Claude Code），再供应商（如 Codex 自带 / 部署配的模型网关），模型只列选中的 Harness 和供应商的。卡上写成“Harness · 供应商 · 模型名”，Harness 自己的供应商不写（“Claude · Opus 5.5”“Codex · MyGW · GPT-6 Astra”，MyGW 代表部署配的某个网关），见 [Harness 和供应商](harnesses.md#支持的-harness)。只列各 Harness 最近读到的模型目录，读取失败的 Harness 不出现；目录还没准备好时只有一项“模型目录准备中，请稍后重新打开配置”。扩展 Harness 每个模型只列一项，它的推理预设是这一项的思考预算 |
| 模型的顺序 | 第一项是本聊天上一次开始任务用的模型；接着是本聊天最近 14 天选过的模型，选得多的在前；其余按 Harness 分段（Claude、Codex、DeepSeek Harness、Pi、Antigravity，扩展的 Harness 排在它自己声明的位置），段内按模型目录的顺序，部署可以用 `models_first` 把某些模型排到段首（见[配置](configuration.md#harnessesjson)）。私聊和每个群各算各的 |
| 思考预算 | 推荐档“推荐 · 档位”（模型支持的次高档；Codex 的 `ultra`、Claude 的 `ultracode` 是 xhigh 加多 Agent 编排，不算一档）、模型支持的各档（从高到低）、“模型原生默认（不指定）”。模型没有可选档位时只有“模型自动管理（无可选预算）” |
| 工作模式 | 只在提供工作模式的 Harness（公司扩展的 Harness）的模型时出现：“Focus（推荐）”一个 Agent 自己完成；“Adaptive（派子 Agent）”按需把工作派给子 Agent，更慢、用量更多 |
| 敏感词脱敏 | 只在 Claude 的模型时出现，“关 / 开”，默认值是设置卡「新话题」页的“脱敏”，见[敏感词脱敏](usage.md#敏感词脱敏) |
| 工作区 | 已保存的工作区，最近用过的在前；最后一项“⚙️ 添加或管理工作区…”打开管理页 |
| 运行方式 | “原目录”或“独立 worktree”（只能用于 git 仓库），见[原目录与独立 worktree](usage.md#原目录与独立-worktree) |
| 其他目录… | 在卡内逐层浏览目录，或粘贴绝对路径，见[浏览目录](#浏览目录) |

**预选**：

- 先看设置卡「新话题」页：那一页选了模型、工作区、运行方式、脱敏的，照它预选；只选了 Harness 没选模型时，上次用的是这个 Harness 的模型就用上次的，否则用这个 Harness 的默认模型。
- 「新话题」页选“跟上次一样”的项，预选本聊天上一次开始任务时的选择；本聊天还没开始过任务时，预选最近一次在任意聊天的选择。上次的工作区已不在列表里时预选列表里标“兜底”的工作区。运行方式没设时从“原目录”开始。
- 思考预算：设置卡「新话题」页设了思考预算时，同一 Harness 的模型先预选这一档（模型支持它时；比如设成 high 后启动卡不再推荐 xhigh）；没设、Harness 不同或模型没有这一档时，预选本聊天给这个模型最常选的一档（最近 14 天里最近 10 次）；没选过时预选推荐档。没有合适的推荐档时不预选，提示“此模型没有合适的推荐档，请选择预算”，选好才能开始。
- 换一个模型后，思考预算按上一条重新预选，工作区、运行方式保持。

**点“开始任务”之后**：

- 启动卡变成回执：绿色对勾和“已提交”，标签写运行方式和敏感词脱敏，副标题写话题、模型和思考预算，正文是工作区名（完整路径在“完整工作区路径”里）。任务卡随后出现（通常 1–2 秒）。
- 提交时再核对一次：模型或预算目录刚更新、所选目录不存在时，任务不启动，按提示重新选择后再点。重复点击不会重复开始。
- 话题开始后再点它的启动卡，提示“本话题配置已固定；新任务请在主聊天发送消息”。
- 启动卡没能发出时，话题里收到“配置卡暂未送达，请在本话题回复消息以重新显示；任务尚未启动。”。在本话题再发一条消息就会出现新的启动卡。

开始前在话题里继续发的消息也会保存，每条下面各出现一张启动卡。在任意一张上点“开始任务”，这些消息按顺序依次执行。启动卡 7 天没人点（期间话题里也没有别的操作）时自动关闭，卡上写“超过 7 天未处理，已自动关闭；需要继续请在本话题直接发消息。”。

## 工作区

### 浏览目录

启动卡的“其他目录…”和管理页的“＋ 添加工作区…”用同一个浏览页，整张卡换成它：

| 控件 | 作用 |
| --- | --- |
| 📂 当前目录 | 目录名和完整路径；已在工作区列表时写“· 已在列表” |
| “上一级”“刷新” | 回到父目录；重新读取当前目录 |
| 搜索框、“搜索” | 填名称：搜当前目录的子目录（不分大小写，包含即可），往下最多 3 层。填以 `/` 或 `~` 开头的路径：直接前往 |
| 目录行 | “进入”进入该目录；“使用”（启动卡）或“添加”（管理页）直接选这一项。每页 15 行 |
| “使用此目录”/“添加此目录” | 选用或添加当前目录 |
| “返回”/“返回管理页” | 回到启动卡或管理卡，不改动已选内容 |

- 启动卡上选用后，卡片回到启动卡并写明“已选择工作区：名称”。仍要点“开始任务”才会启动。
- 列目录只读当前这一层，不跟随链接。搜索不进以 `.` 开头的目录、`node_modules` 和 `__pycache__`，最多查 5000 个目录、6 秒；没查完时状态行写“只查了前 N 个目录，可进入子目录再搜”。
- 读取或搜索要等时状态行写“正在读取…”，读到后卡片自动刷新。

### 管理工作区列表

两个入口：菜单「设置」的「工作区」标签；或启动卡工作区一行最后的“⚙️ 添加或管理工作区…”（整张启动卡换成管理页，底部有“返回启动卡”和“结束，不启动任务”）。

- 列表里兜底的工作区在最前，其余最近用过的在前，每页 8 个。每行是名称、状态标签（兜底 / 目录不存在 / 未确认）、路径和最近使用日期，右侧是“移除”。新话题用哪个工作区在设置卡「新话题」页的“工作区”一行选；“兜底”只是启动卡没有上次可跟时用的那个。
- 超过一页时列表上方可以按名称或路径搜索、按状态筛选（全部 / 目录不存在 / 30 天以上未使用 / 从未用于任务）。有确认不存在的目录时，多一个“移除不存在的（N）”。
- 移除只改列表，不删除磁盘上的目录；已开始的话题记下了自己的目录，不受影响。兜底的工作区不能移除。
- 其他话题还没开始的启动卡仍可能列出被移出的工作区，选它开始会提示“未找到该工作区，可能已从列表移除；…”。

服务器上用命令维护工作区列表见[日常操作](operations.md#日常操作)。

第一次用的目录自动加入列表，名称取目录名，重名时加 `-2`、`-3`。

### 独立 worktree

- 机器人从仓库当前提交（`HEAD`）新建分支 `bridge/<时间>-<话题 ID 前 8 位>`，在数据根的 `worktrees/` 下检出，话题在与所选目录对应的子目录里运行。源检出里未提交的改动不会带过去。
- 点“开始任务”后整张卡换成“正在创建独立 worktree…”，通常几秒到十几秒，完成后任务自动开始。
- 检出失败（包括检出期间服务重启）时，卡片换回启动表单并保留已选内容，顶部写“⚠️ 任务未启动：原因”。已经建好的 worktree 不会删除。
- 话题结束后 worktree 和分支都保留，由你合并或自己删除（例如 `git worktree remove <路径>`）。

## 排队

- 排队的消息有自己的任务卡。前面有本话题的任务时，卡的第一行（状态行）写“这句话会在 #1190 结束后单独执行”；阶段写“排队中 · 排在 #1190 后面 · #1190 已运行 1小时23分（10:05 开始）”或“排队中 · 并发已满（最多 10 个任务）”。
- 任务在跑时在话题里发的消息先补充给它（`COVEY_TOPIC_STEER`，默认开，见[排队消息卡上的补充](#排队消息卡上的补充)），没送进去才留在这里排队。
- 每张任务卡上的“停止”只取消这张卡的任务：排队中的立即取消、不调用后端。
- Claude（和有同样行为的扩展 Harness）的原生问题等你回答时，任务仍占一个执行名额；Codex 遇到必须回答的问题会结束本轮、释放名额；检查点里登记的问题也在本轮结束时释放名额。

## 补充

补充表单的标题是“补充任务 T8 · #252”。提交后表单换成一行回执，“查看详情”里列出各状态的时间和补充原文。任务结束后，还开着的表单变成“任务已结束，不能再补充”。

### 打断正在跑的命令

Claude 只在两次工具调用之间读补充，一条长命令在跑时，补充要等它结束才读到。两种办法让它马上读到：

- **点“打断它，马上读”**：回执卡上，补充还没读到时出现。Bridge 停掉模型正在等的那条命令（只停这条命令，不停这一轮），模型拿到命令被停的结果，接着读补充。
- **急的补充自动打断**：补充里有“马上”“立刻”“赶紧”“停一下”“过期”“重发”这类词，送达 20 秒还没读到，Bridge 自动这样做。负责人或管家转给话题的话也算。

推送、部署、发布、安装、远程拷贝、改服务、删除和移动文件这类命令（`git push`、`deploy`、`pip install`、`kubectl`、`rsync`、`rm`、`mv` 等）不打断，回执上写明；模型在等子任务或正在写回答时没有命令可停，回执上也写明。设备上的任务不能打断。时长和开关见[配置](configuration.md)的 `COVEY_STEER_URGENT_SECONDS`。

### 送达状态

每条补充只发送一次：

| 卡上写法 | 含义 |
| --- | --- |
| ✓ 任务开始前收到，已并入本轮请求 | 目标任务还在排队，补充并入它的请求 |
| ⏳ 已保存，尚未送达 #N | 任务刚开始，后端还不能接收。先保存，能接收时自动送入，只送一次；送入前可以“撤回” |
| ✓ 后端已接收 · 当前一步结束后读到 | 已交给模型后端。模型在手上这一步（一条命令、一个子任务）结束后才读到它；长命令或前台子任务在跑时要等它们结束 |
| ✓ 已送达 · 还没读到 · 已等 N 秒 | 只在 Claude：已交给后端，模型还没读到。送达后 20 秒、1 分钟、3 分钟、10 分钟、30 分钟各刷新一次等了多久；下面有“打断它，马上读” |
| ✓ 模型已读取 | Claude 把补充回放进了会话（只有 Claude 有这一步） |
| ⚠️ 任务 #N 已结束，模型没有读到这条补充 | 只在 Claude：后端接收了，但任务在读到它之前就结束了 |
| ⚠️ 没有补充到 #N：原因 | 什么都没发出（任务在收尾、已结束、在等回答，或后端拒绝）。表单保留内容，可直接再次提交 |
| ⏳ 补充 #N 送达未确认 | 发出后没拿到确认。**不会自动重发**，点“检查送达状态”核对 |
| 已撤回，这条补充没有发给 #N | 在送入前撤回了 |
| 已补充到 #N，不另开一轮 | 任务在跑时在话题里发的消息，自动补充给了 #N（[排队消息卡上的补充](#排队消息卡上的补充)）；后面跟着上面各行的送达状态 |
| #N 结束前没有读到这条补充，已排成新一轮 #M | 自动补充的消息确定没被读到，自动排成了新一轮，只排一次 |

回执上的按钮按状态出现：**撤回**（已保存、尚未送达时）；**检查送达状态**（送达未确认，或 Claude 已接收、还没读到时；只核对已有记录，不重发）；**重新排队执行**（只对排队消息转成的补充，在没有发出、已撤回或模型没有读到时可用，把原消息排成一个新任务，只能排一次；自动补充的消息确定没读到时自己排，不出这个按钮）。

补充送入后，目标任务卡在“本轮请求”上方显示“📝 最新补充 HH:MM · 内容开头”。

### 任务在等回答时

任务在等一个**必须回答才能继续**的问题时，机器人不发送补充：暂停中的回合不接收输入。这时点“补充”回复“补充当前任务未完成：任务 #N 正在等待回答，请先回答问题，之后可以再补充”。Codex 的**非阻塞**提问（问题卡写“其他工作继续”）不暂停任务，补充照常送入。

### 排队消息卡上的补充

排队消息自己的任务卡上的补充按钮写作“现在补给 #N”，它补充的是**上一任务**：同一话题里排在这条消息之前、最近的那个未结束任务，按钮上写出编号。这条消息的任务开始后，按钮改回“补充”，补充的是它自己。

- 点一下就把这条消息原样交给上一任务，连同附件和话题背景。不点，这条消息照常排队。
- 上一任务已结束、已取消或正在等回答时不发送，这条消息继续排队，原因写在它自己的卡上。
- 送入后排队卡整卡换成回执“✓ 已补充到 #N，不再单独排队”，这条消息不会单独执行；送达未确认时也不单独执行，以免重复。

**任务在跑时发的消息自动这样送**（`COVEY_TOPIC_STEER`，默认开；设成 `0` 就只在点按钮时送）：上一任务已经开始，消息一进来就照上面点一下那样交给它，卡先写“正在补充到 #N”，随即换成回执“✓ 已补充到 #N，不另开一轮”，查看详情里写“来源：#N 在做时发到话题里的消息，自动作为补充交给它”。只对支持执行中补充的后端，不含管家（管家本来就补充）；群里谁的消息被服务，谁的就这样送，送进去的话和平时一样以发送人开头。

- 连着发几条：每条各是一个补充，按收到的顺序送，每条只送一次；飞书重投同一条消息也不再送。
- 没有发出（任务正在收尾、已结束、在等回答，或后端拒绝）：消息照旧排成下一轮，卡的第一行写“这句话会在 #N 结束后单独执行”，下面一行写“⚠️ 没有补充到 #N：任务正在收尾，不能再补充”这样的原因，按钮“现在补给 #N”可以再试。
- 送达未确认：和点按钮一样不单独执行、不重发，回执上点“查送达状态”核对。
- 确定没读到（任务刚开始时保存的补充没等到送入任务就结束了，或 Claude 到结束都没读到它）：自动排成新一轮，和点“重新排队”一样只排一次，回执写“#N 结束前没有读到这条补充，已排成新一轮 #M”（排队进行中写“正在排成新一轮”）。你停掉的任务带着的补充不自动排，回执上留“重新排队”。
- 任务在任务进程里跑时，任务进程只标记，任务进程结束后由 Bridge 排；那一刻 Bridge 不在（重启、部署），下次启动时由话题所在 Harness 补排。

## 回答

### 问题卡

问题卡开头是结论带：小字“等你 · T12 #108”，大字“要你定：”加问题（几道题时写“3 个问题”），灰字说明它会不会挡住任务：“等你回答后继续”（任务等你）、“其他工作继续”（不阻塞）、“本轮已结束，可继续补充”。

- 每道题以题号和题目标签开头。只有一道有选项的单选题时，每个选项一个按钮（最后一个是“不回答此题”），点了就提交，补充说明一起带上；回答框里写了字再点选项，以点的选项为准，要按写的回答提交就点“提交回答”。几道题时有选项的题是下拉框（多选题为多选框）。下拉框下面还有一个“自己写回答”的输入框：写了就以写的为准。没有选项的题只有回答框。
- 每道题都能选“不回答此题”，模型收到“用户选择不回答此题（不表示同意或授权）”。
- 卡片最下面是**补充说明（可选）**输入框，不针对某一题，模型收到单独一段“用户补充说明：…”。
- 输入框只能填文字，每个最多 1,000 字符；只有一个待答问题时直接在话题里回复不受这个限制。
- 漏答或填法冲突时，机器人回一张小卡说明原因，改好后在问题卡上再点“提交回答”。
- 卡片里不能放图片。有问题待答时发的图也会交给模型：单题时随回答一起送出，多题时随暂存的补充一起送出。
- **以后这类按推荐走**（`COVEY_STANDING_ANSWERS=1`，`./install` 默认开）：每道题都有一个推荐选项时，卡下面多这个按钮。点了小模型起草一句原则，另发一张卡写着这句话，按钮“记下”“改一下”“算了”。点“记下”才把它记成这个工作区的原则，并按推荐选项回答这张卡；之后这类问题不再问你。只有你点了算数。

### 多题待答时直接发的消息

多道题待答时，话题里直接发的消息既不当作回答，也不排成新任务，而是暂存为补充，出现小卡“📝 这条消息还没发给模型：#1106（20:24）的 2 道题还没答，提交回答时会一起带上”。按钮：

- 什么都不点：它随下一次提交的回答一起交给模型。
- **作为问题反馈发送**：现在就把它作为对问题的反馈交给模型。反馈不算回答，未回答的部分不视为同意或授权。
- **留作下一轮**：问题都回答后，这条消息单独排队执行。
- **撤回**：这条消息不发送。

一条补充只会发送一次。已经随回答发出时，小卡改为“已随回答一起发送”。

### 回答之后

- Claude 的原生问题：答案送回仍在等待的原任务，同一轮继续。
- Codex 必须回答的问题，以及[检查点](usage.md#长任务与检查点)里登记的问题：提问时本轮已结束，答案排成同话题的续接任务，在同一会话里继续。续接任务卡标题写“问了什么 → 答了什么”。
- 不阻塞的问题：任务还在执行时答案直接送入；本轮已结束时排成续接任务。

回答后问题卡折叠成摘要，标题写明去了哪：“❓ #1107 的提问 · 已回答 → #1111 有结果”。重复提交、在别的话题提交都会被拒绝。

- 标题为“回答已保存 · 送达未确认，请先核查，不会自动重复发送”时，卡上有“核查已保存回答并继续”：排一个续接任务，先核查后端会话、已有产物和外部操作再继续。
- 同一话题出现新的问题卡后，更早还没回答的问题卡自动收起，写“已收起 → #1106 又提了问题”，要说的写在新卡上。
- 模型提出必须回答的问题时，机器人**先把正文发到话题，再显示问题卡**。正文没送达时不显示问题卡，在话题里发消息会提示先点重试按钮补发。
- 停止任务会同时取消它还没回答的问题。任务进程退出后（例如机器重启），原生等待中的问题随进程失效，需要继续时在话题里重新说明要求。
- 问题 7 天没有回答（期间话题里也没有其他操作）时自动关闭，等它的任务一起关闭。

## 撤回与编辑

- **撤回**：这条消息的任务还在排队就不执行，在跑就停下，任务卡写“原消息已撤回”。如果它是发给正在跑的任务的补充，任务会再收到一句“这条撤回了，别按它做”。这一轮已经记下的记忆和知识条目也一起作废。管家已经因为这条消息开了话题的，话题串里会出现“来源消息已撤回”和一个停止按钮，停不停由你定。
- **编辑**：正文真的改了才算（只加了话题串、表情不算），改后的内容作为补充交给这条消息的任务。还在排队的，开跑时直接按改后的做；在跑的，当前一步结束后读到。任务已经做完的不会自动重做，话题里会提示你一句，要重做就再说一句。
- 只对你自己发的消息生效；撤回或编辑超过一天，或者任务结束超过 10 分钟后才改的，不再跟进。Bridge 重启后，重启前发的消息也不再跟进。
- 回复一条被撤回或编辑过的消息时，模型会知道它已撤回（不会看到原文），或者看到的是改后的内容。

## 换配置卡

在任务卡（排队、运行中和结束后的都有）上点“换配置”。在话题里发“换配置”是普通的补充或追问。

1. 话题里出现一张“换配置”卡，第一行是当前配置。下面是和启动卡一样的清单：点一行展开选项，点一项选中，卡片重画。和当前配置不同的那一行名称变成蓝色加粗；一项都没改时“确认更换”是灰的。
2. 分级选 Harness、供应商、模型。提供工作模式的 Harness 的模型还有工作模式一行。
3. 工作区（不能在这里输入新目录，先在设置卡「工作区」里添加）和运行方式。
4. 选中 Claude 的模型时还有脱敏一行。开着脱敏时选了不能脱敏的模型，卡上写明确认后本话题会关闭脱敏，点“确认更换”先弹确认框。
5. 点“确认更换”。成功后卡片变成“🔁 已换配置”，逐项写改了什么。点“取消”则话题保持原样。

## 换配置之后

确认更换时会重新检查：有任务在排队或执行、正在创建 worktree、有回答在提交，或上一轮结果还没送达时，卡上出现“⚠️ 还没有换（时:分）：…”，话题保持原配置，已选的项不变。处理完（例如先点任务卡上的“停止”）再点“确认更换”。

更换后：

- **换了 Harness、供应商、模型、思考预算、工作模式、工作区或运行方式**：下一条消息开一个新会话。从 Claude 的模型换走、且之前已有会话时，原模型先在更换前会话的一个分叉上写一份交接摘要（目标、已做的决定、当前状态、文件和提交、未决问题和下一步，约 1500 字以内，存在话题目录下的 `handoff/summary-r<版本>.md`）；任务卡的执行过程里写着“正在请原模型写交接摘要”，最多等 3 分钟，失败、超时、原来不是 Claude，或刚 ↩️ 回退过一轮还没发下一条就换配置时没有摘要，照常往下走。原会话被安全拒绝或官方模型降级停过、是安全拒绝后换旧模型重试的那个会话、或已禁止续接时，也不写摘要，执行过程里按原因写一行。等摘要时点停止，这一轮就此停下，新模型不会开跑。新会话的第一轮拿到摘要、最近几轮问答的原文（有摘要时 1 轮，没有时 3 轮，每条超过 2000 字的截断），和一个完整会话记录文件的位置（话题目录下的 `handoff/transcript-r<版本>.md`），模型需要更早的背景时自己去读。换了工作目录时还告诉它原来的目录在哪。这些只给换配置后的第一轮（第一轮没留下可续接的会话时给下一轮）；之后同一配置下再开新会话（安全拒绝后的自动重试、会话因失败不能续接、回退了会话的第一轮）都和平常的新会话一样，用最近几轮问答。
- **工作区和运行方式**：原目录 → 独立 worktree 时，从所选工作区的当前提交新建分支和 worktree；独立 worktree → 原目录时直接回到工作区目录，原来的 worktree 和分支保留。
- **只改敏感词脱敏**：会话不变，下一条消息起生效。之前各轮已经原样发出过，收不回。
- 之前留下的待答问题作废（只改脱敏时不作废）。
- 更换前的任务卡只能查看，不能再重试、回退或换配置。
- 换回之前用过的 Harness 时同样开新会话，不接着它更早的会话。

## 回退

- **文件怎么改回**：用 Claude Code 自己的文件快照，把这一轮用编辑工具改过的文件改回这一轮开始时的样子，新建的文件删除。命令改的文件和 git 提交不会动；原目录运行时，别的话题之后对这些文件的改动也会一起改回。
- **只能回退最新一轮**，一次一步。话题有任务在排队或执行、有回答在提交、结果还没送达时不能回退。换过配置之后，换之前的轮次不能回退。代答话题和管家没有这个按钮。
- **撤销回退**：只回退了对话时，发下一条消息之前可以点“撤销回退”。连文件一起回退的不能撤销。
- 其他 Harness 没有这个按钮。

## 任务卡

**标题栏**写“T12 · #196 · 问题开头”，卡片标题发出后改不了。**状态**是带颜色圆点的加粗状态词（词和颜色见 [UI 规范](ui.md#3-状态词表)），结束后写几点结束。**输入/输出灰框**：“输入”是 Harness ｜ 供应商 ｜ 模型 ｜ 思考 xhigh ｜ 脱敏开/关 ｜ 工作区；“输出”运行中是开始时间 ｜ 已运行 ｜ token ｜ 每秒 token 数 ｜ 上下文占比，结束后是用时 ｜ 每秒 token 数 ｜ token ｜ 缓存命中比例。

**状态行**写得很短：

- 运行中一般是“阶段：…”和“当前：最近一步 · 2 分钟前在跑测试”。命令写模型自己说明的用途，没有用途时写命令本身（去掉 shell 外壳和管道尾巴，长路径只留最后两段）。子任务运行时写子任务最近的一步。“2 分钟前在跑测试”是最近一次动静（执行过程的一步、流式输出、模型请求、检查点更新）和它的人话，只写到分钟，不到一分钟不写，从不写原始命令。
- 检查点写了 `steps` 且这一轮做完了至少两步（或这个话题以前做完过三轮以上）时，第一行末尾写“预计还要约 40 分钟”：按这一轮平均每步用时（从第一次看到计划算起；那时已经标完成的步骤是上一轮做的，不算）乘剩下的步数，再减去当前这步已经做了的时间，所以干等着只会往下走，不会越等越长；以往各轮用时的中位数比这一轮已用的长时，再往它拉一半；估不出来就不写。
- 当前这步做得比此前平均每步还久时，不再给“还要多久”，改写“本步 35 分钟 · 此前平均每步约 6 分钟”；看板、手上的事和汇总写“第 3 步比此前几步慢”。
- 超过 30 分钟没有动静（`COVEY_PROGRESS_STUCK_MINUTES`）时，状态行的状态词变成“可能卡住”，下面写“超过 30 分钟没有动静，可能卡住了”，再多一个“看看”：Bridge 只读地看一眼这一轮的任务进程、它下面的进程这一秒有没有在用 CPU、任务进程的日志和执行过程最近几步，在话题里回一句结论（还在干活、在等某条命令、在等模型、任务进程已经不在了）和依据；话题用 Claude Code 且没开脱敏时，这句话由小模型按这些依据写。它不停、不改、不重跑任何东西。有了新动静或这一轮结束，按钮自动撤下。
- 任务详情里写阶段、步骤（已完成 3/5）、最近动静（“14:05 在跑测试”）和预计（“预计还要约 40 分钟（14:20 估）”；这步慢了写“第 3 步 16:33 开始，此前平均每步约 6 分钟”）。
- 模型请求在重试时写“模型请求重试中 · 第 N 次 …”和上游原因，可以点“停止”结束等待。
- 还没有输出时写“当前：已提交给模型，等待首个输出”；只在思考、不流式输出时写“当前：模型思考中”。
- 检查点里写了 `steps` 时，状态行写“第 3/5 步：<步骤> · 本步 40 分钟”，看板的状态卡和管家的快照也写第几步。
- 运行一结束，状态行换成结局和结束时刻，按钮行同时移除。结果没能送达时改为“停住了”。

**用时**在每张卡上是同一个数：从 Bridge 请求后端开工到这一轮执行结束（`core/metrics.py` 的 `run_seconds`）。写法“45秒”“1分30秒”“1小时23分”。

**话题列表的预览**跟着任务走：排队时“T42 排队 · 问题开头”，运行中“T42 在做 · 阶段”，等回答时“T42 等你”，结束后“T42 有结果 · 用时 3分39秒”。答案卡的预览是“T42 有结果 · 回答开头”。卡片标题只取文字，像密钥的值写成“[已隐藏]”。

**执行过程**是一个折叠面板，运行中展开、结束后折叠，标题写“执行过程 · 128 步”。

- 按时间从早到晚排，最新的在最下面。主任务和子任务的条目按开始时间穿插，子任务的条目前面写“子任务 · 名称 · ”。
- 进展说明保留全文，放在浅蓝底块里。两条说明之间的命令、文件修改、搜索、工具调用逐条列出：“✓ **执行命令** · 1.2 秒 · 10:32:06”（完成 ✓、运行中 ●、失败 ✕），下一行灰字是摘要。一段超过 8 项时只列最后 3 项，前面的收进折叠的“收起了更早的 N 项操作：…”。
- 卡片约 30 KB 放不下时，从最早的一段开始把命令收成一行计数，最后才收进最早的进展说明。最后一条进展说明的结尾始终完整。
- 写本任务检查点文件的命令显示为“更新检查点”。没收到完成事件的步骤标“结束状态未确认”。
- 机器人重启时插入一行“机器人 HH:MM 重启过，任务未中断。”。
- 卡片不显示工具输出和推理内容。没有执行记录的一轮结束后是一行“执行过程 · 无执行记录”。

**任务详情**只写别处没有的：工作模式、设了超时时的超时、敏感词脱敏的替换数、TTFT，有子任务时分主任务和各子任务的 token。都没有时不显示。

- token 是本轮主任务加各层子任务的合计，含缓存命中，每次模型请求只算一次。它是各次请求的输入之和，不是一次请求的上下文长度，也不是计费折算量。token/s 是主任务的平均输出速度，后端给了生成计时才有。
- 子任务的用量没收全时写“部分统计：”和缺什么。后端没提供的项不显示，不估算。口径见[执行指标口径](architecture.md#执行指标口径)。

**本轮命令留下的进程**：每轮后端关闭后，机器人查找这一轮的命令留下、仍在运行的进程。搜索工具（rg、grep、find、fd 等）直接结束，执行过程里写“机器人 HH:MM 结束了本轮命令留下的 N 个搜索进程：…”；其他进程（服务、训练等）不处理，只写“本轮命令留下的 N 个进程仍在运行，没有处理：…”，需要时自己结束。

**内存看门狗的告警**：开了[内存看门狗](operations.md#内存看门狗)的机器上，某个任务的命令占内存过多时，机器人在这个任务的话题里发一条“【内存看门狗】…”；不属于任何任务的发到私聊。每小时最多 6 条。

**刷新节奏**：前 3 分钟流式更新，状态行约每 2 秒刷新；之后状态行每 60 秒刷新，检查点或重试状态变化时提前刷新。超过 15 分钟没有新进展时加一行“较长时间没有新进展，可能正在等待外部任务；尚不能据此判定失败。”。机器人不推断失败，也不生成进度百分比；“后端进程仍在运行”只说明本机进程活着，**不能证明外部训练等任务健康**。

## 答案卡

- 后端交来已核验的回答时，回答单独发在任务卡下方，作为一张答案卡（超过 20,000 字节时作为 Markdown 文件，后面补一张只有产物和灰框的小卡）。答案卡从上到下：回答；产物（折叠，标题“产物 2 个 · REPORT.md 等”）；改了代码的轮次再有一个折叠的“改动”（提交、部署、验收，取自检查点的 `delivery`），列的提交号在工作区所在的 git 仓库里找不到时，折叠下面一行橙色的“提交号对不上”写出是哪几个（展开后那个提交号后面也标“工作区的仓库里没有”；查不了时不写）；输入/输出灰框。
- 任务卡正文这时写加粗的“结论”和回答的第一个标题或第一句。
- 回答里的标题加粗显示，表格和代码块照常显示，只有一行的代码块改成行内代码。飞书拒收这张卡片时，回答作为 Markdown 消息发出。
- 没有单独发送的回答显示在任务卡正文，以“✅ 答案”开头。超过卡片容量时卡片保留预览并注明“完整内容会以 Markdown 文件发到本话题”。
- 答案里用 Markdown 图片语法引用的本机图片（绝对路径或相对工作区）会上传并显示为图片。
- 任务改了 git 工作区里的文件时，答案末尾附修改摘要（文件数和前 10 个文件），完整差异报告作为产物上传。
- **马上看的图片**：登录二维码、要你确认的截图不等这一轮结束：任务把图片写进检查点的 `show_images`，机器人读到就发到这个话题的串里，先一行说明、再一张图片（手机上长按能识别二维码）。标了 `urgent` 的，同时在私聊聊天区再发一份，第一行写“T号 · 说明”并带“到话题里看 ›”链接；在话题串里没发出去的也会发到聊天区。管家自己的只发在聊天区。同一张图只发一次，同一个文件改写后（比如二维码刷新）会再发；这只在这一轮还在执行时生效（`app/turn_images.py`）。

## 产物与导出

### 产物上传到云空间

任务完成且结果送达后，机器人以自己的身份把本轮产物上传到云空间，卡片上直接给出下载链接。

- **哪些文件**：模型在[检查点](usage.md#长任务与检查点)的 `artifacts` 里登记的文件、长答案文件、本轮的差异报告。
- **放在哪**：机器人云空间的“Harness Bridge 产物”文件夹，里面按日期每天一个文件夹，当天每个任务一个子文件夹。你对这个文件夹有可管理权限。文件夹满了 1500 个时自动新建“日期 (2)”或“Harness Bridge 产物 2”接着放，旧的不删不动。
- **卡片**：产物在答案卡上；答案在任务卡正文里时在任务卡上。正在上传、上传失败或有文件没上传时保持展开，能看到“重新上传”。
- **限制**：非空普通文件，不超过 200 MB。登记的目录打包成“目录名.zip”：`.git`、`.env` 这类配置和凭据文件以及符号链接不打包，总大小不超过 200 MB、文件不超过 5000 个。`.git`、`.ssh`、`.codex`、`.claude`、扩展声明的 Agent 目录（如扩展的子 Agent 工作目录）、`.env` 等路径不上传，也不列出。同一内容只上传一次。上传的文件不会自动删除。
- **失败**：卡片显示原因（例如“机器人应用缺少云空间权限：…”“云空间接口调用失败（错误码 …：…）”）和“重新上传”，处理好后点它，已上传的不会重复上传。权限见[配置飞书应用](feishu-app.md#在开发者后台手动配置)。

### 下载请求与结果

Claude 和 Codex 话题的任务卡结束后（完成、失败、停止都有），最底下有“下载请求与结果”，用来排查问题：把这一轮发给模型的每一次请求和模型的回复原样打包下载。

- 点一下，卡上写“正在打包…”，打好后上传到“Harness Bridge 产物”里当天的文件夹，这一行换成文件链接和大小，按钮之后直接打开这个文件。
- 文件是一个用 xz 压缩的 JSON。解压：`xz -d 文件名`，或 `python3 -c "import lzma,sys;sys.stdout.buffer.write(lzma.open(sys.argv[1]).read())" 文件名 > 文件.json`。
- **Claude**：`main.requests` 是本轮每次模型请求，按 Claude Code 的会话记录还原成它发出的请求对象；`digest_verified` 为 true 表示和 Claude Code 记下的请求摘要一致。`responses` 是模型的回复。会话记录不保存发给模型的图片原文，含图片的请求里那条消息写成 `{"missing_message": …}`。
- **Codex**：`request.input` 按 Codex 的会话记录（rollout）还原，是这次请求的全部输入项；`response` 是模型输出和用量；`turn_context` 是那一轮的设置。会话记录不存请求的其他字段（model、reasoning 等）；Codex 另加、记录里没有的部分写在该请求的 `not_recorded`。
- 其他 Harness 没有这个按钮。

## 附件与转发消息

- **图片和文件**：先下载到本话题的状态目录，提示词里列出本地路径请模型按需读取，下载失败的单独列出。支持原生图片输入的后端，还会把 PNG、JPEG、WebP、GIF 图片直接交给模型，见 [Harness 说明](harnesses.md#支持的-harness)；超过该 Harness 能直接附上的大小的图片只给路径，执行过程里写明“… 张图片没有直接交给模型”。
- **回复消息**：回复某条消息时，被回复的内容也一起交给模型。
- **合并转发**：递归展开（最多 50 条、5 层），嵌套的文字、卡片、图片和文件都提取和下载；无权查看、下载失败和截断都会写明，不补造内容。任务卡上显示为“[合并转发 N 条…]”。
- **飞书文档链接**：机器人只取得链接和标题，不读正文，提示词要求模型按自己的权限读取。

## 脱敏词表

点菜单「设置」的「脱敏」标签，一层，从上到下：

- 一行小字统计：几个词、近 7 天替换几次、几个话题开着脱敏。
- **填词**：一个多行框，每行一个词（词里可以有空格；飞书输入框一次最多 1000 字），可以整批粘贴。点“加入词表”一次加进去；点“从词表删除”把框里的词一次删掉（要和词表里的词整词一致，“不区分大小写”开着时大小写不论），删后卡上有“撤销”，整批放回。加不进去、没找到的行按行号说原因。替身词由系统自动生成（“RX + 8 位十六进制”），不能指定。
- 搜索框（一直在）：按词查找，下面写“找到几个”和“清除搜索”。
- **词表**：每页 10 个词，最新的在前，一个词一行：首字和字数，加近 7 天命中次数，右边是“删除”；删除后卡上有“撤销”。旧版本手动设过的替身词已不再使用，这些词也换成自动替身；旧版本设的“任意位置匹配”照常生效，行上标出来，删了再撤销能原样放回。
- 两个默认收起的折叠面板：**开关与上游地址**（“不区分大小写”“回复还原”点一下切换；新话题默认开不开脱敏在「新话题」页的“脱敏”一行；Claude 账号的上游地址，“修改地址”在折叠面板下面打开输入框，“探测”看没填时这一轮的请求会发到哪里）、**记录**（开着脱敏的话题和最近 10 轮）。**试一下**是折叠面板外的一行，点“展开”出输入框：粘贴一段文字，显示发出去的样子、替换了几处，以及还原后是否与原文一致。（飞书的折叠面板里放不了表单，所以输入框不收在折叠面板里。）
- **卡片上不出现原词**：词表里的词在卡上只写首字和字数（如“内··（4 字）”），替身词也不显示；框里输入的内容不留在卡上，加不进去的原因也不提原词。私聊和话题里的卡片，模型可能读到再发给厂商，所以这样做。框里输入的词提交时会经过飞书送到机器人一次。改动从下一轮起生效。
- **网页工作台**：开了[网页工作台](web.md)时，它的设置页也能批量加删词，和这张卡改的是同一份词表。以前的独立网页看板已经去掉。

## 本周用量

点菜单「用量」，私聊里收到一张「本周用量」卡（只读），不开任务。

- **范围**：最近 7 天（往前滚动 7×24 小时）开始的任务，私聊和各群的都算。一次运行算一次任务，提问后接着做的那一轮也算。
- **卡上**：最上面一条结论带写本周 token 总量，下一行是任务数、话题数和缓存命中占输入的比例，再下面一条分段条是任务怎么结束的（做完、在做、等你、排队、停住了、已停止，词和看板一样：你自己停的算“已停止”，失败、中断和负责人、护栏、代答停的算“停住了”）；然后是输入、缓存命中、输出三块数字，每天的 token 柱状图，各 Harness 的 token 占比环形图和表格（次数、token、缓存命中），最后一行“更新于”。已下架的 Harness 不算也不列。
- **token 总量**：输入加输出，含缓存命中，含子任务，和任务详情的算法一样。没有 token 记录的任务另写一行有几次。
- 每次点都按当时的任务记录重新算。

## 手上的事

部署开了「手上的事」时，私聊里置顶的那张卡原地更新：

- **等你**：在等你的事，最新的在前：话题和管家、负责人问你的问题，还有等你在启动卡上点开始的消息。点话题号直接打开那张问题卡或启动卡。等了一天以上的不再单列，最后一行灰字写有几个和它们的话题号，旁边是“不管了”（开了话题看板时才有按钮）。
- **在做**：排队和在跑的任务，先开始的在前，写几点开始的、阶段、Harness 和工作区。
- **刚结束**：刚完成、失败、停止或中断的任务，留 10 分钟。
- 每部分最多列 8 件。只有内容变了才重画（最多每 15 秒一次）。只列私聊里的任务，群里的不列。
- 卡只置顶一次：你在 Pin 里取消后不会再 Pin 上。每 7 天换一张新卡并置顶，旧卡改成“已不再更新”。

## 早晚汇总

- **等你**：和看板的“等你”同一批（见[看板：自动 Pin 话题](#看板自动-pin-话题)）：每个话题最新的待回答问题，或等你在启动卡上点开始的消息，专项里的话题也列在这里。等了一天以上的合成一行“另有 N 个等了一天以上：T…”，也算进个数。
- **在做**：在跑或排队的。
- **做完**：上一次汇总之后做完的，加上更早做完、你还没看过的（和看板的“有结果没看”是同一批，标题里写“另有更早没看的 N 个”）；不在“有结果没看”里的灰字标“已看”。
- 每行点 T 号打开那个话题；“等你”的行打开那张问题卡或启动卡，菜单「看板」上的按钮写“去回答”或“去开始”。每组最多 8 行。你从看板撤下的话题不列。三组都空就不发。
- 部署开了知识条目时，卡的末尾多一节“新记的知识”：上次汇总以来新增、改写、作废的条目，最多 10 行；只有这一节时汇总不会单独发出来。
- 开了手上的事和话题看板时，那一行带「不管了」，和手上的事那个按钮一样；点了这一行变成灰字“已撤下 N 个”。
- 看板不影响定时汇总。

## 看板卡

菜单「看板」的卡，标题旁是几个等你、停住了、可能卡住、在做，数法和结论带一样。最上面一条结论带：“要你处理 N 件事”（等你、停住了、可能卡住加起来），下一行“先看：”最急的那个话题（点结论带打开它），再下面一条分段条按件数画出各状态。下面每个话题一行，前面是状态的圆点和词，整行点了打开那个话题，标题后有“›”；打不开的那行灰字写“找不到它在私聊里的位置，打不开”。时间写到分钟（“等了 45 分钟”）：

- **等你**（橙）：要你定什么（那个话题最新一轮写的阶段）、等了多久，右边「去回答」。等了一天以上的合成一行，带「不管了」。
- **停住了**（红）：失败、中断、被负责人、专项护栏或代答停下的话题，写为什么停（负责人、护栏、代答停的写明是谁）、停在哪一步、几点停的、下一步点什么；右边「去任务卡」打开那次任务的任务卡（「检查并继续」在那里），「不管了」把它从看板撤下（有了新动静会回来）。
- **有结果没看**（绿）：做完了你还没看的，写结论的第一句；右边「记为看过」直接把它挪进下面的折叠，和网页上的“记为看过”一样。
- **在做**（蓝）：现在在干什么，步骤进度条、预计还要多久、几分钟前有动静、已跑多久；超过 30 分钟没动静的换成橙色“可能卡住”，右边「去任务卡」（任务卡上有「看看」）。
- **专项**（灰）：标题写“专项 N 个”和“M 个提议等你定”。每个专项一块，写目标和它的话题里几个等你、停住、在做；它的话题不再单独列在上面。等你定的提议也列在这里（紫色），话题都能点开，右边「建专项」「不管了」直接定，定了看板原地重画，不用回聊天里找提议卡；要改名或增删话题，在提议卡的表单里改。部署开了整理专项时，这里是「整理专项」按钮（只在这里有）。
- **到点回来看**（灰）：部署开了 `COVEY_REVISIT=1` 时，约好回来看的话题各一行，写几点回来看、看什么，右边「取消」；排出去在看的那一行写“正在回来看”，没有按钮。见[到点回来看](usage.md#到点回来看)。
- **做完、已停止**：上一次早晚汇总以来做完、都看过的话题，和你自己停掉的话题（任务卡上的停止、跟管家说停、网页上停、撤回原消息），收进最下面的折叠里（“09:30 以来做完的话题 N 个”，有你停的时写“做完 N 个 · 已停止 M 个”），和专项无关；折叠里每个话题号都能点开。
- 最后一行“更新于”旁边是「刷新」，原地按现在重算。再点一次菜单「看板」是收起，再点展开。
- 手上的事、早晚汇总和看板用同一套词：等你、在做、有结果、做完、停住了、已停止。

## 看板：自动 Pin 话题


部署再开了话题看板时，Bridge 把私聊里的话题自动 Pin 出来，「手上的事」固定在 Pin 列表最下面当索引：

- **顺序**（Pin 页从上到下）：等你 → 在做 → 有结果，组内新的在前。一个话题只出现在一组里。“有结果”包括完成、失败、中断和停止。
- **Pin 的是哪张卡**：话题自己的卡。等你 Pin 问题卡，在做 Pin 任务卡，有结果 Pin 这一轮的答案卡（答案写在任务卡上时 Pin 任务卡）。纯话题模式下有话题串的话题 Pin 一张三行状态卡：话题号和标题、状态和时间、一句话。点一下直接打开那个话题的话题串。
- **做完的留多久**：没看过的一直留着；看过之后从第一次看过算起再留 12 小时才自动撤。“看过”靠飞书的已读事件判断：读到这个话题在结束之后的消息才算。
- **“等你”到处一样**：早晚汇总、菜单「看板」、「手上的事」、管家的快照、网页工作台说的“等你”是同一批，个数也一样：话题和管家、负责人问你、卡已经发出的问题（交给负责人分流、还没轮到你的不算），加上等你在启动卡上点开始的消息（启动卡已经用过或没发出去的不算），每个话题算一个；等了一天以上的也算，只是合成一行；你撤下的话题不算。每一条都带入口，点开就是那张问题卡或启动卡。「手上的事」的“等你 N”是这个数，不是 Pin 了几格。
- **“有结果没看”到处一样**：看板、「手上的事」、早晚汇总、管家的快照和它查话题时说的“有结果没看”，都是看板这一组里还没看过的那些：完成、失败、中断和停止都算，没看过的不论多久都算。「手上的事」的“有结果”后面写“（未看 N）”，看过的那行标“已看”。
- **最多 10 个**：多了先让看过的“有结果”让位；还放不下的在「手上的事」里按组列出。
- **撤下话题**：在 Pin 页里取消它的 Pin；点「手上的事」里那行“不管了”；或跟管家说“T12 不用管了”。都只改看板，不动任务和问题。撤下的话题等有了新问题或新结果会自己回来。
- **不来回跳**：话题从“等你”或“有结果”变回“在做”时，原来 Pin 的卡跑满 5 分钟才挪。
- 顺序变了最多每分钟调整一次；Pin 和取消 Pin 不产生新消息、不加未读。

## 管家的细节

**表情和卡。** 你发一句话，它先不发卡，只在这句话上加一个表情：开工时 “OnIt”，自己答完换成 “DONE”，交给话题换成 “Get”，失败或被拒换成 “❌”，你停了或它要你回答时表情去掉。一轮跑过 90 秒还没完，它的卡才发出来，在你这句话的话题串里，能看进度、能停止。卡结束时状态行写它做了什么（“✅ 已答：开头”“↪ 开了 T44「标题」”“↪ 交给 T42 接着做”“↪ 拆成 2 件”）。一句话里有几件事就开几个话题；两个以上话题都像时，它出一道单选题问你。

**聊天区的消息。** 它直接给的答案、话题每一轮的结论、要你回答的问题卡，都作为新消息出现在聊天区最下面。最上面一块灰底写“你问 · 12:31 ›”和你那句话的原文（表单作答开的一轮写“你答”和“问题 → 回答”）。这一轮属于哪个话题，点了就跳到那个话题串里这一轮的位置；管家自己答的，点了回到你那句话在聊天里的位置。

- 只交给了话题、没说别的的一轮不另发答案，表情 “Get” 就是回执。
- 这一轮失败、被拒或超时，聊天区另发一条带“你问”的短消息说明；答案没发出去时，这条消息上有“重新投递结果”或“检查并继续”。
- 话题每一轮的结论和话题串里的答案卡一个样子，“输出”那行末尾多一个 T 号，点了跳到这一轮的卡。你自己点停止的那一轮不发。引用这些卡回话，就是对那个话题说。
- 聊天区那张问题卡上面带这一轮的输出。和话题里的卡一样，只有一道单选题时每个选项一个按钮，点了就提交。在哪张上答都一样，答了两张一起收起。

**交给话题的是什么。** 话题的模型收到管家整理的任务说明，加上你的原话和这条消息的图片、文件。话题的卡上只显示你的原话。

**原则管到哪。** 不管话题用哪个 Harness 都带上原则。只对某个工作区成立的记在那个工作区下；通用的只在你自己发的消息那一轮带上。

**不用管家。** 在「管家」页“更多”里把“私聊顶层的消息”选成“每条直接开一个话题”，卡上先说一句改了会怎样，点“确定改”才生效，顶层的新消息就各开一个话题。这时「管家」页只剩这一行，选回“交给管家”马上改回。正在回答的那一轮会做完；管家开过的话题照常在各自的话题串里继续，只是结论不再回到顶层。管家的会话留着，改回时接着用。Claude Code 暂时不可用时，顶层消息也会照旧新开话题。

**它在回答时你又发了消息。** 这条并入正在回答的这一轮。并不进去的排到这一轮后面。这一轮正在收尾、没来得及读到你这条就结束时，这条自动作为新的一轮处理，和你刚发的一样：表情和回答都在这条消息上，不用再发一次。几条都这样时按发出的顺序各算一轮。你点了停止的那一轮除外；送没送到说不准的，它在这条消息下说一句，不会重发。

**先转发、再说要做什么。** 只转发了卡片、聊天记录，只发了图片、文件或一个链接时，它等你说要做什么，最多 30 秒；这期间你写的话和转发的内容合成一次请求。

**它自己的设置。** 管家的任务卡没有回退和换配置，也不进「手上的事」。它的供应商、模型、思考预算、脱敏在设置卡「管家」页上改，Harness 只能是 Claude Code。上下文超过设置的阈值（默认 20 万 token）时，下一轮开始前自动压缩。

## 群聊

- 机器人先去掉 @ 它的部分再处理。不管谁 @、@ 几次，群都不会自己启用。你第一次在一个群 @ 机器人时，它查一次这个群：外部群只记下，一直只处理你；其余的群等你确认，私聊里来一张启用确认卡（你的个人群、部署关了团队空间时不发）。一个群只发一张；没发出去（比如你还没私聊过机器人）时，你下次在那个群 @ 再发。查询失败时什么都不定，下次 @ 再查。
- **启用确认卡**：写明群名，启用后群里所有成员 @ 机器人都能开话题、追问、补充、回答问题、点卡片，这些话题在你的机器上用你的全部权限、凭据和模型额度运行，群里的人都看得到卡片、答案和产物。“启用”和群聊卡的“启用”一样；“先不启用”和“停用”一样：只处理你，你再 @ 也不会再问。点了以后卡原地换成结果；这个群已经定过（在这张卡上或群聊卡上）时再点，卡上说已经定过了，什么都不改。
- **群聊卡**：设置卡「群聊」标签列出记录过的群，每个群的状态（已启用 / 等你确认 / 已停用 / 未确认 / 外部群）。等你确认的排在最前，有“启用”和“先不启用”；已启用的可以“停用”，其余可以“启用”。停用后只处理你，你再 @ 也不会再问。群里发“停用本群”是普通任务。
- **免@**（部署打开时才有）：每个群一行多一个“免@”按钮，选这个群里谁说话不用 @：**关闭**、**只有你**、**你和选中的人**（列出群成员）、**群里所有人**（每个人的每句话都会开任务，以你的全部权限运行）。成员只在已启用的群里免@；代答在用的群不能免@。免@ 的群里 @ 了别人却没 @ 机器人的消息当作在跟别人说话，不接。两个机器人在同一个群都开免@ 时每句话两个都会接，一个群只给一个开。
- **谁发的**：群里每条消息交给模型时，第一行写明发送者（“发送者：主人”或“发送者：群成员 …”）。
- 群成员点“添加或管理工作区…”或“其他目录…”时，卡上提示“仅机器人主人可以…”。其余被拒的消息和点击都不回复，只在 `bridge.log` 记一行。

## 代答

### 代答卡

机器人菜单的「代答」（部署有代答发送器才有这一项）打开这张卡。从上到下：

- **状态行**：“代答开着 ｜ 白名单 12 个 ｜ 3 条在处理”，关着写“代答关着”；有暂停的联系人时多一项“暂停 N 个”，没有在处理的就不写“在处理”。读不到你的消息或发不出去时，状态行上面先有一条警告，用人话写原因，变量名放在括号里。
- **开启代答 / 关闭代答**：总开关。“开启代答”是主按钮，“关闭代答”是文字按钮。第一次开启时机器人新建一个代答群（只有你和机器人），并把最近一次用的 Harness、模型、思考预算定为代答话题的配置。
- **登录**：网页登录正常时只有一行灰字“网页登录正常”；登录失效或还没确认过时才出“去登录”，二维码回复在卡下面，用飞书手机端扫码（用你本人的账号）。登录好以后，之前因为没登录而扣住的回复自动再发一次。
- **白名单**：每行“名称 · 私聊/群 @我 · 运行中/⏸ 已暂停”，带“暂停/恢复”“删除”。暂停后已经在处理的回复也不发；删除只移出白名单，话题保留。一起加入的群成员合成一行，带“暂停全部”“恢复全部”“删除全部”“同步成员”“逐个管理”。
- **添加**：输入框里可以一次写多个人名、邮箱、群名或 ou_/oc_ ID（一次最多 20 个），点“查找”后逐个列结果，点“全部添加”或单个“添加”。群有两个按钮：“群里@我”（只代答群里 @你 的消息）和“全员 N 人”（先确认，再把每个成员加成一条私聊白名单；超过 500 人的群不能整体加入）。
- **代答话题的模型**（最下面，标题行写着当前模型和思考预算）：Harness、供应商、模型、思考预算四行，和启动卡一样点开一行再点一项。改了就保存，所有联系人话题都用它，已有话题在没有任务进行时自动换过去。

点击被拒绝或出错时，原因写在这张卡上。只有最新的一张代答卡能用。

### 代答怎么工作

- **一个联系人一个话题**：每个人、每个群在代答群里各有一个话题，同一个会话接着聊。只回加入白名单之后的新消息；对方连发几条，合成一次回复（停下约 10 秒再回，至多等 45 秒）。
- **怎么回**：Bridge 把这个会话最近 20 条聊天（含你自己发的）附给模型，模型再按需检索（更早的聊天、相关群聊和文档、你的代码和记录、联系人笔记的摘要），答案明确就直接以你的身份发出，不等你确认，话题里记一行“✅ 已代你回复”。对方聊的是你在做的事时，模型以你的身份接话、给具体内容，不用反问代替回答。你在做的项目和常用说法写在 `<state>/proxy/owner-context.md`（只写能对外说的），口吻照 `<state>/proxy/style.md` 里归纳的你的聊天风格写，想调整就改这两个文件。群里是引用回复那条 @你 的消息。
- **不用回的时候**：对方只是收尾或确认（好的、收到、谢谢、表情），模型不发，话题里留一行“· 不用回”。
- **不回的时候**：涉及承诺、审批、费用、人事、隐私、凭据，或回错会有后果的事，模型不发，话题里出一张“⏸ 没有代你回复”的卡，有建议回复时带按钮**按建议回复**。你也可以在话题里 @机器人 说怎么回，那一轮的回复会发给对方。
- **对方又发了消息**：任务还在跑时对方又发了消息，这一轮的回复不发，新的一轮把前后的消息一起回（连着这样 2 轮后不再这样）。刚开始跑（不到 90 秒）的那一轮跑完再接新的一轮，新的一轮接着它的会话、不用重查一遍；还在排队或已跑得久的直接停下。
- **暂停、关闭、删除**：已经在跑的任务照常结束，但回复不发；恢复或开启后不会自动补发。对方最新一条消息已过去 2 小时还没发出的回复也不自动发。
- **不会重复发**：你已经在会话里亲自回了的，不跑任务也不发。每个联系人一小时最多代答 10 条。发送结果不明的标“⚠️ 可能已发出”，不会自动重发，请到会话里看一眼。
- **没发出去时**：确定没发出的会再试，共 3 次；都没发出时话题里出一张“⚠️ 代答没有发出”的卡，写为什么，下面是原文。点**重新发送**原样再发（不重新跑模型）。
- 代答话题不出问题卡：模型要问你的问题会被丢掉，这一轮直接写回复。代答话题的任务卡只有“换配置”。

### 代发草稿

话题要以你的身份给同事发飞书消息时（比如把开好的 key 交给对方），这一轮结束后话题里出一张“✉️ 代发草稿”卡，私聊区顶层也提示一行。卡上写发给谁（姓名、部门、邮箱）、为什么发，正文在输入框里可以直接改。点**发送**才以你的身份私聊发出，发出的是框里的内容；点**不发**就不发。同名多人时先点选是谁。发出后卡上和话题里各说一句，话题之后的轮次也知道结果；没发出时卡上写原因，可以改了再点**重新发送**；结果不明的标“可能已发出”，不会自动再发。只有你能点。部署没有代答发送器时没有这个功能。

## 知识条目

- 话题里记：那一轮模型把要记的列在回复里，Bridge 在那一轮结束后记下；只有你本人说了“记一下 / 记住 / 记下来”才记，代答话题和开了脱敏的话题不记。
- 搜条目时说“包括改过的”，也搜已取代、已作废的。
- 每条最多 200 字，分决定、做法、坑、事实、待定五类；通用的所有话题都带，只对某个工作区的只有那个工作区的话题带。同一组里意思相同的不重复记。
- 新话题的第一轮带最近的条目（总共约 1500 字，超出的是较早的）；续接的会话只补上一轮之后新增或改动的。
- 部署还配了历史搜索（`COVEY_HISTORY_CMD`）时，话题里的模型和管家在你问“之前 / 上次 / 那个 X 怎么弄的”时会自己查：管家先查知识条目，再按链接、路径找话题，最后搜全部历史轮次。

## 停住以后

### 检查并继续

- 任务卡没法再改时，另发一张恢复卡：开头的结论带写“停住了 · T12 #431”、原因和下一步，下面是停在哪一步、已做完的和按钮。点“检查并继续”后原卡片写明已转到新任务。
- 新任务带上原请求、上一轮结果和检查点。执行前机器人检查检查点里登记的、工作区内的产物是否存在，并要求模型先查询外部任务状态、禁止直接重复提交。检查点内容不是完成证明。
- 限流：走模型网关的 Codex、Pi、DeepSeek Harness 任务在同一轮里自己重试，不用点。
- 官方拒绝或降级：Claude 的主任务或子任务带了明确的 `refusal`、`fallback` 时停止这一轮；只有一个子代理第一次被拦时不停，执行过程里记一行，主任务自己绕开。因 cyber、bio 拒绝停下的一轮换旧模型在新会话里自动重试一次，原卡写“已转到任务 #N 继续”。见 [policy-stop.md](policy-stop.md)。

### 自动重试

下面三种情况结束、又没有发出任何回复时，机器人自动执行“检查并继续”：

- **模型服务限流**（只有 Claude）：失败后 60 秒一次；仍然限流，再过 180 秒一次；两次都限流就停下。
- **本轮未全部完成**（只有 Claude）：60 秒后一次；又这样结束就停下。设了任务超时的不自动继续。
- **被重启打断**（所有 Harness）：机器或机器人重启时任务进程没了，或任务进程收到 SIGTERM，这一轮按中断处理，机器人起来后 60 秒自动检查并继续一次；又被打断就停下。

- 三种各算各的次数，交替出现也不会重新计数。你点过“停止”的、因官方拒绝停止的、有已保存的结果等着重新投递的，都不自动继续。
- 等待期间卡上写“⏳ 模型服务限流，将于 20:15 自动重试（第 1/2 次）…”之类，按钮多一个“停止自动重试”。到点前点“检查并继续”立即重试；点“停止自动重试”、在本话题发消息或换配置会取消它。
- 计划写在任务记录里，Bridge 重启后照常执行。提交时出错时不再自动重试，卡片提示先查看话题再决定。

### 任务进程退出后

每个任务在自己的任务进程里运行。任务进程退出时（例如机器重启、崩溃、被 `kill`），任务**不会被静默重跑**，也不算“已停止”：原卡片换成“T12 · #N · 任务已中断”，写明当前阶段、已完成步骤和下一步，按钮是“检查并继续”。

任务进程在模型被调用前就退出时，机器人隔 2 秒自动再启动一次；再失败或根本起不来时，卡片换成“任务未能启动”，括号里写原因。

### 任务卡没出来

飞书拒收任务卡时，机器人先去掉“补充”“换配置”，只留“停止”再发一次。卡建好了、但回复到话题时被飞书明确拒绝（比如 2200 “Something went wrong”）时，先在原处再回复一次，还不行就改发到会话顶层；卡上的 T 号和任务号照常，点它的按钮照常进这个话题，任务记录的 `last_card_error` 记下飞书的错误码和最后发在哪。可能已经送达的失败（超时等）不再另发。都没发出去时，话题里收到“任务 #N 已收到，但任务卡没有发出去（飞书返回 …）。…”（点“检查并继续”“重试”时也在入队那句后面说）：任务照常执行，执行中每分钟再补发一次任务卡，最多 3 次；补发成功之前没法在飞书里停止它或回答它的提问，结果单独发回本话题。反馈问题时带上括号里的错误码。

### 结果送达失败

模型已经完成、但结果没能发到飞书时，任务不会重跑：

- 任务卡写“完整结果尚未成功发送，原始回复已保留。…”，机器人在后台自动重试投递。
- 重试按钮是“**重新投递结果**”（或等待回答的“**重新投递问题**”）：只发送已保存的正文和问题卡，不调用模型；已经送达的不会再发。
- 没送达的结果在等时，本话题的新消息先被拦下，提示先重新投递。
- 飞书内容审核拒收含明文邮箱或手机号的消息（错误码 230028）时，机器人把它们打码后再发一次；原文仍保存在本地任务记录。

### 机器人重启或更新

- 机器人重启或部署新版本时，正在执行的任务继续运行，同一张任务卡接着刷新，执行过程里注明“机器人 HH:MM 重启过，任务未中断。”。排队中的任务按原顺序继续排队。
- 机器人停着的那段时间点卡片没有响应，等它恢复后再点。
- 飞书把同一条消息再推一次时，机器人只处理第一次。

## 已下线的功能

下面这些功能已经下线。旧卡上的按钮和旧话题照常不会崩溃，只是不再做原来的事：

| 功能 | 现在怎么办 | 旧卡或旧话题点了会怎样 |
| --- | --- | --- |
